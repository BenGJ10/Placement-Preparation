# Routing Protocols

**Routing Protocols** are standardized sets of rules that routers use to **communicate routing information**, build routing tables, and determine optimal paths across networks.

Unlike routing algorithms (which are abstract mathematical procedures), routing protocols are **implemented and deployed** on real network devices.

Routing protocols are classified by their scope:

- **Interior Gateway Protocols (IGP):** Used within a single autonomous system (AS)
  - RIP, OSPF, EIGRP, IS-IS
- **Exterior Gateway Protocols (EGP):** Used between autonomous systems
  - BGP

---

## 1. Autonomous System (AS)

An **Autonomous System (AS)** is a collection of networks under a single administrative domain that share a common routing policy.

Each AS is assigned a unique **AS Number (ASN)** — a 16-bit or 32-bit number assigned by IANA.

**Examples:**
- Google's AS: AS15169
- Cloudflare's AS: AS13335
- Amazon AWS: AS16509

| Protocol | Type | Used Within / Between |
|----------|------|-----------------------|
| RIP      | IGP  | Within one AS         |
| OSPF     | IGP  | Within one AS         |
| EIGRP    | IGP  | Within one AS (Cisco) |
| BGP      | EGP  | Between ASes          |

## 2. RIP (Routing Information Protocol)

### Overview

**RIP** is one of the oldest and simplest routing protocols. It is a **Distance Vector** protocol that uses **hop count** as its sole routing metric.

### Versions

| Version | Features                                                    |
|---------|-------------------------------------------------------------|
| **RIP v1** | Classful, no subnet mask in updates, broadcast-based      |
| **RIP v2** | Classless (CIDR support), includes subnet mask, multicast (224.0.0.9) |
| **RIPng**  | RIP for IPv6 networks                                    |

### How RIP Works

1. Each router broadcasts its routing table to neighbors every **30 seconds**.
2. Neighbors update their own tables based on received information.
3. The **Bellman-Ford algorithm** is used to compute shortest paths.
4. Routers select paths with the **lowest hop count**.

### RIP Characteristics

| Feature                | Value / Description              |
|------------------------|----------------------------------|
| **Metric**             | Hop count                        |
| **Maximum hop count**  | 15 (16 = unreachable/infinity)   |
| **Update interval**    | 30 seconds                       |
| **Convergence**        | Slow                             |
| **Algorithm**          | Bellman-Ford (Distance Vector)   |
| **Protocol type**      | IGP                              |
| **Port**               | UDP port 520                     |
| **Admin distance**     | 120                              |

### RIP Timers

| Timer             | Duration | Purpose                                         |
|-------------------|----------|-------------------------------------------------|
| **Update Timer**  | 30 sec   | Interval between routing table broadcasts       |
| **Invalid Timer** | 180 sec  | Time before a route is marked invalid           |
| **Holddown Timer**| 180 sec  | Prevents accepting new info about a failed route|
| **Flush Timer**   | 240 sec  | Time before a route is removed from the table   |

### Limitations of RIP

- Maximum network diameter of **15 hops** — not suitable for large networks
- **Slow convergence** leads to temporary routing loops
- Uses only hop count — ignores bandwidth, delay, or reliability
- **Count-to-infinity problem** (mitigated by split horizon and poison reverse)
- High bandwidth usage due to periodic full-table broadcasts

### When to Use RIP

- Small networks with simple topologies
- Networks with no more than 15 hops
- Lab/educational environments

## 3. OSPF (Open Shortest Path First)

### Overview

**OSPF** is a **Link State** routing protocol and is the most widely used IGP in enterprise networks. It uses **Dijkstra's Shortest Path First (SPF) algorithm** to compute loop-free, optimal paths.


### How OSPF Works

1. **Neighbor Discovery:** Routers send **Hello packets** via multicast (`224.0.0.5`) to discover OSPF neighbors.
2. **Database Exchange:** Neighbors exchange **Link State Advertisements (LSAs)** and build a synchronized **Link State Database (LSDB)**.
3. **SPF Computation:** Each router runs Dijkstra's algorithm on the LSDB to compute the shortest path tree.
4. **Routing Table Population:** The shortest path tree is used to build the router's forwarding table.

### OSPF Hierarchical Design — Areas

OSPF organizes routers into **areas** to improve scalability:

| Area Type          | Description                                        |
|--------------------|----------------------------------------------------|
| **Backbone Area (Area 0)** | Central area; all other areas must connect to it |
| **Standard Area**  | Regular OSPF area with full LSA exchange          |
| **Stub Area**      | Does not receive external LSAs; uses default route |
| **Totally Stubby Area** | Receives only a default route from ABR        |
| **NSSA (Not-So-Stubby)** | Allows external routes via NSSA-LSA (Type 7) |

### OSPF Router Types

| Router Type | Role                                                  |
|-------------|-------------------------------------------------------|
| **IR (Internal Router)** | All interfaces within one area            |
| **ABR (Area Border Router)** | Connects multiple areas              |
| **ASBR (AS Boundary Router)** | Connects OSPF to external networks   |
| **BR (Backbone Router)** | Has at least one interface in Area 0     |

### OSPF DR and BDR Election

On multi-access networks (Ethernet), OSPF elects:

- **DR (Designated Router):** Central point for LSA exchange
- **BDR (Backup Designated Router):** Takes over if DR fails
- **DROther:** All other routers only exchange LSAs with DR/BDR

Election is based on **Router Priority** (default: 1) then **Router ID** (highest wins).

### OSPF Characteristics

| Feature                | Value / Description                     |
|------------------------|-----------------------------------------|
| **Metric**             | Cost (based on bandwidth: 10^8 / BW)    |
| **Algorithm**          | Dijkstra (Link State)                   |
| **Convergence**        | Fast                                    |
| **Protocol**           | IP protocol number 89                   |
| **Update type**        | Triggered (not periodic)                |
| **Admin distance**     | 110                                     |
| **Supports VLSM/CIDR** | Yes                                     |
| **Authentication**     | Supported (MD5, SHA)                    |
| **IPv6 version**       | OSPFv3                                  |

### OSPF Cost Calculation

```
Cost = Reference Bandwidth / Interface Bandwidth
     = 10^8 bps / Interface speed (bps)
```

| Interface Type | Bandwidth     | OSPF Cost |
|----------------|---------------|-----------|
| 10 Mbps Ethernet | 10,000,000  | 10        |
| 100 Mbps FastEthernet | 100,000,000 | 1    |
| 1 Gbps Gigabit | 1,000,000,000 | 1 (needs adjusted reference) |

### OSPF Packet Types

| Type | Name                     | Purpose                                     |
|------|--------------------------|---------------------------------------------|
| 1    | Hello                    | Neighbor discovery and keepalive            |
| 2    | DBD (Database Description) | Summary of LSDB for synchronization      |
| 3    | LSR (Link State Request) | Request specific LSAs                       |
| 4    | LSU (Link State Update)  | Full LSA content                            |
| 5    | LSAck                    | Acknowledgment of received LSAs             |

## 4. BGP (Border Gateway Protocol)

### Overview

**BGP** is the **de facto routing protocol of the Internet**. It is an **Exterior Gateway Protocol (EGP)** that manages routing between different **Autonomous Systems (AS)**.

BGP is a **Path Vector protocol** — it selects routes based on a set of **path attributes** rather than a single metric.

### BGP Types

| Type      | Description                                         |
|-----------|-----------------------------------------------------|
| **eBGP** (External BGP) | Between routers in different ASes     |
| **iBGP** (Internal BGP) | Between routers within the same AS    |

### How BGP Works

1. Routers form a **BGP session** (TCP connection on port 179) with configured neighbors (peers).
2. BGP exchanges **Network Layer Reachability Information (NLRI)** — which IP prefixes a neighbor can reach.
3. BGP applies **route selection policies** based on path attributes to choose the best path.
4. BGP propagates the selected routes to other peers.

### BGP Path Attributes

BGP selects the best route based on a set of attributes evaluated in order:

| Priority | Attribute                | Description                                      |
|----------|--------------------------|--------------------------------------------------|
| 1        | **Weight** (Cisco only)  | Higher is preferred (local to router)            |
| 2        | **Local Preference**     | Higher preferred; used within an AS              |
| 3        | **Locally originated**   | Prefer routes originated by the local router     |
| 4        | **AS Path length**        | Shorter AS path preferred                       |
| 5        | **Origin**               | IGP > EGP > Incomplete                          |
| 6        | **MED** (Multi-Exit Discriminator) | Lower preferred; hints to external AS |
| 7        | **eBGP vs iBGP**         | eBGP preferred over iBGP                        |
| 8        | **IGP metric**           | Lower cost to next hop preferred                |
| 9        | **Router ID**            | Lowest Router ID preferred as tiebreaker        |

### BGP Characteristics

| Feature               | Description                                |
|-----------------------|--------------------------------------------|
| **Type**              | Path Vector (EGP)                          |
| **Transport**         | TCP port 179                               |
| **Update type**       | Incremental (only changes sent)            |
| **Metric**            | Path attributes (AS path, local pref, MED) |
| **Convergence**       | Slow (policy-driven)                       |
| **Admin distance**    | eBGP: 20 / iBGP: 200                      |
| **Scalability**       | Highly scalable (manages global internet routing) |
| **Authentication**    | MD5 supported                              |
| **IPv6 version**      | MP-BGP (Multiprotocol BGP)                |

### BGP Message Types

| Type        | Purpose                                                  |
|-------------|----------------------------------------------------------|
| **OPEN**    | Establishes a BGP session; exchanges AS number and capabilities |
| **UPDATE**  | Advertises new routes or withdraws old ones              |
| **KEEPALIVE** | Maintains the session (sent every 60 seconds by default) |
| **NOTIFICATION** | Reports errors and terminates the session          |

### BGP States

BGP connections go through a state machine:

```
Idle → Connect → Active → OpenSent → OpenConfirm → Established
```

The **Established** state means the BGP session is active and routes are being exchanged.

## 5. Comparison: RIP vs OSPF vs BGP

| Feature             | RIP              | OSPF                 | BGP                    |
|---------------------|------------------|----------------------|------------------------|
| **Type**            | Distance Vector  | Link State           | Path Vector            |
| **Scope**           | IGP              | IGP                  | EGP                    |
| **Algorithm**       | Bellman-Ford     | Dijkstra             | Path attributes        |
| **Metric**          | Hop count        | Cost (bandwidth)     | Path attributes        |
| **Max hops**        | 15               | Unlimited            | Unlimited              |
| **Convergence**     | Slow             | Fast                 | Very slow (policy-based)|
| **Scalability**     | Low              | High                 | Very High              |
| **Transport**       | UDP 520          | IP (protocol 89)     | TCP 179                |
| **Admin Distance**  | 120              | 110                  | eBGP:20 / iBGP:200     |
| **VLSM/CIDR**       | v2 only          | Yes                  | Yes                    |
| **Updates**         | Periodic (30s)   | Triggered            | Incremental            |
| **Use Case**        | Small networks   | Enterprise networks  | Internet routing       |

---

## Key Takeaways

- RIP is simple, uses hop count, limited to 15 hops — suitable only for small networks.

- OSPF uses Dijkstra's algorithm, supports areas for scalability, converges fast, and is cost-based.

- BGP is the Internet's routing protocol; it is policy-driven and operates between autonomous systems.

- OSPF elects a DR and BDR on multi-access segments to reduce LSA flooding overhead.

- BGP uses TCP port 179 for reliable session establishment; it is path-vector, not distance-vector.

- Administrative distance determines which protocol's routes are preferred when multiple protocols learn the same destination.
