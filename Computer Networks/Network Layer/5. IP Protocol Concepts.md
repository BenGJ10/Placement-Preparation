# IP Protocol Concepts — ARP, RARP, ICMP, IGMP

The **Network Layer (Layer 3)** relies on several supporting protocols beyond IP itself to manage address resolution, error reporting, and group communication. These protocols work alongside IP and are essential for the proper functioning of any IP network.

| Protocol | Full Form                             | Primary Purpose                              |
|----------|---------------------------------------|----------------------------------------------|
| **ARP**  | Address Resolution Protocol           | IP address → MAC address mapping            |
| **RARP** | Reverse Address Resolution Protocol   | MAC address → IP address mapping            |
| **ICMP** | Internet Control Message Protocol    | Error reporting and network diagnostics      |
| **IGMP** | Internet Group Management Protocol   | Multicast group membership management       |

---

## 1. ARP (Address Resolution Protocol)

### Overview

**ARP** is used to resolve a known **IP address** to an unknown **MAC address** within a local network.

Routers forward packets using IP addresses, but actual frame delivery on a LAN requires MAC addresses. ARP bridges this gap.

### Why ARP is Needed

A host knows the destination IP but not the destination MAC address required to construct an Ethernet frame. ARP resolves this:

```
IP Address (Layer 3)  →  ARP  →  MAC Address (Layer 2)
```

### ARP Operation

**Step 1 — Check ARP Cache:**
The sender first checks its local ARP table for an existing IP-to-MAC mapping.

```
arp -a      (Windows / Linux)
ip neigh     (Linux modern)
```

**Step 2 — ARP Request (Broadcast):**
If the mapping is not found, the sender broadcasts an ARP request:

```
Destination MAC: FF:FF:FF:FF:FF:FF  (Broadcast)
"Who has IP 192.168.1.20? Tell 192.168.1.10"
```

**Step 3 — ARP Reply (Unicast):**
The target device replies directly to the requester:

```
Destination MAC: <requester's MAC>  (Unicast)
"192.168.1.20 is at BB:BB:BB:BB:BB:BB"
```

**Step 4 — ARP Cache Update:**
The sender stores the mapping for future use. Entries are temporary and expire after a timeout.

### ARP Packet Fields

| Field                | Size (bits) | Description                          |
|----------------------|-------------|--------------------------------------|
| Hardware Type        | 16          | Network type (Ethernet = 1)          |
| Protocol Type        | 16          | Protocol (IPv4 = 0x0800)             |
| Hardware Addr Length | 8           | MAC address length (6 bytes)         |
| Protocol Addr Length | 8           | IP address length (4 bytes)          |
| Opcode               | 16          | 1 = Request, 2 = Reply               |
| Sender MAC Address   | 48          | Requester's MAC                      |
| Sender IP Address    | 32          | Requester's IP                       |
| Target MAC Address   | 48          | All 0s in request (unknown)          |
| Target IP Address    | 32          | IP being queried                     |

### Types of ARP

| Type               | Description                                               |
|--------------------|-----------------------------------------------------------|
| **Standard ARP**   | Normal IP-to-MAC resolution                               |
| **Gratuitous ARP** | Device announces its own IP-MAC mapping (used to detect IP conflicts and update stale ARP tables) |
| **Proxy ARP**      | Router responds to ARP requests on behalf of a host in another network |
| **Reverse ARP (RARP)** | MAC-to-IP resolution (see Section 2 below)           |

### ARP Spoofing (Security Concern)

Since ARP has no authentication mechanism, an attacker can send fake ARP replies:

- **Attack:** "Gateway IP is at [attacker MAC]"
- **Result:** Traffic is redirected to the attacker — a **Man-in-the-Middle (MITM)** attack
- **Defenses:** Dynamic ARP Inspection (DAI), static ARP entries, network monitoring tools

## 2. RARP (Reverse Address Resolution Protocol)

### Overview

**RARP** performs the **reverse of ARP** — it resolves a known **MAC address** to an **IP address**.

It was used historically by diskless workstations that knew their MAC address but needed an IP address at boot time.

### How RARP Works

1. A diskless host broadcasts a **RARP Request** containing its own MAC address.
2. A **RARP Server** on the network has a pre-configured table of MAC-to-IP mappings.
3. The RARP Server sends back a **RARP Reply** with the corresponding IP address.
4. The host configures itself with the received IP address.

### RARP Limitations

| Limitation                                  |
|---------------------------------------------|
| Requires a RARP server on every network segment (broadcast-limited) |
| Provides only an IP address — no subnet mask, gateway, or DNS info |
| Cannot cross routers (broadcasts are not forwarded) |
| Obsolete — replaced by **BOOTP** and later **DHCP** |

### ARP vs RARP

| Feature          | ARP                           | RARP                           |
|------------------|-------------------------------|--------------------------------|
| **Resolves**     | IP Address → MAC Address      | MAC Address → IP Address       |
| **Who uses it**  | Any networked host            | Diskless workstations (legacy) |
| **Request type** | Broadcast                     | Broadcast                      |
| **Reply type**   | Unicast                       | Broadcast or Unicast           |
| **Status**       | Still actively used           | Obsolete (replaced by DHCP)    |

## 3. ICMP (Internet Control Message Protocol)

### Overview

**ICMP** is a **Network Layer protocol** used for **error reporting and network diagnostics**. It allows routers and hosts to communicate error conditions and operational information back to the source of a packet.

ICMP does **not transport user data** — it is a control and management protocol.

ICMP is defined in **RFC 792** (for IPv4); **ICMPv6** (RFC 4443) is its IPv6 equivalent.

### ICMP Message Format

Every ICMP message carries:

| Field        | Size    | Description                              |
|--------------|---------|------------------------------------------|
| Type         | 8 bits  | Category of the ICMP message             |
| Code         | 8 bits  | Subcategory providing more detail        |
| Checksum     | 16 bits | Error detection for the ICMP message     |
| Data         | Variable| Context-specific (often the IP header + first 8 bytes of the offending packet) |

### Common ICMP Message Types

| Type | Code | Message                        | Description                                     |
|------|------|--------------------------------|-------------------------------------------------|
| 0    | 0    | Echo Reply                     | Response to a ping                              |
| 3    | 0    | Destination Unreachable: Network | Network is unreachable                         |
| 3    | 1    | Destination Unreachable: Host  | Host is unreachable                             |
| 3    | 3    | Destination Unreachable: Port  | Port is unreachable (UDP)                       |
| 4    | 0    | Source Quench                  | Congestion control — router asks sender to slow down (deprecated) |
| 5    | 0    | Redirect                       | Inform host of a better route                   |
| 8    | 0    | Echo Request                   | Ping request                                    |
| 11   | 0    | Time Exceeded: TTL             | Packet's TTL reached 0 (used by traceroute)     |
| 11   | 1    | Time Exceeded: Reassembly      | Fragment reassembly time expired                |
| 12   | 0    | Parameter Problem              | Invalid IP header field detected                |

### ICMP-Based Tools

**ping**

Used to test reachability and measure round-trip time (RTT) between two hosts.

```
ping 8.8.8.8
```

Working:
1. Sender sends **ICMP Echo Request (Type 8)**
2. Destination replies with **ICMP Echo Reply (Type 0)**
3. RTT is calculated from the time difference

**traceroute (tracert on Windows)**

Used to trace the path packets take to a destination, revealing each intermediate router.

```
traceroute google.com
tracert google.com    (Windows)
```

Working:
1. Sends packets with **TTL = 1, 2, 3, ...** incrementally
2. Each router decrements TTL by 1
3. When TTL hits 0, the router discards the packet and sends back **ICMP Time Exceeded (Type 11)**
4. The source records the router that sent the error
5. This reveals the entire path, hop by hop

### ICMP and Security

ICMP is often restricted by firewalls because it can be abused:

| Attack                | Description                                                |
|-----------------------|------------------------------------------------------------|
| **Ping of Death**     | Sending oversized ICMP packets to crash target systems     |
| **ICMP Flood (Smurf)**| Attacker sends ping to broadcast address with spoofed source IP |
| **ICMP Redirect Attack** | Attacker sends fake redirects to alter routing paths   |

## 4. IGMP (Internet Group Management Protocol)

### Overview

**IGMP** is a **Network Layer protocol** used to manage **multicast group memberships** on a local network.

Multicast allows one sender to deliver data to multiple receivers **simultaneously** without sending individual copies to each host.

- Hosts use IGMP to **join or leave multicast groups**
- Routers use IGMP to **track which local hosts belong to which multicast groups**

Multicast addresses in IPv4 are in the range **224.0.0.0 – 239.255.255.255** (Class D).

### IGMP Versions

| Version   | Key Features                                                         |
|-----------|----------------------------------------------------------------------|
| **IGMPv1** | Basic group join; router queries all groups; no leave mechanism     |
| **IGMPv2** | Added explicit **Leave Group** message; group-specific queries      |
| **IGMPv3** | Added **source filtering** (ASM/SSM); hosts can specify which sources to receive from |

### How IGMP Works

**Joining a Multicast Group:**
1. A host wishing to receive multicast traffic sends an **IGMP Membership Report** to the multicast group address.
2. The router records the membership in its multicast routing table.
3. Multicast traffic for that group is now forwarded to that network segment.

**Leaving a Group (IGMPv2+):**
1. A host sends an **IGMP Leave Group** message to `224.0.0.2` (all-routers multicast address).
2. The router sends a **Group-Specific Query** to confirm if any other hosts still want the group.
3. If no response, the router stops forwarding traffic for that group on that segment.

**Router Queries:**
- Multicast routers periodically send **IGMP General Queries** to `224.0.0.1` (all-hosts address) to determine which groups have active members.

### IGMP Message Types

| Type   | Message                | Description                                          |
|--------|------------------------|------------------------------------------------------|
| 0x11   | Membership Query       | Router asks which groups have active members         |
| 0x16   | Membership Report (v2) | Host announces it is joining a group                 |
| 0x17   | Leave Group            | Host announces it is leaving a group                 |
| 0x22   | Membership Report (v3) | Includes source filtering information               |

### IGMP Role in Multicast Delivery

```
Sender → Multicast Router → [checks IGMP table] → Forwards to segments with group members
```

Without IGMP, the router would have to flood multicast traffic to all segments — wasting bandwidth. IGMP ensures multicast is delivered **only where needed**.

### IGMPv2 vs IGMPv3

| Feature                 | IGMPv2          | IGMPv3                        |
|-------------------------|-----------------|-------------------------------|
| **Leave mechanism**     | Yes             | Yes                           |
| **Source filtering**    | No              | Yes (include/exclude sources) |
| **Group-specific query**| Yes             | Yes                           |
| **Source-specific multicast** | No       | Yes (SSM support)             |

## 5. Protocol Comparison Summary

| Feature          | ARP               | RARP              | ICMP                   | IGMP                    |
|------------------|-------------------|-------------------|------------------------|-------------------------|
| **Purpose**      | IP → MAC          | MAC → IP          | Error reporting / diagnostics | Multicast group management |
| **OSI Layer**    | Network / Data Link | Network / Data Link | Network               | Network                 |
| **Direction**    | Broadcast Q, Unicast R | Broadcast    | Error or query messages| Membership reports      |
| **Uses**         | LAN communication | Legacy diskless boot | ping, traceroute       | Multicast streaming     |
| **Status**       | Active            | Obsolete          | Active                 | Active                  |
| **IPv6 equiv.**  | NDP (Neighbor Discovery) | DHCPv6    | ICMPv6                 | MLD (Multicast Listener Discovery) |

---

## Key Takeaways

- ARP resolves IP addresses to MAC addresses within a local network using broadcasts.

- RARP is the reverse of ARP but is obsolete — DHCP replaced it entirely.

- ICMP is not a data transport protocol; it handles error reporting and diagnostics (ping, traceroute).

- Traceroute exploits ICMP Time Exceeded messages by incrementing the TTL field.

- IGMP manages multicast group memberships, allowing routers to deliver multicast traffic only where needed.

- IGMPv3 adds source-specific multicast (SSM) capability, allowing hosts to filter by source.

- In IPv6, ARP is replaced by NDP, ICMP becomes ICMPv6, and IGMP becomes MLD.
