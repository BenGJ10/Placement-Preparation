# Subnetting, Supernetting, and CIDR

At the **Network Layer**, IP addresses need to be organized and allocated efficiently. Three closely related concepts govern this:

- **Subnetting** — dividing a large network into smaller sub-networks
- **Supernetting** — merging multiple smaller networks into a larger one
- **CIDR (Classless Inter-Domain Routing)** — a flexible, class-independent addressing scheme

---

## 1. Subnet Mask

Before subnetting, it is essential to understand the **subnet mask**.

A **subnet mask** is a 32-bit number that separates an IP address into:

- **Network portion** — identifies the network
- **Host portion** — identifies the specific device

### How It Works

| IP Address     | 192.168.1.100          |
|----------------|------------------------|
| Subnet Mask    | 255.255.255.0          |
| Binary Mask    | 11111111.11111111.11111111.00000000 |
| Network Part   | 192.168.1              |
| Host Part      | .100                   |

The **1s** in the mask represent the network portion; the **0s** represent the host portion.

**Network address** = IP AND Subnet Mask

```
192.168.1.100  →  11000000.10101000.00000001.01100100
255.255.255.0  →  11111111.11111111.11111111.00000000
AND            →  11000000.10101000.00000001.00000000
             = 192.168.1.0  (Network Address)
```

## 2. Subnetting

### Definition

**Subnetting** is the process of **dividing a single large IP network into multiple smaller networks** called **subnets**.

It is done by **borrowing bits from the host portion** of the address and adding them to the network portion.

### Why Subnet?

- Reduces network congestion by limiting broadcast domains
- Improves security by isolating network segments
- Enables efficient IP address utilization
- Simplifies network management

### Key Formulas

| Quantity                  | Formula           |
|---------------------------|-------------------|
| Number of subnets         | `2^n`             |
| Number of usable hosts    | `2^h - 2`         |
| Total hosts per subnet    | `2^h`             |

Where:
- `n` = number of bits borrowed from host portion
- `h` = remaining host bits after borrowing

**The -2 accounts for:**
- Network address (all host bits = 0)
- Broadcast address (all host bits = 1)

### Subnetting Example

**Given:** IP Address `192.168.1.0/24`, divide into **4 subnets**

**Step 1:** Determine bits to borrow
`4 subnets = 2^n → n = 2 bits`

**Step 2:** New prefix length
`/24 + 2 = /26`

**Step 3:** New subnet mask
`255.255.255.192` (11111111.11111111.11111111.11000000)

**Step 4:** Block size per subnet
`2^6 = 64` addresses per subnet

**Step 5:** List all subnets

| Subnet | Network Address   | Usable Range              | Broadcast       |
|--------|-------------------|---------------------------|-----------------|
| 1      | 192.168.1.0/26    | 192.168.1.1 – 192.168.1.62  | 192.168.1.63  |
| 2      | 192.168.1.64/26   | 192.168.1.65 – 192.168.1.126 | 192.168.1.127 |
| 3      | 192.168.1.128/26  | 192.168.1.129 – 192.168.1.190 | 192.168.1.191 |
| 4      | 192.168.1.192/26  | 192.168.1.193 – 192.168.1.254 | 192.168.1.255 |

**Usable hosts per subnet:** `2^6 - 2 = 62`

### VLSM (Variable Length Subnet Masking)

Standard subnetting creates equal-sized subnets, which is often inefficient.

**VLSM** allows subnets of different sizes within the same network, assigning address space based on actual host requirements.

**Example:** A company needs:
- Department A: 60 hosts → /26 (62 usable)
- Department B: 25 hosts → /27 (30 usable)
- Department C: 10 hosts → /28 (14 usable)
- WAN link: 2 hosts → /30 (2 usable)

Each department gets exactly the subnet size it needs, minimizing wastage.

## 3. Supernetting

### Definition

**Supernetting** (also called **route aggregation** or **route summarization**) is the process of **combining multiple contiguous smaller networks into one larger network**.

It is the **opposite of subnetting** — instead of borrowing host bits, supernetting **returns network bits back to the host portion**.

### Why Supernet?

- Reduces the number of entries in routing tables
- Simplifies routing and improves router performance
- Decreases routing protocol overhead

### How Supernetting Works

**Given:** Four Class C networks to be summarized:
```
192.168.0.0/24
192.168.1.0/24
192.168.2.0/24
192.168.3.0/24
```

**Step 1:** Write the third octets in binary:
```
192.168.00000000.0  → 0
192.168.00000001.0  → 1
192.168.00000010.0  → 2
192.168.00000011.0  → 3
```

**Step 2:** Find common prefix bits in third octet:
`00000000, 00000001, 00000010, 00000011`
Common prefix: `000000` (6 bits match)

**Step 3:** New prefix:
`/24 - 2 = /22`

**Result:** `192.168.0.0/22` — a single supernet covering all four networks.

### Condition for Supernetting

For networks to be combined into a supernet:
1. Networks must be **contiguous** (consecutive addresses)
2. All networks must have the **same prefix length**
3. The block must be a **power-of-two** in size
4. The first network address must be **divisible by the block size**

## 4. CIDR (Classless Inter-Domain Routing)

### Definition

**CIDR** is an IP addressing scheme that **replaces the old class-based system** (Class A, B, C) with a flexible, prefix-based approach.

Introduced in **1993 (RFC 1519)** to slow IPv4 address exhaustion and reduce routing table growth.


### CIDR Notation

CIDR uses **slash notation** (also called prefix notation):

```
192.168.1.0/24
```

The `/24` indicates that the first **24 bits** are the network portion.

### CIDR vs Classful Addressing

| Feature              | Classful (Old)                  | CIDR (Classless)               |
|----------------------|---------------------------------|--------------------------------|
| **Address blocks**   | Fixed: /8, /16, /24            | Any prefix length              |
| **Address waste**    | High (large blocks assigned)   | Minimal (right-sized blocks)   |
| **Routing table**    | Large                           | Smaller (aggregation possible) |
| **Flexibility**      | Low                             | High                           |
| **IPv6 compatible**  | No                              | Yes                            |

### CIDR Block Examples

| CIDR Notation     | Subnet Mask        | Total Addresses | Usable Hosts |
|-------------------|--------------------|-----------------|--------------|
| `/30`             | 255.255.255.252    | 4               | 2            |
| `/29`             | 255.255.255.248    | 8               | 6            |
| `/28`             | 255.255.255.240    | 16              | 14           |
| `/27`             | 255.255.255.224    | 32              | 30           |
| `/26`             | 255.255.255.192    | 64              | 62           |
| `/25`             | 255.255.255.128    | 128             | 126          |
| `/24`             | 255.255.255.0      | 256             | 254          |
| `/23`             | 255.255.254.0      | 512             | 510          |
| `/22`             | 255.255.252.0      | 1024            | 1022         |
| `/16`             | 255.255.0.0        | 65,536          | 65,534       |
| `/8`              | 255.0.0.0          | 16,777,216      | 16,777,214   |

### CIDR Route Aggregation

CIDR allows ISPs to advertise a single aggregated route instead of many specific routes:

**Without CIDR (Classful):**
```
Route 1: 200.10.0.0/24
Route 2: 200.10.1.0/24
Route 3: 200.10.2.0/24
Route 4: 200.10.3.0/24
```

**With CIDR (Aggregated):**
```
Single route: 200.10.0.0/22
```

One routing table entry instead of four — this is the power of **CIDR-based route aggregation**.

## 5. Important Calculations

### Finding Network Address

`Network Address = IP Address AND Subnet Mask`

### Finding Broadcast Address

`Broadcast = Network Address OR (NOT Subnet Mask)`

For `192.168.1.0/26`:
- Subnet Mask: `255.255.255.192`
- NOT Mask: `0.0.0.63`
- Broadcast: `192.168.1.0 OR 0.0.0.63 = 192.168.1.63`

### Number of Hosts

`Usable Hosts = 2^(32 - prefix) - 2`

For `/26`: `2^(32-26) - 2 = 2^6 - 2 = 62 hosts`

### Quick Prefix-to-Mask Reference

| Prefix | Last Octet Value | Block Size |
|--------|-----------------|------------|
| /25    | 128             | 128        |
| /26    | 192             | 64         |
| /27    | 224             | 32         |
| /28    | 240             | 16         |
| /29    | 248             | 8          |
| /30    | 252             | 4          |

## 6. Comparison Summary

| Concept        | Operation           | Prefix Change | Purpose                          |
|----------------|---------------------|---------------|----------------------------------|
| **Subnetting** | Divides network     | Increases (/larger) | Segment a network          |
| **Supernetting** | Merges networks   | Decreases (/smaller) | Aggregate routes           |
| **CIDR**       | Flexible allocation | Any value     | Efficient address assignment     |

---

## Key Takeaways

- Subnetting borrows host bits to create multiple smaller networks from one large network.

- Every subnet has a network address (all host bits 0) and broadcast address (all host bits 1), both unusable.

- VLSM allows subnets of different sizes, making address allocation more efficient.

- Supernetting combines contiguous networks into a single larger block for route aggregation.

- CIDR replaces classful addressing with flexible prefix lengths, reducing address waste and routing table size.

- The formula for usable hosts is always `2^h - 2` where `h` is the number of host bits.
