# IPv4 vs IPv6 Addressing

The **Internet Protocol (IP)** is the fundamental protocol responsible for **logical addressing and routing** of packets across interconnected networks at the **Network Layer (Layer 3)**.

Two versions of IP are in use today:

- **IPv4** — the original version, still dominant worldwide
- **IPv6** — the modern successor, designed to address IPv4 limitations

---

## 1. IPv4 (Internet Protocol Version 4)

### Overview

IPv4 is a **32-bit addressing scheme** that has been the backbone of internet communication since the early 1980s.

**Total address space:**
`2^32 = 4,294,967,296` addresses (approximately 4.3 billion)

### Address Format

IPv4 addresses are written in **dotted-decimal notation**:

```
192.168.1.1
```

Each section is called an **octet** (8 bits), and there are 4 octets:

| Octet 1 | Octet 2 | Octet 3 | Octet 4 |
|---------|---------|---------|---------|
| 192     | 168     | 1       | 1       |
| 11000000 | 10101000 | 00000001 | 00000001 |

**Binary representation:** `11000000.10101000.00000001.00000001`

### IPv4 Address Classes

| Class | Range              | Default Subnet Mask | Purpose                 |
|-------|--------------------|---------------------|-------------------------|
| **A** | 1.0.0.0 – 126.x.x.x    | 255.0.0.0 (/8)       | Large networks          |
| **B** | 128.0.0.0 – 191.255.x.x | 255.255.0.0 (/16)    | Medium networks         |
| **C** | 192.0.0.0 – 223.255.255.x | 255.255.255.0 (/24) | Small networks          |
| **D** | 224.0.0.0 – 239.255.255.255 | N/A              | Multicast groups        |
| **E** | 240.0.0.0 – 255.255.255.255 | N/A              | Reserved / Experimental |

**Note:** 127.x.x.x is reserved for loopback (localhost).

### Reserved / Special IPv4 Addresses

| Address / Range          | Purpose                      |
|--------------------------|------------------------------|
| `127.0.0.1`              | Loopback (localhost)         |
| `0.0.0.0`                | Default / Unspecified address |
| `255.255.255.255`        | Limited broadcast            |
| `10.0.0.0/8`             | Private (Class A)            |
| `172.16.0.0 – 172.31.255.255` | Private (Class B)       |
| `192.168.0.0/16`         | Private (Class C)            |
| `169.254.x.x`            | APIPA (link-local, auto-assigned) |

### IPv4 Header Structure

The IPv4 header is **20 bytes minimum** and contains:

| Field            | Size    | Purpose                              |
|------------------|---------|--------------------------------------|
| Version          | 4 bits  | IP version (4)                       |
| IHL              | 4 bits  | Header length in 32-bit words        |
| DSCP / ECN       | 8 bits  | Quality of service                   |
| Total Length     | 16 bits | Total size of packet (header + data) |
| Identification   | 16 bits | Fragment identification              |
| Flags            | 3 bits  | Fragmentation control                |
| Fragment Offset  | 13 bits | Position of fragment                 |
| TTL              | 8 bits  | Time To Live (hop limit)             |
| Protocol         | 8 bits  | Upper layer protocol (TCP=6, UDP=17) |
| Header Checksum  | 16 bits | Error detection for header           |
| Source IP        | 32 bits | Sender's IP address                  |
| Destination IP   | 32 bits | Receiver's IP address                |
| Options          | Variable| Optional fields                      |

### Limitations of IPv4

- **Address exhaustion:** Only ~4.3 billion addresses, which are essentially depleted
- **No built-in security:** IPSec is optional, not mandatory
- **Manual configuration:** Requires DHCP for dynamic addressing
- **Complex headers:** Variable header length adds processing overhead
- **Fragmentation issues:** Routers can fragment packets, adding overhead

## 2. IPv6 (Internet Protocol Version 6)

### Overview

IPv6 is a **128-bit addressing scheme** developed to overcome the limitations of IPv4, providing a virtually unlimited address space.

**Total address space:**
`2^128 = 340 undecillion addresses` (3.4 × 10^38)

This is enough to assign trillions of addresses to every person on Earth.

### Address Format

IPv6 addresses are written in **colon-hexadecimal notation**:

```
2001:0db8:85a3:0000:0000:8a2e:0370:7334
```

- 128 bits total, divided into **8 groups of 16 bits**
- Each group is represented as **4 hexadecimal digits**
- Groups are separated by colons `:`

### Simplification Rules

**Rule 1 — Leading zero suppression:**
`2001:0db8:85a3:0000:0000:8a2e:0370:7334`
becomes → `2001:db8:85a3:0:0:8a2e:370:7334`

**Rule 2 — Consecutive all-zero groups can be replaced with `::`** (only once):
`2001:db8:85a3:0:0:8a2e:370:7334`
becomes → `2001:db8:85a3::8a2e:370:7334`

### IPv6 Address Types

| Type        | Prefix        | Description                                   |
|-------------|---------------|-----------------------------------------------|
| **Unicast** | Various       | One-to-one communication                     |
| **Multicast** | `FF00::/8`  | One-to-many (group) communication            |
| **Anycast** | Same as unicast | Sent to the nearest node with the address  |

There is **no broadcast** in IPv6 — multicast takes its place.

### IPv6 Unicast Address Subtypes

| Subtype                 | Prefix         | Usage                                       |
|-------------------------|----------------|---------------------------------------------|
| **Global Unicast**      | `2000::/3`     | Public internet-routable addresses          |
| **Link-Local**          | `FE80::/10`    | Communication within a single network link |
| **Loopback**            | `::1`          | Equivalent to 127.0.0.1 in IPv4            |
| **Unspecified**         | `::`           | Equivalent to 0.0.0.0 in IPv4              |
| **Unique Local (ULA)**  | `FC00::/7`     | Private use (equivalent to RFC1918 ranges) |

### IPv6 Header Structure

The IPv6 header is a **fixed 40 bytes**, simpler than IPv4:

| Field            | Size    | Purpose                                    |
|------------------|---------|--------------------------------------------|
| Version          | 4 bits  | IP version (6)                             |
| Traffic Class    | 8 bits  | QoS / differentiated services             |
| Flow Label       | 20 bits | Identifies packet flows for QoS           |
| Payload Length   | 16 bits | Length of data following the header       |
| Next Header      | 8 bits  | Type of next header (extension or protocol)|
| Hop Limit        | 8 bits  | Replaces IPv4 TTL                         |
| Source Address   | 128 bits| Sender's IPv6 address                     |
| Destination Address | 128 bits | Receiver's IPv6 address              |

**Key improvement:** No checksum field (handled by upper-layer protocols), and no fragmentation by routers — hosts handle fragmentation.

### IPv6 Key Features

- **Auto-configuration (SLAAC):** Devices can automatically configure their own IP addresses without DHCP using Stateless Address Autoconfiguration.
- **IPSec mandatory:** Security is built into the protocol specification.
- **No fragmentation by routers:** Only source hosts fragment packets (Path MTU Discovery).
- **Simplified header:** Fixed 40-byte header improves router processing speed.
- **No NAT required:** Every device can have a globally routable address.
- **Better multicast support:** More efficient than IPv4 broadcast.

## 3. IPv4 vs IPv6 Comparison

| Feature                 | IPv4                         | IPv6                              |
|-------------------------|------------------------------|-----------------------------------|
| **Address Length**      | 32 bits                      | 128 bits                          |
| **Address Space**       | ~4.3 billion                 | ~3.4 × 10^38 (virtually unlimited)|
| **Notation**            | Dotted decimal (x.x.x.x)     | Colon hexadecimal (x:x:x:x:x:x:x:x) |
| **Header Size**         | 20–60 bytes (variable)       | 40 bytes (fixed)                  |
| **Broadcast**           | Supported                    | Not supported (multicast instead) |
| **Multicast**           | Optional                     | Built-in                          |
| **Anycast**             | Limited                      | Fully supported                   |
| **IPSec**               | Optional                     | Mandatory                         |
| **Fragmentation**       | By routers and hosts         | Only by source host               |
| **Header Checksum**     | Present                      | Absent                            |
| **Auto-configuration**  | Via DHCP                     | SLAAC (stateless) + DHCPv6        |
| **NAT Required**        | Yes (due to shortage)        | No                                |
| **Loopback**            | 127.0.0.1                   | ::1                               |
| **Deployment**          | Widely deployed              | Growing, dual-stack common        |

## 4. Transition Mechanisms (IPv4 to IPv6)

Since both protocols must coexist during the transition period, several mechanisms are used:

### 1. Dual Stack
- Devices run both IPv4 and IPv6 simultaneously.
- Choose based on the destination address.
- Most common approach for modern devices.

### 2. Tunneling
- IPv6 packets are encapsulated inside IPv4 packets.
- Allows IPv6 traffic to travel through IPv4 infrastructure.
- Examples: 6to4, Teredo, ISATAP.

### 3. Translation (NAT64 / DNS64)
- Translates IPv6 packets to IPv4 and vice versa.
- Allows IPv6-only clients to communicate with IPv4-only servers.

---

## Key Takeaways

- IPv4 uses 32-bit addressing; IPv6 uses 128-bit addressing.

- IPv4 is nearly exhausted; IPv6 provides a virtually unlimited address pool.

- IPv6 headers are fixed at 40 bytes — simpler and faster to process.

- IPv6 eliminates broadcast; multicast and anycast replace it.

- IPSec is mandatory in IPv6, making it inherently more secure.

- Dual-stack is the most common IPv4-to-IPv6 transition strategy.

- IPv6 loopback is `::1`; IPv4 loopback is `127.0.0.1`.
