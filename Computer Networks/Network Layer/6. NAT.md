# NAT (Network Address Translation)

**NAT (Network Address Translation)** is a technique used by routers to **modify the source and/or destination IP addresses in packet headers** as they pass through the router.

It was designed to address the **IPv4 address exhaustion problem** by allowing multiple devices within a private network to share a single public IP address for internet access.

---

## 1. Why NAT Exists

IPv4 provides approximately **4.3 billion** unique addresses. With the explosive growth of internet-connected devices, this pool was insufficient.

NAT solved this by allowing organizations to use private, non-routable IP address ranges internally and NAT the traffic to a shared public IP when communicating with the internet.

**Private IP Address Ranges (RFC 1918):**

| Class | Range                         | CIDR Notation    |
|-------|-------------------------------|------------------|
| **A** | 10.0.0.0 – 10.255.255.255    | 10.0.0.0/8       |
| **B** | 172.16.0.0 – 172.31.255.255  | 172.16.0.0/12    |
| **C** | 192.168.0.0 – 192.168.255.255| 192.168.0.0/16   |

These addresses are **not routable on the public internet** — they are only valid within a private network.

---

## 2. How NAT Works

NAT operates on the border router (or firewall) between the private network and the internet.

### Basic NAT Flow

**Outbound (Private → Internet):**

1. Host A (192.168.1.10) sends a packet to a web server (8.8.8.8).
2. The NAT router receives the packet.
3. NAT rewrites the **source IP** from `192.168.1.10` to the router's **public IP** (e.g., `203.0.113.5`).
4. The NAT router stores a mapping in the **NAT translation table**.
5. The modified packet is forwarded to the internet.

**Inbound (Internet → Private):**

1. The web server replies to `203.0.113.5`.
2. The NAT router receives the reply.
3. NAT looks up the translation table to find the original requester.
4. NAT rewrites the **destination IP** back to `192.168.1.10`.
5. The packet is forwarded to Host A.

### NAT Translation Table

| Private IP       | Private Port | Public IP      | Public Port | Protocol |
|------------------|-------------|----------------|-------------|----------|
| 192.168.1.10     | 2345        | 203.0.113.5    | 50001       | TCP      |
| 192.168.1.11     | 3456        | 203.0.113.5    | 50002       | TCP      |
| 192.168.1.12     | 5678        | 203.0.113.5    | 50003       | UDP      |

## 3. Types of NAT

### 3.1 Static NAT (One-to-One Mapping)

A fixed private IP is permanently mapped to a fixed public IP.

**Characteristics:**
- Every private IP has a dedicated public IP
- Bidirectional — external hosts can initiate connections to internal hosts
- Used when internal servers must be reachable from the internet

**Example:**
```
Internal server: 192.168.1.100  ↔  Public IP: 203.0.113.100 (permanent)
```

**Use case:** Web servers, mail servers, FTP servers that must be publicly accessible.

---

### 3.2 Dynamic NAT (Pool-Based Mapping)

A private IP is temporarily mapped to an available public IP from a configured **pool** of public addresses.

**Characteristics:**
- Mapping is created on demand when a connection is initiated
- Mapping is released when the connection terminates
- Number of simultaneous connections is limited by pool size
- Only inside hosts can initiate connections

**Example:**
```
Pool: 203.0.113.1 – 203.0.113.10
192.168.1.10 → 203.0.113.3 (assigned dynamically)
192.168.1.11 → 203.0.113.7 (assigned dynamically)
```

**Use case:** Organizations with a pool of public IPs but more private hosts than public IPs.

---

### 3.3 PAT / NAT Overload (Port Address Translation)

**PAT** (also called **NAT Overload** or **NAPT**) maps **multiple private IP addresses to a single public IP** by using different **port numbers** to distinguish sessions.

This is the most common type of NAT used in homes and enterprises.

**Characteristics:**
- One public IP supports thousands of simultaneous private connections
- Each connection is uniquely identified by a (public IP, public port) combination
- Only inside hosts can initiate connections
- Extremely efficient use of public IP address space

**Example:**

| Host             | Source IP:Port         | Translated IP:Port       |
|------------------|------------------------|--------------------------|
| Host A           | 192.168.1.10:2345      | 203.0.113.5:50001        |
| Host B           | 192.168.1.11:2345      | 203.0.113.5:50002        |
| Host C           | 192.168.1.12:3456      | 203.0.113.5:50003        |

All three hosts share the single public IP `203.0.113.5`, differentiated only by port number.

**Use case:** Home routers (a single public IP shared by all devices), small business networks.

## 4. NAT Terminology

| Term                      | Definition                                                  |
|---------------------------|-------------------------------------------------------------|
| **Inside Local**          | Private IP of the internal host (before NAT)                |
| **Inside Global**         | Public IP representing the internal host (after NAT)        |
| **Outside Local**         | IP of external host as seen inside the network              |
| **Outside Global**        | Actual public IP of the external host                        |

### Example Breakdown

Host A (192.168.1.10) accessing Google (8.8.8.8) through NAT router (203.0.113.5):

| Term               | Value           |
|--------------------|-----------------|
| Inside Local       | 192.168.1.10    |
| Inside Global      | 203.0.113.5     |
| Outside Local      | 8.8.8.8         |
| Outside Global     | 8.8.8.8         |

## 5. Advantages and Disadvantages of NAT

### Advantages

| Advantage                         | Description                                                  |
|-----------------------------------|--------------------------------------------------------------|
| **Conserves IPv4 addresses**      | Many private hosts share one or few public IPs               |
| **Security (implicit firewall)**  | Hides internal network structure from external entities      |
| **Flexible internal addressing**  | Internal IPs can be reassigned without affecting external routing |
| **ISP flexibility**               | Changing ISPs does not require renumbering internal hosts    |

### Disadvantages

| Disadvantage                      | Description                                                  |
|-----------------------------------|--------------------------------------------------------------|
| **Breaks end-to-end principle**   | External hosts cannot initiate connections to internal hosts |
| **Performance overhead**          | Every packet header must be rewritten by the NAT device      |
| **Complicates some protocols**    | Protocols that embed IP addresses in payload (FTP, SIP, IPSec) need special handling (ALG) |
| **Troubleshooting complexity**    | Harder to trace connections across NAT boundaries            |
| **Not a security solution**       | NAT is not a substitute for a proper firewall                |

---

## 6. NAT and IPv6

With IPv6, every device can have a globally routable address, eliminating the primary reason for NAT — address conservation.

However, some organizations still use **NAT66** (IPv6 NAT) for:
- Network renumbering simplification
- Privacy (hiding internal topology)
- Transition between IPv4 and IPv6 (NAT64)

**NAT64:** Translates between IPv6 and IPv4, allowing IPv6-only clients to communicate with IPv4 servers.

---

## 7. NAT in Practice

### Home Router (PAT)

A typical home router uses PAT:
- All devices (laptop, phone, TV, etc.) share the ISP-assigned public IP
- The router assigns ephemeral port numbers to each session
- The router's NAT table tracks all active sessions

### Port Forwarding

Port forwarding is a **static NAT rule** that redirects traffic arriving at a specific public port to a specific internal host:

```
Incoming: 203.0.113.5:80  →  Internal: 192.168.1.100:80
```

Used to make internal servers (web, game, VPN) accessible from the internet.

---

## 8. Comparison: Static NAT vs Dynamic NAT vs PAT

| Feature              | Static NAT          | Dynamic NAT              | PAT (NAT Overload)         |
|----------------------|---------------------|--------------------------|----------------------------|
| **Mapping**          | One-to-one (fixed)  | One-to-one (dynamic)     | Many-to-one                |
| **Public IPs needed**| One per host        | Pool (1 per active host) | One for all hosts           |
| **Initiated by**     | Either side         | Inside only              | Inside only                 |
| **Port translation** | No                  | No                       | Yes                         |
| **Use case**         | Public servers      | Dynamic access pool      | Home/enterprise internet access |
| **Address conservation** | Low           | Medium                   | Very High                   |

---

## Key Takeaways

- NAT translates private IP addresses to public IP addresses at the router level.

- Static NAT provides a fixed one-to-one mapping — useful for hosting public-facing servers.

- Dynamic NAT uses a pool of public IPs assigned on demand — limited to pool size.

- PAT (NAT Overload) maps many private IPs to one public IP using port numbers — most common type.

- NAT tables track active sessions using (IP, port, protocol) tuples.

- NAT breaks the end-to-end connectivity principle — external hosts cannot initiate connections to NAT-ed internal hosts without port forwarding.

- IPv6 eliminates the need for NAT due to its vast address space, though transition mechanisms like NAT64 still use translation.
