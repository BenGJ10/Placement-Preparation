# Address Resolution Protocol (ARP)
![ARP](https://marvel-b1-cdn.bc0a.com/f00000000310757/www.fortinet.com/content/dam/fortinet/images/cyberglossary/what-is-arp.jpg)

---

## 1. What is ARP?

**ARP (Address Resolution Protocol)** is a Network Layer protocol used to map:

IP Address → MAC Address

Although ARP is conceptually associated with the Network Layer (Layer 3), it operates between:

* Network Layer (IP)
* Data Link Layer (MAC/Ethernet)

ARP is required because:

* IP addresses are logical addresses used for routing.
* MAC addresses are physical addresses used for local delivery inside a LAN.

Routers forward packets using IP addresses, but actual frame delivery inside a local network happens using MAC addresses.

---

## 2. Why ARP is Needed?

Suppose a device wants to send data to another device within the same local network.

The sender knows:

* Destination IP address

But it does NOT know:

* Destination MAC address

Without the MAC address, it cannot create the Ethernet frame.

This is where ARP is used.

---

## 3. ARP Working (Same Network Case)

Let’s take a practical example.

### Network Setup

Device A:
IP → 192.168.1.10
MAC → AA:AA:AA:AA:AA:AA

Device B:
IP → 192.168.1.20
MAC → BB:BB:BB:BB:BB:BB

Both are connected to the same LAN via a switch.

---

### Step 1: Check ARP Cache

Device A first checks its ARP table (cache).

Command in Linux:
arp -a

If mapping already exists:
192.168.1.20 → BB:BB:BB:BB:BB:BB

Then no ARP broadcast is needed.

If not found, ARP process begins.

---

### Step 2: ARP Request (Broadcast)

Device A sends an ARP Request:

Destination MAC → FF:FF:FF:FF:FF:FF (Broadcast)
Source MAC → AA:AA:AA:AA:AA:AA

Message:

“Who has IP 192.168.1.20? Tell 192.168.1.10”

This broadcast is received by ALL devices in the LAN.

---

### Step 3: ARP Reply (Unicast)

Only Device B recognizes that:

IP = 192.168.1.20 (matches)

So Device B replies directly to Device A:

Destination MAC → AA:AA:AA:AA:AA:AA
Source MAC → BB:BB:BB:BB:BB:BB

Message:

“192.168.1.20 is at BB:BB:BB:BB:BB:BB”

This is a unicast reply.

---

### Step 4: ARP Table Update

Device A stores mapping in its ARP cache:

192.168.1.20 → BB:BB:BB:BB:BB:BB

Now it can send Ethernet frames directly to Device B.

## 4. ARP Packet Format

An ARP packet consists of the following fields:

### ARP Header Fields

1. **Hardware Type (HTYPE)**
   Identifies the type of physical network.

   * Ethernet = 1

2. **Protocol Type (PTYPE)**
   Identifies the protocol being mapped.

   * IPv4 = 0x0800

3. **Hardware Address Length (HLEN)**
   Length of the hardware address.

   * 6 bytes for MAC address

4. **Protocol Address Length (PLEN)**
   Length of the protocol address.

   * 4 bytes for IPv4

5. **Opcode**
   Specifies the type of ARP message.

   | Opcode | Meaning     |
   | ------ | ----------- |
   | 1      | ARP Request |
   | 2      | ARP Reply   |

6. **Sender MAC Address**

7. **Sender IP Address**

8. **Target MAC Address**

9. **Target IP Address**

### Important Notes

* In an **ARP Request**, the Target MAC address is set to `00:00:00:00:00:00` because it is unknown.
* In an **ARP Reply**, the Target MAC field contains the actual resolved MAC address.

## 5. What Happens if Destination is in a Different Network?

ARP operates only within the local broadcast domain. When a destination IP belongs to a different network, ARP resolves the MAC address of the **default gateway**, not the final destination.

### Step-by-Step Process

Assume:

Device A
IP: 192.168.1.10
Subnet: 255.255.255.0
Gateway: 192.168.1.1

Destination IP: 192.168.2.50

### Step 1: Subnet Check

Device A checks whether the destination IP belongs to its subnet.

* If destination ∈ 192.168.1.0/24 → Same network
* If destination ∉ 192.168.1.0/24 → Different network

Since 192.168.2.50 is outside 192.168.1.0/24, it is a different network.

### Step 2: ARP for Gateway

Instead of resolving:

Destination IP → Destination MAC

The device resolves:

Gateway IP → Gateway MAC

### Step 3: Frame Transmission

1. Device A sends an ARP request for 192.168.1.1
2. Router replies with its MAC address
3. Device A sends the Ethernet frame to the router
4. The router forwards the packet to the correct network

### Key Rule

ARP never resolves the MAC address of a host outside the local network.
It only resolves MAC addresses within the local broadcast domain.

## 6. ARP Cache (ARP Table)

Each device maintains an ARP cache (also called the ARP table) to store IP-to-MAC mappings.

### Purpose

The ARP cache prevents repeated broadcasts for the same IP address and improves network efficiency.

### Example ARP Table

| IP Address   | MAC Address       | State     |
| ------------ | ----------------- | --------- |
| 192.168.1.1  | 00:11:22:33:44:55 | REACHABLE |
| 192.168.1.20 | BB:BB:BB:BB:BB:BB | STALE     |

### Viewing the ARP Table

Windows:

```
arp -a
```

Linux:

```
ip neigh
```

### Entry Types

1. **Dynamic Entries**

   * Learned automatically through ARP requests and replies
   * Expire after a timeout period

2. **Static Entries**

   * Manually configured
   * Do not expire automatically
   * Used in controlled or security-sensitive environments

### Entry Lifetime

* ARP entries are temporary by default
* They expire after a specific timeout
* They are refreshed when communication continues

### Importance of ARP Cache

Without ARP caching:

* Every packet transmission would require a broadcast
* Network traffic would increase significantly
* Performance would degrade

ARP caching ensures efficient local communication by minimizing unnecessary broadcasts.

## 7. Types of ARP

### 1. Standard ARP

Normal IP → MAC resolution.

### 2. Gratuitous ARP

A device broadcasts its own IP-MAC mapping.
Used for:

* Duplicate IP detection
* Updating ARP tables

### 3. Reverse ARP (RARP)

MAC → IP mapping (obsolete now, replaced by DHCP).

### 4. Proxy ARP

Router responds to ARP request on behalf of another device.

---

## 8. ARP vs DNS (Common Interview Confusion)

ARP:
IP → MAC
Used inside LAN

DNS:
Domain → IP
Used globally

ARP works only within local broadcast domain.

---

## 9. Security Issue: ARP Spoofing

Since ARP has no authentication, it is vulnerable to attack.

**ARP Spoofing**:

Attacker sends fake ARP replies:
“Gateway IP is at attacker MAC”

Result:
Traffic gets redirected to attacker (Man-in-the-Middle attack).

Protection:

* Dynamic ARP inspection
* Static ARP entries
* Network monitoring tools

---

## 10. Complete Flow Summary (Same Network)

1. Sender checks ARP cache
2. If not found → Broadcast ARP request
3. Target device replies with MAC
4. Sender updates ARP table
5. Data transmission begins

---

## Key Takeaways

* ARP maps IP addresses to MAC addresses.

* It works only inside local networks.

* ARP request is broadcast.

* ARP reply is unicast.

* Entries are stored in ARP cache.

* ARP has security vulnerabilities.

* If destination is outside LAN, ARP resolves gateway MAC, not final host MAC.
