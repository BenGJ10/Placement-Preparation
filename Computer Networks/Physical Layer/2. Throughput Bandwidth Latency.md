# Bandwidth, Throughput, Latency

![Bandwidth Manager](https://images.ctfassets.net/aoyx73g9h2pg/2RSeqHqi6GRPrU4b6UFIEs/9ea7cceb14b65c0b900bdf199427ae80/Bandwidth-Management-Diagram.jpg)

In computer networks, **Bandwidth**, **Throughput**, and **Latency** are three fundamental performance metrics.

They define:

* How much data *can* be transmitted
* How much data is *actually* transmitted
* How long data takes to travel

These concepts are heavily asked in interviews and are critical for system design and troubleshooting.

---

## 1. Bandwidth

**Bandwidth** is:

> The maximum data carrying capacity of a network link per unit time.

It represents the theoretical upper limit of data transfer.

---

### Unit

* Measured in **bits per second (bps)**
* Common units:

  * Kbps (10³)
  * Mbps (10⁶)
  * Gbps (10⁹)
  * Tbps (10¹²)

---

### Example

If a link supports **100 Mbps**, it means:

It can transmit **100 million bits per second** under ideal conditions.

---

### Important Points

* It is a **theoretical maximum**
* Higher bandwidth does NOT always mean faster download
* Determined by:

  * Physical medium
  * Network technology
  * Hardware capability

---

## Real-World Analogy

Think of bandwidth as:

> The width of a highway.

More lanes → more cars can travel simultaneously.

---

## 2. Throughput

**Throughput** is:

> The actual amount of data successfully transmitted per unit time.

It is always:

```
Throughput ≤ Bandwidth
```

---

### Unit

* Measured in **bps**
* Often shown as Mbps or Gbps

---

### Why Throughput is Lower than Bandwidth?

Because of:

* Network congestion
* Packet loss
* Retransmissions
* Protocol overhead (headers)
* Hardware limitations

---

### Example

Bandwidth = 100 Mbps
Actual data transfer = 72 Mbps

So:

```
Throughput = 72 Mbps
```

---

### Goodput (Advanced Concept)

Goodput = Useful data rate
(Excludes headers and retransmissions)

```
Goodput ≤ Throughput ≤ Bandwidth
```

---

### Real-World Analogy

If bandwidth is highway width:

Throughput = number of cars that actually reach destination successfully.

---

## 3. Latency

**Latency** is:

> The total time taken for a packet to travel from source to destination.

Measured in:

* Milliseconds (ms)

Lower latency = Faster response.

---

### Components of Latency

Total latency consists of:

```
Latency = Processing Delay
        + Queuing Delay
        + Transmission Delay
        + Propagation Delay
```

---

### 1. Processing Delay

* Time taken by router to examine packet header
* Usually microseconds

---

### 2. Queuing Delay

* Time packet waits in router buffer
* Depends on congestion
* Can vary significantly

---

### 3. Transmission Delay

Time required to push all packet bits onto the link.

Formula:

```
Transmission Delay = Packet Size / Bandwidth
```

Example:

Packet size = 1,000 bits
Bandwidth = 1 Mbps

```
1000 / 1,000,000 = 0.001 sec = 1 ms
```

---

### 4. Propagation Delay

Time taken for signal to travel across medium.

Formula:

```
Propagation Delay = Distance / Propagation Speed
```

Propagation speed ≈ 2 × 10⁸ m/s (in fiber)

---

### Important Distinction

| Concept            | Meaning                     |
| ------------------ | --------------------------- |
| Transmission Delay | Time to send bits onto wire |
| Propagation Delay  | Time for signal to travel   |

---

### Real-World Analogy

Latency is like:

> The total travel time of a car from start to destination.

Even if highway is wide (high bandwidth), distance (propagation delay) still matters.

---

## 4. Comparison Table

| Parameter   | Bandwidth         | Throughput              | Latency               |
| ----------- | ----------------- | ----------------------- | --------------------- |
| Definition  | Maximum capacity  | Actual data transferred | Time delay            |
| Unit        | bps               | bps                     | milliseconds          |
| Nature      | Theoretical       | Practical               | Time-based            |
| Affected by | Medium & hardware | Congestion & errors     | Distance & processing |
| Goal        | Higher is better  | Higher is better        | Lower is better       |

---

## 5. Practical Scenarios

### 1. Video Streaming

* Needs high bandwidth
* Moderate latency acceptable

### 2. Online Gaming

* Low latency critical
* Moderate bandwidth sufficient

### 3. File Download

* High throughput required
* Latency less important

### 4. Stock Trading Systems

* Ultra-low latency required

---


## 7. Formula Summary

Transmission Delay:

```
Packet Size / Bandwidth
```

Propagation Delay:

```
Distance / Speed
```

Total Latency:

```
Processing + Queuing + Transmission + Propagation
```

---

## Key Takeaways

* **Bandwidth** = Maximum capacity

* **Throughput** = Actual achieved rate

* **Latency** = Time delay

* Throughput ≤ Bandwidth

* Low latency is critical for real-time systems

* Bandwidth affects transmission delay only

* Distance affects propagation delay

* Congestion affects queuing delay
