# SQL Views

A **View** in SQL is a **virtual table** that provides a **stored query result** from one or more tables.  
It doesn’t store data itself but displays data **dynamically from the base tables** when queried.

> **Think of a View as a saved SQL query that acts like a table.**

---

## Definition

- A **view** is created using the `CREATE VIEW` statement.  

- It can include **SELECT**, **JOIN**, **WHERE**, **GROUP BY**, and **HAVING** clauses.

- The data in a view is **updated automatically** when the underlying tables are modified.

---

## Syntax

```sql
CREATE VIEW view_name AS
SELECT column1, column2, ...
FROM table_name
WHERE condition;
````

---

## Example 

Suppose we have a table named **Employees**:

| EmpID | Name  | Department | Salary | Location |
| ----- | ----- | ---------- | ------ | -------- |
| 101   | Alice | HR         | 50000  | Delhi    |
| 102   | Bob   | IT         | 70000  | Mumbai   |
| 103   | Carol | IT         | 75000  | Delhi    |
| 104   | David | Sales      | 45000  | Chennai  |

---

### Create a Simple View

```sql
CREATE VIEW IT_Employees AS
SELECT Name, Salary, Location
FROM Employees
WHERE Department = 'IT';
```

Now, querying the view:

```sql
SELECT * FROM IT_Employees;
```

**Result:**

| Name  | Salary | Location |
| ----- | ------ | -------- |
| Bob   | 70000  | Mumbai   |
| Carol | 75000  | Delhi    |

---

### Creating a View with Join

```sql
CREATE VIEW Employee_Dept AS
SELECT E.EmpID, E.Name, D.DeptName, D.Manager
FROM Employees E
JOIN Departments D
ON E.Department = D.DeptID;
```

This view combines information from both tables to make querying easier.

---

### Creating a View with Aggregation

```sql
CREATE VIEW Dept_Salary AS
SELECT Department, AVG(Salary) AS AvgSalary
FROM Employees
GROUP BY Department;
```

**Querying the View:**

```sql
SELECT * FROM Dept_Salary;
```

---

## Modifying a View

To modify an existing view:

```sql
CREATE OR REPLACE VIEW IT_Employees AS
SELECT Name, Salary
FROM Employees
WHERE Department = 'IT' AND Location = 'Delhi';
```

---

## Dropping a View

To delete an existing view:

```sql
DROP VIEW view_name;
```

Example:

```sql
DROP VIEW IT_Employees;
```

---

## Updating Data Through a View

In some cases, you can **insert, update, or delete** data using a view.
However, **it depends** on whether the view is **updatable** or not.

### Updatable Views

You can update data in a view **if:**

* It is based on a single table.
* It doesn’t use aggregation, DISTINCT, GROUP BY, or JOIN.

**Example:**

```sql
UPDATE IT_Employees
SET Salary = 80000
WHERE Name = 'Bob';
```

**❗️This will update the base table (Employees) as well.**

---

### Non-Updatable Views

Views **cannot be updated** if they include:

* Aggregate functions (`SUM`, `AVG`, etc.)

* `GROUP BY` or `HAVING` clauses

* `DISTINCT` keyword

* `UNION` or `JOIN`

* Subqueries

---

## Materialized View (Advanced)

A **Materialized View** is a **physical copy** of a query’s result stored in memory or disk.
Unlike a normal view, it **stores data** and must be **refreshed** manually or automatically.

```sql
CREATE MATERIALIZED VIEW sales_summary AS
SELECT region, SUM(sales_amount)
FROM sales
GROUP BY region;
```

* **Normal View** → Virtual (no data stored)
* **Materialized View** → Physical (data stored and can be refreshed)

---

## Advantages of Views

| **Advantage**                   | **Explanation**                                             |
| ------------------------------- | ----------------------------------------------------------- |
| **Data Security**               | Users can be restricted to view only specific columns/rows. |
| **Simplifies Queries**          | Complex joins and filters can be saved as reusable views.   |
| **Data Independence**           | Changes in base tables don’t affect view users.             |
| **Logical Data Representation** | Provides abstracted or combined data from multiple tables.  |
| **Code Reusability**            | Common query logic can be encapsulated in a view.           |

---

## Disadvantages of Views

| **Disadvantage**                  | **Explanation**                                    |
| --------------------------------- | -------------------------------------------------- |
| **Performance Overhead**          | Views are re-executed each time they are accessed. |
| **Non-updatable Restrictions**    | Some views can’t be modified directly.             |
| **Dependency Maintenance**        | Dropping/altering base tables may affect the view. |
| **Storage in Materialized Views** | They consume additional space.                     |

---

## View vs Materialized View

| Feature            | **View**                 | **Materialized View**          |
| ------------------ | ------------------------ | ------------------------------ |
| **Storage**        | Virtual (no data stored) | Physically stores data         |
| **Data Freshness** | Always up-to-date        | May be outdated                |
| **Performance**    | Slower for large queries | Faster for repeated access     |
| **Maintenance**    | No manual refresh needed | Requires refresh (manual/auto) |
| **Use Case**       | Simple query abstraction | Performance optimization       |
