# SQL Stored Procedures

A **Stored Procedure** is a **prewritten SQL code** stored in the database that performs specific operations.

It can be executed repeatedly with different parameters without rewriting the code.

> **Think of a stored procedure as a function/method in programming — write once, call many times.**

---

## Definition

- A **stored procedure** is a **set of SQL statements** stored in the database.

- It can have **input parameters** and **output parameters**.

- It can perform **multiple operations** (SELECT, INSERT, UPDATE, DELETE).

- It is **compiled and optimized** by the database.

- It is **executed by calling its name** instead of writing full SQL code.

---

## Why Use Stored Procedures?

### Without Stored Procedures
```
Every time you need to insert an employee:
1. Write INSERT query
2. Check if email exists
3. Add to Employees table
4. Add to Benefits table
5. Send notification

Repeat this in every application/script!
```

### With Stored Procedures
```sql
-- Define once
CREATE PROCEDURE AddEmployee (Name, Email, ...)
  ...SQL code...
END;

-- Use everywhere
CALL AddEmployee('Alice', 'alice@example.com', ...);
CALL AddEmployee('Bob', 'bob@example.com', ...);
```

---

## Advantages of Stored Procedures

✓ **Code reusability** — Write once, use many times  
✓ **Reduced network traffic** — Send parameters instead of full SQL  
✓ **Better security** — Hide database structure from applications  
✓ **Performance** — Precompiled and optimized  
✓ **Centralized logic** — Business logic in database  
✓ **Transaction control** — Atomic operations  

---

## Disadvantages of Stored Procedures

✗ **Database dependency** — Tied to specific DBMS  
✗ **Harder debugging** — Errors less obvious  
✗ **Development complexity** — SQL/PL-SQL skills needed  
✗ **Maintenance** — Changes require database update  
✗ **Version control** — Hard to track in Git  

---

## Syntax

```sql
CREATE PROCEDURE procedure_name (
  [IN|OUT|INOUT] parameter1 datatype,
  [IN|OUT|INOUT] parameter2 datatype
)
[CHARACTERISTICS]
BEGIN
  -- SQL statements
END;
```

### Parameter Types

**IN** — Input parameter (default)  
**OUT** — Output parameter (returns value)  
**INOUT** — Both input and output

## Examples

### Example 1: Simple Procedure (No Parameters)

```sql
CREATE PROCEDURE GetAllEmployees()
BEGIN
  SELECT * FROM Employees;
END;

-- Call it:
CALL GetAllEmployees();
```

---

### Example 2: Procedure with IN Parameter

```sql
CREATE PROCEDURE GetEmployeeByDept(IN dept_name VARCHAR(50))
BEGIN
  SELECT * FROM Employees WHERE Department = dept_name;
END;

-- Call it:
CALL GetEmployeeByDept('IT');
CALL GetEmployeeByDept('HR');
```

---

### Example 3: Procedure with OUT Parameter

```sql
CREATE PROCEDURE GetEmployeeCount(OUT emp_count INT)
BEGIN
  SELECT COUNT(*) INTO emp_count FROM Employees;
END;

-- Call it:
CALL GetEmployeeCount(@total);
SELECT @total;  -- Displays the count
```

---

### Example 4: Multiple Operations

```sql
CREATE PROCEDURE AddEmployeeWithBenefits(
  IN emp_name VARCHAR(100),
  IN salary DECIMAL(10,2),
  OUT emp_id INT
)
BEGIN
  -- Insert employee
  INSERT INTO Employees (Name, Salary) VALUES (emp_name, salary);
  
  -- Get inserted ID
  SET emp_id = LAST_INSERT_ID();
  
  -- Add benefits
  INSERT INTO Benefits (EmpID, HealthInsurance) VALUES (emp_id, 1);
END;

-- Call it:
CALL AddEmployeeWithBenefits('Alice', 50000, @newID);
SELECT @newID;
```

---

### Example 5: With Control Flow

```sql
CREATE PROCEDURE ClassifyEmployee(
  IN salary DECIMAL(10,2),
  OUT classification VARCHAR(50)
)
BEGIN
  IF salary > 100000 THEN
    SET classification = 'Senior';
  ELSEIF salary > 50000 THEN
    SET classification = 'Mid-Level';
  ELSE
    SET classification = 'Junior';
  END IF;
END;

-- Call it:
CALL ClassifyEmployee(75000, @class);
SELECT @class;  -- Displays 'Mid-Level'
```

## Procedure vs Function

| Aspect | Procedure | Function |
|--------|-----------|----------|
| **Returns** | Can have OUT parameters | Always returns single value |
| **Used in** | CALL statement | SELECT, WHERE, etc. |
| **Purpose** | Perform actions | Compute values |
| **Side effects** | Can modify data | Should not |
| **Example** | AddEmployee() | SQRT(), UPPER() |

### Procedure Example
```sql
CREATE PROCEDURE UpdateSalary(IN emp_id INT, IN new_salary INT)
BEGIN
  UPDATE Employees SET Salary = new_salary WHERE EmpID = emp_id;
END;

CALL UpdateSalary(101, 60000);
```

### Function Example
```sql
CREATE FUNCTION CalculateBonus(salary DECIMAL) RETURNS DECIMAL
BEGIN
  RETURN salary * 0.1;
END;

SELECT Name, Salary, CalculateBonus(Salary) as Bonus FROM Employees;
```

## Variables in Procedures

### Declare Variables

```sql
CREATE PROCEDURE CalculateSalaryStats()
BEGIN
  DECLARE total_salary DECIMAL(15,2);
  DECLARE avg_salary DECIMAL(10,2);
  DECLARE emp_count INT;
  
  SELECT COUNT(*) INTO emp_count FROM Employees;
  SELECT SUM(Salary) INTO total_salary FROM Employees;
  SET avg_salary = total_salary / emp_count;
  
  SELECT emp_count, total_salary, avg_salary;
END;
```

## Control Structures

### IF Statement

```sql
CREATE PROCEDURE CheckPerformance(IN emp_id INT)
BEGIN
  DECLARE monthly_sales DECIMAL(10,2);
  
  SELECT SUM(SalesAmount) INTO monthly_sales 
  FROM Sales 
  WHERE EmpID = emp_id AND MONTH(Date) = MONTH(NOW());
  
  IF monthly_sales > 100000 THEN
    SELECT 'Excellent' as Rating;
  ELSEIF monthly_sales > 50000 THEN
    SELECT 'Good' as Rating;
  ELSE
    SELECT 'Needs Improvement' as Rating;
  END IF;
END;
```

### LOOP Statement

```sql
CREATE PROCEDURE GenerateNumbers(IN count INT)
BEGIN
  DECLARE i INT DEFAULT 1;
  
  LOOP
    INSERT INTO Numbers VALUES (i);
    SET i = i + 1;
    IF i > count THEN
      LEAVE;
    END IF;
  END LOOP;
END;
```

## Transactions in Procedures

```sql
CREATE PROCEDURE TransferMoney(
  IN from_account INT,
  IN to_account INT,
  IN amount DECIMAL(10,2)
)
BEGIN
  START TRANSACTION;
  
  UPDATE Accounts SET Balance = Balance - amount WHERE AccountID = from_account;
  UPDATE Accounts SET Balance = Balance + amount WHERE AccountID = to_account;
  
  IF ROW_COUNT() = 2 THEN
    COMMIT;
  ELSE
    ROLLBACK;
  END IF;
END;
```

## Error Handling

```sql
CREATE PROCEDURE SafeInsertEmployee(
  IN emp_name VARCHAR(100),
  IN salary DECIMAL(10,2)
)
BEGIN
  DECLARE EXIT HANDLER FOR SQLEXCEPTION
  BEGIN
    SELECT 'Error: Employee not added' as Message;
    ROLLBACK;
  END;
  
  START TRANSACTION;
  INSERT INTO Employees (Name, Salary) VALUES (emp_name, salary);
  COMMIT;
END;
```

## Real-World Example: Order Processing

```sql
CREATE PROCEDURE PlaceOrder(
  IN customer_id INT,
  IN product_id INT,
  IN quantity INT,
  OUT order_id INT
)
BEGIN
  DECLARE product_price DECIMAL(10,2);
  DECLARE total_amount DECIMAL(10,2);
  
  -- Get product price
  SELECT Price INTO product_price FROM Products WHERE ProductID = product_id;
  
  -- Calculate total
  SET total_amount = product_price * quantity;
  
  -- Start transaction
  START TRANSACTION;
  
  -- Insert order
  INSERT INTO Orders (CustomerID, OrderDate, TotalAmount) 
  VALUES (customer_id, NOW(), total_amount);
  SET order_id = LAST_INSERT_ID();
  
  -- Insert order items
  INSERT INTO OrderItems (OrderID, ProductID, Quantity, Price) 
  VALUES (order_id, product_id, quantity, product_price);
  
  -- Update inventory
  UPDATE Products SET Stock = Stock - quantity WHERE ProductID = product_id;
  
  COMMIT;
END;

-- Call it:
CALL PlaceOrder(5, 102, 3, @newOrderID);
SELECT @newOrderID;
```

## Performance Considerations

| Aspect | Benefit |
|--------|---------|
| **Network** | Reduces data transfer (parameters only) |
| **Compilation** | Already compiled (faster execution) |
| **Optimization** | Database engine optimizes once |
| **Caching** | Can be cached by DBMS |

## Key Takeaways

- **Stored procedures** encapsulate business logic in database.

- **IN/OUT parameters** control data flow.

- **Variables and control structures** enable complex logic.

- **Transactions** ensure data consistency.

- **Performance benefit** from precompilation and reduced network traffic.

- Interview focus: **creating procedures, parameters, transactions, control flow, real-world scenarios, when to use vs when not**.
