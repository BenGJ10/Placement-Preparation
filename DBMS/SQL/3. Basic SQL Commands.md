# Basic SQL Commands (DDL, DML, DCL, TCL) with Examples

SQL commands are categorized based on their purpose and functionality.  
They help manage both the **structure** and the **data** within a database.

---

## 1. DDL – Data Definition Language

**Definition:**  
DDL commands are used to **define**, **create**, and **modify** the structure of database objects such as tables, schemas, and indexes.

**Common DDL Commands:**
- `CREATE`
- `ALTER`
- `DROP`
- `TRUNCATE`
- `RENAME`

---

### CREATE
Used to create a new database or table.

```sql
-- Create a database
CREATE DATABASE school;

-- Create a table
CREATE TABLE Students (
    StudentID INT PRIMARY KEY,
    Name VARCHAR(50),
    Age INT,
    Marks FLOAT
);
````

---

### ALTER

Used to modify an existing table structure (add, delete, or modify columns).

```sql
-- Add a new column
ALTER TABLE Students ADD COLUMN Email VARCHAR(100);

-- Modify a column data type
ALTER TABLE Students MODIFY Marks DECIMAL(5,2);

-- Rename a column
ALTER TABLE Students RENAME COLUMN Name TO StudentName;
```

---

### DROP

Deletes an entire table or database permanently.

```sql
-- Delete a table
DROP TABLE Students;

-- Delete a database
DROP DATABASE school;
```

⚠️ **Note:** Once dropped, the data cannot be recovered.

### TRUNCATE

Removes **all records** from a table but keeps its structure.

```sql
TRUNCATE TABLE Students;
```

Difference between `DELETE` and `TRUNCATE`:

| Command  | Deletes Structure? | Can Rollback? | Speed  |
| -------- | ------------------ | ------------- | ------ |
| DELETE   | No                 | Yes           | Slower |
| TRUNCATE | No                 | No            | Faster |

---

### 🔹 RENAME

Renames a table.

```sql
RENAME TABLE Students TO StudentInfo;
```

---

## 2. DML – Data Manipulation Language

**Definition:**
DML commands are used to **insert**, **update**, **retrieve**, and **delete** data inside the database tables.

**Common DML Commands:**

* `INSERT`
* `SELECT`
* `UPDATE`
* `DELETE`

---

### INSERT

Used to add new data into a table.

```sql
INSERT INTO Students (StudentID, StudentName, Age, Marks, Email)
VALUES (101, 'Alice', 20, 89.5, 'alice@gmail.com');
```

### SELECT

Used to retrieve data from one or more tables.

```sql
-- Retrieve all columns
SELECT * FROM Students;

-- Retrieve specific columns
SELECT StudentName, Marks FROM Students WHERE Marks > 80;
```

### UPDATE

Used to modify existing records.

```sql
UPDATE Students
SET Marks = 95
WHERE StudentID = 101;
```

### DELETE

Used to remove records from a table.

```sql
DELETE FROM Students WHERE StudentID = 101;
```

---

## 3. DCL – Data Control Language

**Definition:**
DCL commands are used to **control access** to data in the database.
They help in defining **user permissions** and **security levels**.

**Common DCL Commands:**

* `GRANT`
* `REVOKE`

---

### GRANT

Gives specific permissions to users.

```sql
GRANT SELECT, INSERT ON school.Students TO 'user1'@'localhost';
```

### REVOKE

Takes back permissions from users.

```sql
REVOKE INSERT ON school.Students FROM 'user1'@'localhost';
```

---

## 4. TCL – Transaction Control Language

**Definition:**
TCL commands manage **transactions** in a database.
A **transaction** is a logical unit of work that must be **fully completed** or **not executed at all** — ensuring **data integrity**.

**Common TCL Commands:**

* `COMMIT`
* `ROLLBACK`
* `SAVEPOINT`

---

### COMMIT

Saves all changes made by the transaction permanently in the database.

```sql
UPDATE Students SET Marks = 90 WHERE StudentID = 102;
COMMIT;
```

### ROLLBACK

Undo the changes made by the current transaction.

```sql
DELETE FROM Students WHERE Marks < 50;
ROLLBACK;
```

After rollback, the deleted records are restored.

### SAVEPOINT

Creates a temporary point within a transaction to which you can rollback later.

```sql
SAVEPOINT BeforeUpdate;

UPDATE Students SET Marks = Marks + 5;

ROLLBACK TO BeforeUpdate;
```

**Quick Recap:**

* **DDL** – Defines structure.

* **DML** – Manipulates data.

* **DCL** – Controls access.

* **TCL** – Manages transactions.

Each plays a crucial role in maintaining a robust, secure, and reliable **database environment**.
