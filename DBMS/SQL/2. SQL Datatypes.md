# Data Types in SQL

**SQL Data Types** define the **type of data** that can be stored in a column of a table.  
Choosing the correct data type is important for **data integrity**, **storage efficiency**, and **query performance**.

---

## Categories of SQL Data Types

SQL data types can be broadly categorized as:

1. **Numeric Data Types**

2. **Character / String Data Types**

3. **Date and Time Data Types**

4. **Binary Data Types**

5. **Miscellaneous / Other Data Types**

---

## 1️⃣ Numeric Data Types

Used to store numeric values like integers, decimals, or floating-point numbers.

| Data Type | Description | Example |
|------------|-------------|----------|
| **INT / INTEGER** | Whole numbers (positive or negative) | `100`, `-23` |
| **SMALLINT** | Smaller range of integer values | `32767` |
| **BIGINT** | Large integer values | `9223372036854775807` |
| **DECIMAL(p, s)** / **NUMERIC(p, s)** | Fixed-point numbers with precision `(p)` and scale `(s)` | `DECIMAL(6,2)` → `1234.56` |
| **FLOAT(n)** / **REAL** | Approximate floating-point values | `3.14159` |
| **BIT** | Boolean type; stores 0 or 1 | `1` (True), `0` (False) |

> 💡 **Tip:** Use `INT` for counters and IDs, `DECIMAL` for financial calculations to avoid rounding errors.

---

## 2️⃣ Character / String Data Types

Used to store text or string-based information.

| Data Type | Description | Example |
|------------|-------------|----------|
| **CHAR(n)** | Fixed-length string; always uses `n` bytes | `'YES'`, `'NO '` |
| **VARCHAR(n)** | Variable-length string up to `n` characters | `'Hello'` |
| **TEXT / CLOB** | Large text data, like paragraphs | `'This is a long description.'` |
| **NCHAR(n)** / **NVARCHAR(n)** | Unicode characters for multi-language support | `'こんにちは'`, `'你好'` |


> 💡 **Tip:** Use `CHAR` when all values have a fixed length (e.g., country codes).  

> 💡 **Tip:** Use `VARCHAR` when length varies.

---

## 3️⃣ Date and Time Data Types

Used to represent date and time information.

| Data Type | Description | Example |
|------------|-------------|----------|
| **DATE** | Stores date in `YYYY-MM-DD` format | `'2025-10-07'` |
| **TIME** | Stores time in `HH:MM:SS` format | `'14:30:00'` |
| **DATETIME** / **TIMESTAMP** | Stores date and time together | `'2025-10-07 14:30:00'` |
| **YEAR** | Stores year in 2- or 4-digit format | `'2025'` |
| **INTERVAL** | Represents a time duration | `'3 days'`, `'5 hours'` |

> 💡 **Tip:** Use `TIMESTAMP` for tracking record creation or update times (with `CURRENT_TIMESTAMP`).

---

## 4️⃣ Binary Data Types

Used to store data in **raw binary format**, such as images, files, or multimedia.

| Data Type | Description | Example |
|------------|-------------|----------|
| **BINARY(n)** | Fixed-length binary data | `01010101` |
| **VARBINARY(n)** | Variable-length binary data | `0x4F2A` |
| **BLOB (Binary Large Object)** | Stores large binary data (e.g., images, PDFs) | Image bytes |

---

## 5️⃣ Miscellaneous Data Types

Other specialized data types supported by various SQL dialects.

| Data Type | Description | Example |
|------------|-------------|----------|
| **BOOLEAN** | Stores TRUE or FALSE values | `TRUE` |
| **ENUM** | Stores predefined set of string values | `ENUM('small', 'medium', 'large')` |
| **SET** | Stores multiple predefined values | `SET('A', 'B', 'C')` |
| **JSON** | Stores JSON-formatted text data | `'{"name":"Alice", "age":21}'` |
| **XML** | Stores XML-formatted data | `'<student><name>John</name></student>'` |

---

## Choosing the Right Data Type

| Purpose | Recommended Data Type |
|----------|-----------------------|
| Numeric IDs | `INT` / `BIGINT` |
| Prices, Money | `DECIMAL(p, s)` |
| Names, Text | `VARCHAR(n)` |
| Dates | `DATE`, `DATETIME` |
| Booleans | `BIT` / `BOOLEAN` |
| Images, Files | `BLOB` |
| Structured Data | `JSON` / `XML` |

---

## SQL Example: Using Various Data Types

```sql
CREATE TABLE Employees (
    EmpID INT PRIMARY KEY,
    Name VARCHAR(50),
    Salary DECIMAL(10,2),
    IsActive BIT,
    JoinDate DATE,
    ProfileImage BLOB,
    Preferences JSON
);
```

---

## Summary

* **Numeric** → For integers and decimals.
* **Character** → For text and strings.
* **Date/Time** → For temporal values.
* **Binary** → For multimedia or binary data.
* **Miscellaneous** → For JSON, ENUM, SET, etc.

Selecting the **correct data type** ensures efficiency, precision, and maintainability in your SQL database design.
