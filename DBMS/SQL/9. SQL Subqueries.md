# SQL Subqueries

A **Subquery** (also called **Inner Query** or **Nested Query**) is a **query within another query**.

The subquery provides data to the main query, allowing you to solve complex problems by breaking them into steps.

> **Think of a subquery as asking a question to answer another question.**

---

## Definition

- A **subquery** is a SELECT statement within another SELECT, INSERT, UPDATE, or DELETE statement.

- The subquery is **executed first**, and its result is used by the outer (main) query.

- Subqueries must be **enclosed in parentheses**.

---

## Why Use Subqueries?

### Without Subquery
```
Problem: Find all employees earning more than the average salary

Step 1: Calculate average salary manually
Step 2: Write WHERE clause with that value
Step 3: Update if data changes

Tedious and error-prone!
```

### With Subquery
```sql
SELECT * FROM Employees 
WHERE Salary > (SELECT AVG(Salary) FROM Employees);

-- Subquery automatically calculates average
-- Always uses current data
-- Single query does everything
```

---

## Types of Subqueries

### 1. Scalar Subquery (Returns Single Value)

```sql
SELECT * FROM Employees 
WHERE Salary > (SELECT AVG(Salary) FROM Employees);
```

**Result:** Subquery returns one number (e.g., 60000)

---

### 2. Row Subquery (Returns Single Row, Multiple Columns)

```sql
SELECT * FROM Employees 
WHERE (Department, Salary) = (
  SELECT Department, Salary 
  FROM Employees 
  WHERE Name = 'Alice'
);
```

**Result:** Subquery returns one row with multiple columns

---

### 3. Table Subquery (Returns Multiple Rows/Columns)

```sql
SELECT * FROM Employees 
WHERE Salary IN (
  SELECT Salary FROM Employees WHERE Department = 'IT'
);
```

**Result:** Subquery returns multiple rows

---

### 4. Correlated Subquery (References Outer Query)

```sql
SELECT * FROM Employees e1
WHERE Salary > (
  SELECT AVG(Salary) 
  FROM Employees e2 
  WHERE e2.Department = e1.Department
);
```

**Key:** Subquery uses columns from outer query (e1.Department)

---

## Subquery Positions

### In SELECT Clause
```sql
SELECT Name, 
  (SELECT COUNT(*) FROM Departments) as TotalDepts
FROM Employees;
```

### In WHERE Clause
```sql
SELECT * FROM Employees 
WHERE Department IN (SELECT DeptID FROM Departments);
```

### In FROM Clause
```sql
SELECT * FROM (
  SELECT Name, Salary FROM Employees WHERE Salary > 50000
) AS HighEarners;
```

### In HAVING Clause
```sql
SELECT Department, COUNT(*) 
FROM Employees 
GROUP BY Department
HAVING COUNT(*) > (SELECT AVG(DeptSize) FROM ...);
```

---

## Operators Used with Subqueries

### IN / NOT IN
```sql
-- Employees in 'IT' or 'HR' departments
SELECT * FROM Employees 
WHERE Department IN (SELECT DeptID FROM Departments WHERE Name IN ('IT', 'HR'));
```

### EXISTS / NOT EXISTS
```sql
-- Departments that have employees
SELECT * FROM Departments d
WHERE EXISTS (SELECT 1 FROM Employees WHERE DeptID = d.DeptID);
```

### Comparison (=, <, >, <=, >=, !=)
```sql
-- Employees earning more than average
SELECT * FROM Employees 
WHERE Salary > (SELECT AVG(Salary) FROM Employees);
```

### ALL / ANY / SOME
```sql
-- Employees earning more than all IT employees
SELECT * FROM Employees 
WHERE Salary > ALL (SELECT Salary FROM Employees WHERE Department = 'IT');
```

## Examples

### Example 1: Simple Subquery
```sql
-- Find employees earning more than average

SELECT Name, Salary 
FROM Employees 
WHERE Salary > (SELECT AVG(Salary) FROM Employees);
```

**Result:**
| Name  | Salary |
|-------|--------|
| Bob   | 70000  |
| Carol | 75000  |

---

### Example 2: IN Subquery
```sql
-- Find employees in departments with highest salary

SELECT Name, Department 
FROM Employees 
WHERE Department IN (
  SELECT Department 
  FROM Employees 
  WHERE Salary = (SELECT MAX(Salary) FROM Employees)
);
```

---

### Example 3: Correlated Subquery
```sql
-- Find employees earning more than their department average

SELECT Name, Department, Salary
FROM Employees e1
WHERE Salary > (
  SELECT AVG(Salary) 
  FROM Employees e2 
  WHERE e2.Department = e1.Department
);
```

---

### Example 4: EXISTS Subquery
```sql
-- Find departments that have at least one employee

SELECT DISTINCT d.DeptName
FROM Departments d
WHERE EXISTS (
  SELECT 1 FROM Employees e WHERE e.DeptID = d.DeptID
);
```

## Subquery vs JOIN

### Same Result, Different Approaches

**Using Subquery:**
```sql
SELECT Name FROM Employees 
WHERE DeptID IN (SELECT DeptID FROM Departments WHERE Location = 'Delhi');
```

**Using JOIN:**
```sql
SELECT e.Name 
FROM Employees e 
JOIN Departments d ON e.DeptID = d.DeptID 
WHERE d.Location = 'Delhi';
```

### Which is Better?

| Approach | Readability | Performance | Use Case |
|----------|-------------|-------------|----------|
| **Subquery** | Clear logic | Slower | Complex conditions |
| **JOIN** | More SQL code | Faster | Simple relationships |

**Modern DBMSs optimize both equally!**

---

## Advantages of Subqueries

✓ **Logical breakdown** — Easier to understand complex queries  
✓ **Reusability** — Subquery can be used multiple times  
✓ **Dynamic filtering** — Uses calculated values (AVG, MAX, etc.)  
✓ **Cleaner code** — Sometimes simpler than JOIN  

---

## Disadvantages of Subqueries

✗ **Performance** — Can be slower than JOIN (depending on DB optimizer)  
✗ **Readability** — Nested subqueries hard to follow  
✗ **Correlated subqueries** — Run once per outer row (slow for large datasets)  
✗ **Limited by DBMS** — Some DBMS have subquery limitations  

---

## Performance Tips

### Avoid Correlated Subqueries in Large Tables
```sql
-- SLOW: Runs subquery for each employee
SELECT * FROM Employees e1
WHERE Salary > (
  SELECT AVG(Salary) FROM Employees e2 WHERE e2.Department = e1.Department
);

-- FASTER: Use window function or JOIN
SELECT e.* 
FROM Employees e
JOIN (SELECT Department, AVG(Salary) as AvgSal FROM Employees GROUP BY Department) avg
ON e.Department = avg.Department
WHERE e.Salary > avg.AvgSal;
```

### Use EXISTS Instead of COUNT
```sql
-- SLOW
SELECT * FROM Departments 
WHERE (SELECT COUNT(*) FROM Employees WHERE DeptID = Departments.DeptID) > 0;

-- FASTER
SELECT * FROM Departments d
WHERE EXISTS (SELECT 1 FROM Employees WHERE DeptID = d.DeptID);
```

## Real-World Example: E-commerce

**Find all products in categories where average price > $500**

```sql
SELECT ProductName, Category, Price
FROM Products
WHERE Category IN (
  SELECT Category 
  FROM Products 
  GROUP BY Category 
  HAVING AVG(Price) > 500
);
```

|------|---------|----------|
| Scalar | Single value | Comparisons |

| Table | Multiple rows/columns | IN, EXISTS operators |

---

## Key Takeaways

- **Subqueries** break complex queries into logical steps.

- **IN/EXISTS** most common operators for subqueries.

- **Correlated subqueries** powerful but can be slow.

- **JOIN usually faster** than subqueries in modern DBMS.

- **EXISTS faster** than COUNT for existence checks.

- Interview focus: **subquery types, correlated vs non-correlated, performance comparison, real-world scenarios**.
