# First Normal Form (1NF)

**First Normal Form (1NF)** is the **foundational stage of normalization**.  

A relation is in 1NF when **all its attributes contain only atomic (indivisible) values** and **there are no repeating groups or arrays**.

It focuses on ensuring that data is stored in a **tabular, structured, and unambiguous** manner.

---

## 1. Definition

A relation is said to be in **First Normal Form** if it satisfies the following conditions:

1. Each table cell contains **a single value** (atomic value).  

2. Each record is **unique** (no duplicate rows).  

3. Attribute domains are **same type and valid values**.  

4. No **repeating groups, multivalued attributes, or composite attributes**.  

> In short: **No arrays, lists, or nested tables inside a cell.**

---

## 2. What 1NF Eliminates

1NF removes:
- repeating columns  
- multivalued attributes  
- nested relations  
- non-tabular structure  

This converts an unstructured table into a **flat relational table**.

---

## 3. Example – Table Not in 1NF

| StudentID | Name | Courses        |
|-----------|------|----------------|
| 1         | Ravi | DBMS, OS       |
| 2         | Meera| DBMS, Networks |

### Problems
- **Courses** field stores multiple values → **multivalued attribute**
- Violates 1NF rule

---

## 4. Converting to 1NF (Decomposition)

Break multi-valued attributes into **separate rows**:

| StudentID | Name | Course   |
|-----------|------|----------|
| 1         | Ravi | DBMS     |
| 1         | Ravi | OS       |
| 2         | Meera| DBMS     |
| 2         | Meera| Networks |

Now each field is **atomic** → relation is in **1NF**.

---

## 5. Another Example – Repeating Groups

Table not in 1NF:

| OrderID | Product1 | Product2 | Product3 |
|---------|----------|----------|----------|
| 101     | Pen      | Pencil   | Eraser   |

### Issues
- Repeating columns Product1, Product2, Product3
- Difficult to handle variable number of products

### Convert to 1NF

| OrderID | Product |
|--------|--------|
| 101    | Pen    |
| 101    | Pencil |
| 101    | Eraser |

Repeating groups removed.

---

## 6. Atomic vs Non-Atomic ⭐️

| Value Type | Example | Status in 1NF |
|-----------|--------|----------------|
| Atomic value | "Delhi" | Valid |
| Non-atomic | "Delhi, Mumbai" | Not allowed |
| Composite | "FirstName LastName" stored separately? | Prefer split |
| Set / list | {Maths, English} | Not allowed |

---

## 7. Formal Definition Using Relational Model

For a relation R to be in 1NF:

- Domain of each attribute must contain **atomic values only**
- Each tuple must be **unique**
- Attributes must contain **single value from its domain**

Mathematically:
> Relation is 1NF if domain of each attribute is a **flat set** of atomic values.

---

## 8. Key Characteristics of 1NF

- Only scalar values allowed
- Order of rows and columns does not matter
- Table must have **primary key**
- No **null groups or repeating groups**

---

## 9. 1NF Does NOT Solve Everything

Even if table is in 1NF, it may still suffer from:

- **Partial dependency** → violates 2NF  
- **Transitive dependency** → violates 3NF  
- **Insertion/update/deletion anomalies**  

Thus 1NF is **only the first step**.

---

## 10. Advantages of 1NF

| Advantage | Explanation |
|-----------|-------------|
| Simplifies table design | Clear and atomic values |
| Easier querying | Simple selects and joins |
| Eliminates repeating groups | Avoids irregular columns |
| Basis for higher NFs | Mandatory step |

---

## 11. Disadvantages / Limitations

| Limitation | Explanation |
|-----------|-------------|
| May increase rows | Due to splitting multi-valued attributes |
| Does not remove redundancy | 1NF alone isn’t enough |
| Anomalies still exist | Needs 2NF, 3NF, BCNF |

---

## Key Takeaways

- 1NF enforces **atomicity and tabular structure**.  

- No multiple values, lists, or repeating columns are allowed.  

- Forms the **foundation of normalization**.  

- Higher normal forms **depend on 1NF being satisfied first**.

- 1NF alone does not guarantee a well-designed database; further normalization is needed.
