# Introdcution to Relational Model and Relational Algebra

## Relational Model

- A **Relational Model** represents data as a collection of tables (relations) consisting of rows (tuples) and columns (attributes).

- It was proposed by **E. F. Codd (1970)** and organizes data into **relations (tables)**, while **Relational Algebra** provides the mathematical framework to query and manipulate this data.

- The relational model emphasizes data integrity, consistency, and the use of **SQL** for data operations.

---


## Components of Relational Model
| Component        | Description                                                                 | Example (STUDENT Table)           |
|------------------|-----------------------------------------------------------------------------|-----------------------------------|
| **Relation**     | A table with rows and columns.                                              | STUDENT                           |
| **Tuple**        | A row in a relation.                                                       | (101, Alice, CSE, 20)             |
| **Attribute**    | A column in a relation.                                                    | StudentID, Name, Department, Age  |
| **Domain**       | Set of possible values for an attribute.                                   | Age domain = {16–30}              |
| **Degree**       | Number of attributes in a relation.                                        | 4 (in STUDENT table)              |
| **Cardinality**  | Number of tuples (rows) in a relation.                                     | 5 (if 5 students exist)           |
| **Schema**       | Logical definition (relation name + attribute names).                      | STUDENT(StudentID, Name, Dept, Age) |
| **Instance**     | Snapshot of data in a relation at a given point in time.                   | Current rows in STUDENT table     |

---


## Properties of a Relation

- **Uniqueness:** No duplicate tuples.

- **Atomic Values:** Each cell contains a single value.

- **Order Irrelevance:** Tuple order and attribute order don’t matter.

- **Integrity Constraints:**  
  
  - **Primary Key Constraint**: Uniquely identifies each tuple.  
  
  - **Foreign Key Constraint**: Maintains referential integrity.  
  
  - **Domain Constraint**: Values must be from predefined domains.  
  
  - **Entity Integrity**: Primary key cannot be NULL.

---

## Advantages vs Disadvantages of Relational Model

| Advantages                                      | Disadvantages                                  |
|-------------------------------------------------|------------------------------------------------|
| Simple and intuitive data representation        | Performance can degrade with complex queries  | 
| Flexibility in querying with SQL                 | Not ideal for hierarchical or graph data      |
| Data integrity through constraints               | Can require complex joins for related data    |
| Data independence (logical vs physical)         | May not handle unstructured data well         |
| Widely adopted and supported                     | Scalability issues with very large datasets   |
| Strong theoretical foundation (set theory)       | Overhead of normalization in some cases       |

---

## Relational Algebra

- **Relational Algebra** is a **procedural query language** that uses mathematical operations to manipulate relations.

- Produces a **new relation** as a result of operations.

- Basis of **SQL**.

---

## Basic Operations in Relational Algebra

| Operation        | Symbol      | Description                                                       | Example                                                |
|------------------|-------------|-------------------------------------------------------------------|--------------------------------------------------------|
| **Selection**    | σ          | Filters rows (tuples) based on a condition.                       | σ<sub>Dept='CSE'</sub>(STUDENT) → Students in CSE      |
| **Projection**   | π          | Selects specific columns (attributes).                            | π<sub>Name, Age</sub>(STUDENT) → List of Names & Ages  |
| **Union**        | ∪          | Combines tuples from two relations (duplicates removed).           | STUDENT<sub>CSE</sub> ∪ STUDENT<sub>ECE</sub>          |
| **Set Difference** | −        | Tuples in one relation but not in another.                        | STUDENT<sub>CSE</sub> − STUDENT<sub>ECE</sub>          |
| **Cartesian Product** | ×    | Combines tuples from two relations (all combinations).             | STUDENT × COURSE                                       |
| **Rename**       | ρ          | Renames a relation or its attributes.                             | ρ<sub>S</sub>(STUDENT)                                 |

---


## Advanced Operations
| Operation        | Symbol | Description                                                                 | Example                                                                 |
|------------------|--------|-----------------------------------------------------------------------------|-------------------------------------------------------------------------|
| **Intersection** | ∩      | Tuples common to both relations.                                            | STUDENT<sub>CSE</sub> ∩ STUDENT<sub>ECE</sub>                          |
| **Join**         | ⨝      | Combines tuples from two relations based on a condition.                    | STUDENT ⨝<sub>StudentID=SID</sub> ENROLLMENT                            |
| **Equi-Join**    |        | Join with equality condition.                                               | STUDENT ⨝<sub>STUDENT.DeptID = DEPT.DeptID</sub> DEPARTMENT             |
| **Natural Join** | ⋈      | Automatically joins on common attributes.                                   | STUDENT ⋈ DEPARTMENT                                                    |
| **Division**     | ÷      | Finds tuples in one relation that match **all** tuples in another relation. | COURSE_REQ ÷ COMPULSORY_COURSE                                          |

---

## Example Queries in Relational Algebra

#### Example 1: Find all students in CSE

    σ Dept='CSE'(STUDENT)

#### Example 2: Get student names and ages
    π Name, Age(STUDENT)

#### Example 3: Find students who are enrolled in both CSE and ECE
    STUDENT_CSE ∩ STUDENT_ECE

#### Example 4: Get list of students with their department names
    STUDENT ⨝<STUDENT.DeptID=DEPARTMENT.DeptID> DEPARTMENT

#### Example 5: Find students who have enrolled in all compulsory courses
    COURSE_REQ ÷ COMPULSORY_COURSE

#### Example 6: List names of students not in ECE
    π Name(STUDENT) − π Name(σ Dept='ECE'(STUDENT))

## Relational Model vs Relational Algebra

| Aspect                  | Relational Model                                      | Relational Algebra                                  |
|-------------------------|-------------------------------------------------------|----------------------------------------------------|
| **Definition**          | Framework for structuring and organizing data         | Mathematical query language to manipulate relations |
| **Focus**               | Representation of data (tables, rows, columns)        | Operations for retrieving/manipulating data         |
| **Nature**              | Conceptual model                                      | Procedural approach                                 |
| **Example**             | STUDENT(StudentID, Name, Age, Dept)                   | σ Dept='CSE'(STUDENT)                              |
