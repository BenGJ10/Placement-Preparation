# Relational Database Management System (RDBMS)

![RDBMS](images/dbms_rdbms.png)

## Definition

- A **Relational Database Management System (RDBMS)** is a software system that stores data in **tables (relations)** made up of rows (**tuples**) and columns (**attributes**).  

- It follows **E. F. Codd’s relational model** and provides a structured way to store, manage, and query data using **SQL**.


- Relational in RDBMS refers to the way data is organized in tables, where each table represents an entity and the relationships between these entities are established through **foreign keys**.


---



## Key Characteristics

- **Tabular Structure:** Data organized into relations (tables) with rows and columns.

- **Data Integrity:** Enforces primary key, foreign key, unique constraints, and referential integrity.

- **ACID Properties:** Ensures **Atomicity**, **Consistency**, **Isolation**, and **Durability** for reliable transactions.

- **Data Independence:** Logical data design is separate from physical storage details.

- **Standard Query Language (SQL):** Used for data definition (DDL), manipulation (DML), and control (DCL).

- **Normalization:** Process of organizing data to reduce redundancy and improve data integrity.

---

## How Data Is Stored in Memory

RDBMS uses a **layered architecture** for efficient and reliable storage. Data is ultimately stored on **disk**, but with caching and memory management to speed up access.

### 1️⃣ Logical View

- **Database → Tables → Rows & Columns**

- Logical representation is independent of how data is physically stored.

### 2️⃣ Physical Storage Components
| Component                         | Description                                                                          |
|-----------------------------------|--------------------------------------------------------------------------------------|
| **Data Files**                    | Actual tables and indexes stored on disk (e.g., `.ibd` files in MySQL InnoDB).        |
| **Tablespaces**                   | Logical containers grouping data files for easier management.                         |
| **Pages / Blocks**                | Fixed-size units of I/O (commonly 4 KB, 8 KB, or 16 KB). Smallest unit read/written.  |
| **Extents**                       | Collections of contiguous pages for allocating large tables efficiently.              |
| **Segments**                      | Entire objects like a table or index that occupy one or more extents.                 |

### 3️⃣ In-Memory Structures

- **Buffer Pool / Buffer Cache:**  
  - Holds frequently accessed data pages to reduce disk reads.  
  - Uses algorithms like **LRU (Least Recently Used)** for caching.

- **Redo / Transaction Logs:**  
  - Stored in memory first, then flushed to disk for durability.

- **Lock Tables & Metadata Cache:**  
  - Track active transactions, locks, and schema details.

### 4️⃣ Write Path

1. **SQL Query Execution** – Data is fetched or modified.

2. **Buffer Pool Update** – Changes happen in memory first.

3. **Redo/Undo Logging** – Transaction logs record changes for crash recovery.

4. **Checkpointing** – Dirty pages (modified pages) are periodically flushed to disk.

## RDBMS vs DBMS

| Feature                  | DBMS                                         | RDBMS                                                          |
|--------------------------|----------------------------------------------|----------------------------------------------------------------|
| **Data Model**           | Hierarchical, network, or file-based         | Relational (tables)                                            |
| **Data Storage**         | Files or navigational systems                | Tables with rows and columns                                   |
| **Query Language**       | No standard (proprietary)                    | SQL (standardized)                                             |
| **Transactions**         | May not support ACID                         | Fully supports ACID                                            |
| **Data Relationships**   | Hard to manage                               | Managed using primary & foreign keys                           |
| **Examples**             | XML DB, IMS                                   | MySQL, PostgreSQL, Oracle, SQL Server                          |

---

## Advantages of RDBMS

- **Data Integrity:** Primary/foreign keys maintain consistency.

- **Security:** Role-based access control and privileges.

- **Scalability:** Handles large datasets with indexing and query optimization.

- **Concurrency:** Multiple users can read/write simultaneously using locks & isolation levels.

- **Recovery:** Crash recovery with redo/undo logs.
