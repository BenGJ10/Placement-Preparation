# Zombie Process vs Orphan Process

In process management, **Zombie** and **Orphan** processes are two special conditions that occur due to parent–child process relationships. They appear frequently in OS theory, Linux process management, and interview questions.
---

## 1. Zombie Process

### Definition
A **Zombie Process** (also called a *defunct process*) is a process that has **completed execution**, but **still has an entry in the process table** because its parent has **not yet read its exit status**.

It is “dead” but not removed by the OS.

---

### How a Zombie is Created?

1. Child process finishes execution (`exit()`).
2. Kernel keeps its **PID and exit status** in process table.
3. Parent must call `wait()` or `waitpid()` to collect the exit status.
4. **If parent does NOT call wait() → Zombie is formed.**

---

### Characteristics

- Cannot be killed using `kill` (already dead).
- Occupies minimal resources (just a PCB entry).
- Parent is still alive.
- Removed automatically when the parent calls `wait()`.

---

### Problems Caused

- If many zombies accumulate → process table fills → no new processes can be created (PID exhaustion).
- Indicates a bug (parent not handling child termination properly).

---

### Example in Linux

Run:

```bash
ps aux | grep Z
```

You will see `<defunct>` in the process state.

---

## 2. Orphan Process

### Definition

An **Orphan Process** is a **child process whose parent has terminated** before the child finishes executing.

The orphan must be adopted by another process.

---

### What Happens to an Orphan?

* When parent dies, the OS assigns the orphan’s parent to:

  * **`init` process (PID 1)** in Linux/Unix, or
  * **systemd** (modern systems)

* The new parent later calls `wait()` to clean up the child when it finishes.

Thus, **orphans do NOT become zombies** (because init always reaps them).

---

### Characteristics

* Parent is dead, child is still running.
* Adopted by `init/systemd`.
* Will not cause resource leakage.
* Common in background tasks.

---

## Differences Between Zombie and Orphan Processes

| Feature                     | Zombie Process                     | Orphan Process                    |
| --------------------------- | ---------------------------------- | --------------------------------- |
| **Process state**           | Completed (dead) but entry remains | Running, still executing          |
| **Parent alive?**           | Yes, parent is alive               | No, parent has terminated         |
| **Resource usage**          | Only PCB entry remains             | Uses full resources (CPU, memory) |
| **Clean-up responsibility** | Parent must call `wait()`          | `init/systemd` cleans it up       |
| **Danger level**            | Dangerous if many accumulate       | Not dangerous                     |
| **Killable?**               | No (already dead)                  | Yes (normal process)              |
| **Cause**                   | Parent not reading exit status     | Parent terminated early           |

---

## Visual Understanding

### Zombie Process

```
Parent Process (Alive)
      |
Child finishes → becomes Zombie
      |
Parent NEVER calls wait()
```

### Orphan Process

```
Parent Terminates Early
      |
Child still running → becomes Orphan
      |
Adopted by init/systemd
```

---

## Summary

* **Zombie:** Dead process, parent alive, exit info not collected → PCB entry remains.

* **Orphan:** Running child whose parent died → adopted by init/systemd.

* Zombies must be avoided; orphans are harmless.

* Proper use of `wait()` prevents zombies.
