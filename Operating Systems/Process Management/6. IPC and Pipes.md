# Inter-Process Communication (IPC) and Pipes

Inter-Process Communication (IPC) is a fundamental concept in operating systems that enables processes to **exchange data**, **synchronize actions**, and **coordinate execution**.  

IPC is essential in multitasking systems where processes need to work together.


---

## 1. Inter-Process Communication (IPC)

### Definition
Inter-Process Communication (IPC) is a mechanism that allows processes to **communicate** and **share data** with each other.

Processes may be:
- On the **same machine** (Shared Memory, Pipes, Message Queues)
- On **different machines** (Sockets, RPC)

IPC offers controlled and secure communication between processes.

---

### Why IPC is Needed?

1. **Data Sharing**  
   Processes exchange data (e.g., producer–consumer model).

2. **Modular Programming**  
   Split programs into smaller cooperating processes.

3. **Synchronization**  
   Prevents race conditions during resource access.

4. **Resource Sharing**  
   Enables shared memory, shared files, etc.

5. **Communication in Distributed Systems**  
   Network-based IPC uses sockets, RPC, etc.

---

### Common IPC Mechanisms

| IPC Mechanism | Description | Mode |
|---------------|-------------|------|
| **Pipes** | Unidirectional communication using a buffer | Half-duplex |
| **Named Pipes (FIFOs)** | Pipe with a name, allows unrelated processes | Half-duplex |
| **Message Queues** | Messages stored in queue with priorities | Asynchronous |
| **Shared Memory** | Fastest IPC; memory segment shared between processes | Synchronous user-level sync needed |
| **Semaphores** | Signaling mechanism for synchronization | N/A |
| **Sockets** | Bidirectional communication over network | Full-duplex |
| **Signals** | Notifications of events | Asynchronous |
| **RPC** | Remote Procedure Calls | Client-server |

---

## 2. Pipes (Anonymous Pipes)

### Definition
A **Pipe** is an IPC mechanism that allows **unidirectional data flow** between related processes (typically parent-child).  
Data written at one end of the pipe can be read from the other end.

### A pipe behaves like:
- A **buffer** in kernel memory  
- A conduit for sending data from one process to another  

---

### Characteristics of Pipes

**1. Unidirectional Communication**
Data flows in only one direction:
```

Writer → Pipe → Reader

```

**2. Half-Duplex**
To achieve two-way communication, two pipes are required.

**3. Requires Related Processes**
Usually used between:
- Parent and child processes (via fork)
- Shell pipelines (`ls | grep txt`)

**4. Temporary / Anonymous**
Exists only until processes are running.

**5. Kernel-Managed Buffer**
OS allocates a small buffer (e.g., 4 KB, 8 KB).

---

### How Pipes Work Internally

1. A pipe is created using:
```c
int pipefd[2];
pipe(pipefd);
````

2. This creates:

* `pipefd[0]` → read end
* `pipefd[1]` → write end

3. Writer process writes data:

```c
write(pipefd[1], msg, size);
```

4. Reader process reads data:

```c
read(pipefd[0], buffer, size);
```

5. If no data is available → reader **blocks**
6. If buffer is full → writer **blocks**

---

### Example: Shell Pipeline

Command:

```
ls | grep ".txt"
```

Explanation:

* `ls` writes output into pipe
* `grep` reads from pipe
* Shell forks two child processes and sets up pipe between them

---

### Advantages of Pipes

* Simple and fast
* Supported by all major OS
* Great for parent-child communication
* Useful for pipelines and shell scripts

---

### Limitations of Pipes

| Limitation                 | Explanation                                                |
| -------------------------- | ---------------------------------------------------------- |
| **Half-duplex**            | Only one-way communication; need two pipes for full-duplex |
| **Related processes only** | Anonymous pipes cannot be used between unrelated processes |
| **Temporary**              | Destroyed once communication ends                          |
| **Limited buffer**         | Writer blocks when buffer is full                          |
| **No message boundaries**  | Works like a byte stream, not messages                     |

## IPC Mechanism Comparison

| Mechanism         | Communication | Direction | Processes       | Speed   | Use Case                 |
| ----------------- | ------------- | --------- | --------------- | ------- | ------------------------ |
| **Pipe**          | Stream        | One-way   | Related         | Medium  | Shell pipelines          |
| **FIFO**          | Stream        | One-way   | Unrelated       | Medium  | Named communication      |
| **Message Queue** | Messages      | Two-way   | Any             | Medium  | Ordered communication    |
| **Shared Memory** | Memory region | Two-way   | Any             | Fastest | High-speed data transfer |
| **Semaphores**    | Sync only     | N/A       | Any             | Fast    | Mutual exclusion         |
| **Sockets**       | Stream/packet | Two-way   | Local or remote | Medium  | Networking               |

---

## Summary

* **IPC** allows processes to communicate and sync actions.

* **Pipes** provide simple, unidirectional communication between related processes.

* **Named Pipes** extend this to unrelated processes.

* Pipes are widely used in shell pipelines and UNIX process communication.

* Pipes operate as a byte-stream buffer managed by the kernel.
