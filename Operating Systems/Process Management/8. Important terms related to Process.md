# Important Terms in Process Management

Understanding core OS terms is essential for mastering process management, scheduling, execution, memory allocation, and OS internals.  

---

## 1. Program Counter (PC)

**Definition:**  
The **Program Counter** (also called Instruction Pointer) is a CPU register that stores the **address of the next instruction** to be executed.

**Role in Process Management:**
- During context switching, the PC value is saved in the **PCB**.
- Restored when the process resumes.

**Key Point:**  
PC ensures that a process continues from the exact place it was paused.

---

## 2. CPU Registers

**Definition:**  
CPU registers are **high-speed storage locations** used to hold intermediate values and the current execution context of a process.

**Examples:**
- Accumulator  
- Base register  
- Index register  
- Stack pointer  
- Status flags  
- Instruction register  

**Why Important?**
- Registers are saved/restored during context switching.
- Enable fast computation.

---

## 3. Stack

**Definition:**  
A **Stack** is a LIFO (Last-In-First-Out) memory region used for:
- Function calls  
- Local variables  
- Return addresses  
- Function parameters  

**Characteristics:**
- Grows upward or downward depending on architecture.
- Each thread has its **own stack**.

**Role in Process Management:**
- Stores function call frames (activation records).
- Stores context for nested function calls.

---

## 4. Heap

**Definition:**  
The **Heap** is a memory region used for **dynamic memory allocation** during runtime.

**Allocated Using:**
- `malloc()` / `free()` in C  
- `new` / `delete` in C++  
- Garbage collector in Java/Python  

**Key Points:**
- Shared by all threads of a process.
- Grows dynamically based on program requirements.
- Managed by the OS and runtime memory manager.

---

## 5. Text (Code) Segment

**Definition:**  
Memory area where **executable instructions** of the program are stored.

**Characteristics:**
- Read-only (to prevent modification of code).
- Shared among processes executing the same program.

---

## 6. Data Segment

Stores **global and static variables**.

Types:
- **Initialized Data Segment (.data)** : globals with initial values  
- **Uninitialized Data Segment (.bss)** : globals initialized to zero  

---

## 7. Scheduler

**Definition:**  
The **Scheduler** determines which process gets the CPU next.

**Types:**
- **Long-Term Scheduler:** selects jobs to load into memory  
- **Short-Term Scheduler:** selects ready process to execute  
- **Mid-Term Scheduler:** swaps processes in/out of memory  

**Role:**
- Manages CPU sharing  
- Improves throughput and response time  
- Maintains fairness  

---

## 8. Dispatch / Dispatcher

**Definition:**  
The dispatcher is the OS component that:
- Gives control of the CPU to the selected process  
- Performs **context switching**  
- Loads saved register values from PCB  
- Starts execution of the new process  

**Fast dispatcher = low context switch overhead.**

---

## 9. Process Control Block (PCB)

**Definition:**  
A PCB is a kernel data structure containing **all information about a process**.

**Includes:**
- PID  
- Process state  
- Program counter  
- CPU registers  
- Scheduling info  
- Memory info  
- I/O status  

---

## 10. Process Address Space

**Definition:**  
The logical memory layout assigned to a process.

Typical structure:
```

+---------------------+
|  Command-line args  |
|  Environment vars   |
+---------------------+
|  Stack              |
+---------------------+
|  Heap               |
+---------------------+
|  BSS (uninitialized)|
+---------------------+
|  Data (initialized) |
+---------------------+
|  Text (code)        |
+---------------------+

```

---

## 11. Deadlock

Occurs when a group of processes cannot proceed because each is waiting for the other to release resources.

Requires four conditions:
- Mutual exclusion  
- Hold and wait  
- No preemption  
- Circular wait
