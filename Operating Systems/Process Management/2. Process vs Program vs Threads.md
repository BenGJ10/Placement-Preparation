# Process vs Program vs Threads

Understanding the relationship and differences between a **Program**, **Process**, and **Thread** is fundamental in Operating Systems, CPU scheduling, concurrency, and system design.  

---

## 1. Program

**Definition**

A **Program** is a **passive** set of instructions stored on disk.  
It is not performing any actions by itself.

Examples:
- A C file (`a.out`)
- A Java `.class` file
- A Python script
- MS Word executable (`winword.exe`)

**Characteristics**

- Passive entity (just code)
- Stored in secondary memory
- Has no runtime context (no RAM, no CPU state)
- Becomes a **process** only when executed

---

## 2. Process

**Definition**

A **Process** is a **program in execution**.  
It is an **active** entity that has been loaded into memory and assigned system resources.

A process contains:
- Program code  
- Data section  
- Heap  
- Stack  
- CPU registers, PC  
- Open files, resources  
- Process Control Block (PCB)

**Characteristics**
- Active entity  
- Has its own address space  
- Has unique PID  
- Managed by OS scheduler  
- Heavyweight—context switching is costly  

**Example:**  
Running `chrome.exe` creates multiple processes.

---

## 3. Thread

**Definition**

A **Thread** is the **smallest unit of execution** within a process.  
It represents a single sequence of instructions.

**Characteristics**
- Lightweight  
- Shares process resources (heap, global data)  
- Has its own:
  - Program counter  
  - Registers  
  - Stack  

## Why Threads?

- Enable concurrency  

- Faster context switching  

- Better CPU utilization  

- Useful for parallel tasks (e.g., browser tabs, server handling multiple requests)

---

## Relationship Between Program, Process, and Threads

```

Program → Process → Threads

```

- A **program** becomes a **process** when executed.  


- A **process** can contain **one or multiple threads**.  
- Threads share memory but run independently.

---

## Program vs Process vs Thread

| Aspect                | Program                            | Process                                      | Thread                                             |
|-----------------------|-------------------------------------|-----------------------------------------------|----------------------------------------------------|
| **Definition**        | Passive set of instructions         | Program in execution                          | Smallest execution unit within a process           |
| **State**             | Stored on disk                      | Active, running                               | Active, running                                    |
| **Memory**            | No memory allocated (until run)     | Has its own memory space                      | Shares memory of the process                       |
| **Address Space**     | None                                | Separate for each process                     | Shared within process                              |
| **Creation Overhead** | None                                | High (heavyweight)                            | Low (lightweight)                                  |
| **Context Switching** | Not applicable                      | Costly                                        | Faster                                             |
| **Execution**         | Cannot execute on its own           | Executes independently                        | Executes independently, but inside a process       |
| **Resources**         | Not allocated hardware resources    | Full resources allocated                      | Shares process resources                           |
| **Failure Impact**    | None                                | Crash affects only the process                | Crash may affect entire process                    |
| **Example**           | `.exe`, `.py`, `.class`             | Running Word, Chrome process                  | Browser tabs, multiple worker threads              |
