# Peterson’s Solution

**Peterson’s Solution** is a **classical software-based solution** to the **critical section problem** for **two processes**.  

It guarantees **mutual exclusion, progress, and bounded waiting** using only **shared variables**—no hardware support required.

It is mainly of **theoretical importance** and helps understand how synchronization works at a low level.

---

## 1. What is Peterson’s Solution?

### Definition
Peterson’s Solution is an algorithm that allows **two processes** to share a single-use resource **without conflict**, ensuring that:

- Only one process enters the critical section at a time
- No process waits indefinitely
- No deadlock occurs

---

## 2. Assumptions

Peterson’s Solution assumes:

1. Only **two processes**: `P0` and `P1`
2. Processes execute in **shared memory**
3. **Atomic read/write** operations
4. No reordering by compiler or CPU (important in practice)

---

## 3. Shared Variables Used

```cpp
bool flag[2];   // indicates intent to enter critical section
int turn;       // indicates whose turn it is
```

### Meaning

* `flag[i] = true` → Process `Pi` wants to enter critical section
* `turn = j` → Give priority to process `Pj`

---

## 4. Core Idea

Each process:

1. Declares its intention to enter the critical section
2. Gives **turn** to the other process
3. Waits until:

   * the other process is not interested, or
   * it is its own turn

This avoids conflict **without locks**.

---

## 5. Peterson’s Solution – C++ Implementation

### Process P0

```cpp
#include <iostream>
#include <thread>
using namespace std;

bool flag[2] = {false, false};
int turn;

void process0() {
    while (true) {
        // Entry section
        flag[0] = true;
        turn = 1;
        while (flag[1] && turn == 1);

        // Critical section
        cout << "Process 0 is in the critical section\n";

        // Exit section
        flag[0] = false;

        // Remainder section
    }
}
```

---

### Process P1

```cpp
void process1() {
    while (true) {
        // Entry section
        flag[1] = true;
        turn = 0;
        while (flag[0] && turn == 0);

        // Critical section
        cout << "Process 1 is in the critical section\n";

        // Exit section
        flag[1] = false;

        // Remainder section
    }
}
```

---

### Driver Code

```cpp
int main() {
    thread t1(process0);
    thread t2(process1);

    t1.join();
    t2.join();
    return 0;
}
```

---

## 6. How Peterson’s Solution Works (Step-by-Step)

Suppose both processes want to enter CS:

1. `P0` sets `flag[0] = true`, `turn = 1`

2. `P1` sets `flag[1] = true`, `turn = 0`

3. Now:

   * `P0` waits (turn = 0)
   * `P1` enters critical section

4. After `P1` exits:

   * `flag[1] = false`
   * `P0` proceeds

Thus, **mutual exclusion is maintained**.

---

## 7. Properties of Peterson’s Solution

### 7.1 Mutual Exclusion ✔

Only one process can be in the critical section at a time.

---

### 7.2 Progress ✔

If no process is in the critical section, one of the waiting processes will eventually enter.

---

### 7.3 Bounded Waiting ✔

A process will not wait indefinitely; entry is guaranteed after a finite number of turns.

---

## 8. Why Peterson’s Solution Works

* `flag[]` expresses **interest**
* `turn` resolves **conflict**
* Busy waiting ensures safety without deadlock

---

## 9. Limitations of Peterson’s Solution

| Limitation               | Explanation                      |
| ------------------------ | -------------------------------- |
| Only for 2 processes     | Does not scale                   |
| Busy waiting             | Wastes CPU cycles                |
| Not practical            | Modern CPUs reorder instructions |
| No hardware optimization | Slower than locks                |

---

Not used in production systems.
