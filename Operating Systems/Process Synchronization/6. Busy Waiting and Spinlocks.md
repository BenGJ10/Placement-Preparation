# Busy Waiting and Spin Lock

**Busy Waiting** and **Spin Locks** are closely related concepts used in **process synchronization**, especially at **low-level OS and multiprocessor systems**.  

They trade **CPU efficiency** for **low latency**, making them suitable only in specific scenarios.

---

## 1. Busy Waiting

### Definition
**Busy Waiting** occurs when a process or thread:
> Repeatedly checks a condition in a loop while waiting for access to a resource, **without relinquishing the CPU**.

The process stays active (spins) instead of being blocked or put to sleep.

---

### Example of Busy Waiting

```cpp
while (lock == 1) {
    // keep checking
}
````

Here, the thread:

* does not sleep
* consumes CPU cycles
* waits until `lock` becomes available

---

### Why Busy Waiting Happens

Busy waiting is used when:

* waiting time is expected to be **very short**
* context switching overhead is **more expensive** than spinning
* blocking is not possible (e.g., inside kernel)

---

### Disadvantages of Busy Waiting

* Wastes CPU cycles
* Reduces system throughput
* Not suitable for long waits
* Can degrade performance in single-core systems

---

## 2. Spin Lock

### Definition

A **Spin Lock** is a synchronization mechanism that:

> Uses **busy waiting** to repeatedly check for lock availability until it acquires the lock.

It is a lock where threads **spin in a loop** instead of sleeping.

---

### Basic Spin Lock Implementation (Conceptual)

```cpp
while (test_and_set(lock)) {
    // spin
}
```

* `test_and_set` is an **atomic hardware instruction**
* Lock is acquired when it becomes free

---

## 3. How Spin Lock Works

1. Thread tries to acquire the lock
2. If lock is unavailable:

   * thread keeps checking (spins)
3. When lock becomes free:

   * thread immediately acquires it
4. Thread releases lock after critical section

---

## 4. Spin Lock vs Blocking Lock

| Aspect            | Spin Lock    | Blocking Lock     |
| ----------------- | ------------ | ----------------- |
| Waiting method    | Busy waiting | Sleep / block     |
| CPU usage         | High         | Low               |
| Context switching | None         | Required          |
| Suitable for      | Short CS     | Long CS           |
| Use case          | Kernel, SMP  | User applications |

---

## 5. Spin Lock Example (C++ Conceptual)

```cpp
#include <atomic>

atomic_flag lock = ATOMIC_FLAG_INIT;

void critical_section() {
    while (lock.test_and_set()) {
        // spin
    }

    // critical section

    lock.clear();
}
```

---

## 6. Busy Waiting vs Spin Lock

| Aspect         | Busy Waiting             | Spin Lock                   |
| -------------- | ------------------------ | --------------------------- |
| Concept        | Waiting without sleeping | Lock that uses busy waiting |
| Purpose        | Generic waiting          | Mutual exclusion            |
| Implementation | Simple loop              | Uses atomic operations      |
| Control        | No lock abstraction      | Lock-based                  |

> **Spin lock is a controlled form of busy waiting**.

---

## 7. When Spin Locks Are Useful

Spin locks are ideal when:

* critical section is **very short**
* number of threads ≈ number of CPU cores
* used in **kernel mode**
* context switching cost is high

---

## 8. When Spin Locks Are Dangerous

Avoid spin locks when:

* single-core systems
* critical section is long
* high contention exists
* power efficiency matters

---

## 9. Busy Waiting in Semaphores

### Inefficient Version

```cpp
wait(S) {
    while (S <= 0);
    S--;
}
```

This is **busy waiting**.

### Efficient Version (Blocking)

```cpp
wait(S) {
    S--;
    if (S < 0)
        block();
}
```

Modern OSes prefer **blocking**, not spinning.

---

## 10. Real-World Analogy

**Standing in front of a washroom door**

* Busy waiting: keep checking door continuously
* Blocking: wait until someone tells you it’s free

Spin lock is like **standing very close** to grab the door instantly.

---

## Summary

| Concept      | Description                        |
| ------------ | ---------------------------------- |
| Busy Waiting | Repeated checking without sleeping |
| Spin Lock    | Lock that uses busy waiting        |
| CPU usage    | High                               |
| Best use     | Short critical sections            |
| Risk         | Wasted CPU cycles                  |

---

## Key Takeaways

* Busy waiting wastes CPU but reduces latency

* Spin locks are a structured form of busy waiting

* Useful in kernels and multiprocessor systems

* Bad choice for long waits or single-core systems

* Blocking locks are preferred in user space
