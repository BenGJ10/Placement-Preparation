# Scheduling Queues

**Scheduling queues** are data structures maintained by the Operating System to **manage and organize processes** at different stages of their lifecycle.  

They help the OS decide **which process should run next**, **which should wait**, and **which are suspended or completed**.

---

## 1. What are Scheduling Queues?

### Definition
Scheduling queues are **lists of processes** that are grouped based on their **current state** in the system.

Each process moves between queues as its state changes:
- New → Ready → Running → Waiting → Ready → Terminated

---

## 2. Types of Scheduling Queues

An operating system typically maintains the following queues:

1. **Job Queue**
2. **Ready Queue**
3. **Waiting (Device) Queues**

---

## 3. Job Queue

### Description
The **Job Queue** contains **all processes that have entered the system**, regardless of their current state.

### Role of Scheduler
- Managed by the **Long-Term Scheduler**
- Controls the **degree of multiprogramming**
- Decides which jobs are admitted into main memory

### Key Characteristics
- Usually stored on disk
- Large number of processes
- FIFO-like structure (conceptually)

---

## 4. Ready Queue

### Description
The **Ready Queue** holds all processes that are:
- in main memory
- ready to execute
- waiting only for CPU allocation

Only processes in the **Ready Queue** can be scheduled on the CPU.

---

### Role of Scheduler
- Managed by the **Short-Term Scheduler**
- Selects one process to execute next

### Characteristics
- Implemented using:
  - linked list
  - priority queue
  - multilevel queues
- Ordering depends on scheduling algorithm

---

## 5. Waiting (Device) Queues

### Description
A **Waiting Queue** (or Device Queue) contains processes that are:
- waiting for an I/O operation
- waiting for a resource
- waiting for an event to occur

Each device may have its own waiting queue.

---

### Examples
- Disk I/O queue
- Printer queue
- Network I/O queue

### Key Point
When the I/O operation completes:
- Process moves from **Waiting Queue → Ready Queue**

---

## 6. Suspended Queues (Advanced Concept)

### Description
Suspended processes are:
- temporarily removed from main memory
- stored on secondary storage (disk)

Reasons for suspension:
- memory pressure
- long waiting time
- user request

---

### Types of Suspended Queues

1. **Ready Suspended Queue**
   - Process is ready but swapped out

2. **Blocked Suspended Queue**
   - Process is waiting for I/O and swapped out

Managed by the **Medium-Term Scheduler**.

---

## 7. Process Movement Between Queues

### Typical Transitions

- New → Job Queue  
- Job Queue → Ready Queue (admitted to memory)  
- Ready Queue → Running (CPU allocated)  
- Running → Waiting Queue (I/O request)  
- Waiting Queue → Ready Queue (I/O completed)  
- Running → Ready Queue (preemption)  
- Running → Terminated  

---

## 8. Scheduling Queues and Schedulers

| Queue | Managed By |
|-----|------------|
| Job Queue | Long-Term Scheduler |
| Ready Queue | Short-Term Scheduler |
| Waiting Queue | I/O subsystem |
| Suspended Queues | Medium-Term Scheduler |

---

## 9. Ready Queue vs Waiting Queue

| Aspect | Ready Queue | Waiting Queue |
|------|------------|---------------|
| CPU eligibility | Yes | No |
| Waiting for | CPU | I/O or event |
| State | Ready | Blocked |
| Scheduler | Short-term | I/O manager |

---

## Key Takeaways

- Scheduling queues organize processes based on their states  

- Only processes in the **Ready Queue** can execute  

- Multiple schedulers work together using these queues  

- Queue transitions define the process lifecycle
