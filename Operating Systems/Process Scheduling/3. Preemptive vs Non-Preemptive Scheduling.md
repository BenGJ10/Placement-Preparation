# Preemptive vs Non-Preemptive Scheduling

CPU scheduling can be broadly classified into **Preemptive** and **Non-Preemptive** scheduling based on whether a running process can be interrupted.

---

## Preemptive Scheduling

### Definition
In **preemptive scheduling**, the operating system can **interrupt a running process** and allocate the CPU to another process.

### Key Characteristics
- CPU can be taken away before process completes
- Requires **context switching**
- More responsive
- Suitable for interactive and real-time systems

### Examples
- Round Robin (RR)
- Priority Scheduling (Preemptive)
- Shortest Remaining Time First (SRTF)

---

## Non-Preemptive Scheduling

### Definition
In **non-preemptive scheduling**, once a process gets the CPU, it **keeps it until it finishes or blocks** for I/O.

### Key Characteristics
- No forced interruption
- Simple to implement
- Lower overhead
- Poor response time for interactive systems

### Examples
- First Come First Serve (FCFS)
- Shortest Job First (Non-preemptive)
- Priority Scheduling (Non-preemptive)

---

## Comparison Table

| Aspect | Preemptive | Non-Preemptive |
|------|------------|----------------|
| CPU interruption | Allowed | Not allowed |
| Context switching | Frequent | Minimal |
| Response time | Low (fast) | High (slow) |
| Complexity | Higher | Simpler |
| Starvation risk | Possible | Possible |
| System type | Interactive, Real-time | Batch systems |

---

## Key Takeaway

- **Preemptive scheduling** improves responsiveness but adds overhead.  

- **Non-preemptive scheduling** is simpler but can cause long waiting times.  

- Modern operating systems mostly use **preemptive scheduling**.
