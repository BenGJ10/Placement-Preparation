# Process Scheduling

**Process Scheduling** is a core function of the **Operating System (OS)** that determines **which process gets the CPU, when, and for how long**.  

Since the CPU can execute only one process at a time (per core), scheduling is essential to ensure **efficient CPU utilization**, **fairness**, and **system responsiveness**.

Process scheduling plays a critical role in **multitasking, multi-user systems**, and **real-time systems**.

---

## 1. What is Process Scheduling?

### Definition
Process scheduling is the OS mechanism that:
> Selects one process from the **ready queue** and allocates the **CPU** to it.

The OS scheduler continuously decides:
- which process should run next
- how long it should run
- when to preempt it

---

## 2. Why Process Scheduling is Needed

**Without scheduling:**

- CPU would remain idle during I/O waits

- Only one program could run at a time

- System would be slow and unresponsive

**Process scheduling enables:**

- **Multiprogramming** (multiple processes in memory)

- **Multitasking** (fast switching between processes)

- **Fair resource sharing**

- **Maximum CPU utilization**

---

## 3. Scheduling Queues

The OS maintains multiple queues to manage processes.

### 1. Job Queue
- Contains all processes in the system

### 2. Ready Queue
- Processes waiting to be assigned CPU

### 3. Waiting (I/O) Queue
- Processes waiting for I/O completion

The scheduler picks processes from the **ready queue**.

---

## 4. Components Involved in Scheduling

### 1. Scheduler
The scheduler selects a process from the ready queue. 
There are three types of schedulers:

- **Long-term scheduler** – controls degree of multiprogramming  
- **Short-term scheduler** – selects next process for CPU  
- **Medium-term scheduler** – handles swapping (suspend/resume)

---

### 2. Dispatcher
The dispatcher:
- Performs **context switching**
- Switches CPU to selected process
- Transfers control to user mode

---

## 5. Preemptive vs Non-Preemptive Scheduling

### Non-Preemptive Scheduling

- CPU is released only when process terminates or blocks
- Simpler but less responsive

### Preemptive Scheduling

- CPU can be taken away from a running process
- Improves responsiveness
- Requires context switching

---

## 6. When Does Scheduling Occur?

Scheduling decisions occur when:

-  Process switches from Running → Waiting  
-  Process switches from Running → Ready  
-  Process switches from Waiting → Ready  
-  Process terminates  

Preemptive scheduling applies to cases (2) and (3).

---

## 7. Goals of Process Scheduling

A good scheduling system aims to:

| Goal | Description |
|-----|-------------|
| **CPU Utilization** | Keep CPU busy |
| **Throughput** | Maximize processes completed per unit time |
| **Turnaround Time** | Minimize time from submission to completion |
| **Waiting Time** | Minimize time in ready queue |
| **Response Time** | Quick response for interactive systems |
| **Fairness** | Prevent starvation |

---

## 8. Scheduling and Context Switching

Each scheduling decision may cause a **context switch**, which involves:
- Saving CPU registers of current process
- Loading registers of next process
- Updating PCB

Context switching adds **overhead**, so schedulers try to minimize unnecessary switches.

---

## Key Takeaways

- Process scheduling enables multitasking and CPU efficiency  

- Scheduler selects processes; dispatcher performs execution switch  

- Scheduling goals vary by system type  

- Choice of algorithm directly affects performance and responsiveness
