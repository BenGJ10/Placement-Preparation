# Scheduling Criterias

Before selecting or designing a **CPU scheduling algorithm**, certain **performance criteria** are used to evaluate how effective the scheduler is.  

These criteria help measure **efficiency, responsiveness, and fairness** of process scheduling.

---

## 1. Throughput

### Definition
**Throughput** is the **number of processes completed per unit time**.

> It measures how much work the system finishes in a given period.

### Interpretation
- Higher throughput → better system performance
- Important in **batch systems** where job completion matters more than response

### Example
If a system completes 50 processes in 10 seconds:

```
Throughput = 5 processes/second
```

---

## 2. Waiting Time

### Definition
**Waiting Time** is the **total time a process spends in the ready queue**, waiting for CPU allocation.

> It excludes execution time and I/O time.

### Formula

```
Waiting Time = Turnaround Time − CPU Burst Time
```

### Importance
- Lower waiting time → better user experience
- High waiting time indicates **poor scheduling or starvation**

### Focused In
- FCFS, SJF comparisons
- Scheduling algorithm analysis

---

## 3. Response Time

### Definition
**Response Time** is the **time interval between process submission and the first CPU response**.

> It measures how quickly a system responds to a request.

### Formula

```
Response Time = First CPU Start Time − Arrival Time
```

### Importance
- Crucial for **interactive systems**
- Determines system responsiveness
- More important than turnaround time for user-facing systems

---

## 4. Turnaround Time (TAT)

### Definition
**Turnaround Time (TAT)** is the **total time taken by a process from submission to completion**.

> Includes waiting time, execution time, and I/O time.

### Formula

```
Turnaround Time = Completion Time − Arrival Time
```

### Importance
- Measures overall process efficiency
- Critical for **batch processing systems**

---

## 5. CPU Utilization

### Definition
**CPU Utilization** is the **percentage of time the CPU is actively executing processes**.

> Indicates how effectively the CPU resources are used.

### Formula

```
CPU Utilization = (CPU Busy Time / Total Time) × 100
```

### Importance
- Higher utilization → less idle CPU
- Goal is to maximize utilization without harming responsiveness

---

## Summary Table

| Criterion | Meaning | Optimization Goal |
|---------|---------|-------------------|
| **Throughput** | Processes completed per unit time | Maximize |
| **Waiting Time** | Time in ready queue | Minimize |
| **Response Time** | Time to first response | Minimize |
| **Turnaround Time** | Submission to completion | Minimize |
| **CPU Utilization** | CPU busy percentage | Maximize |

---

## Key Takeaways

- No single scheduling algorithm optimizes all criteria equally.  

- **Batch systems** prioritize throughput and turnaround time.  

- **Interactive systems** prioritize response time.  

- **Efficient scheduling** balances CPU utilization with fairness and responsiveness.
