# Scheduler vs Dispatcher

In an Operating System, both the **Scheduler** and the **Dispatcher** work together to manage CPU allocation, but their **roles are different and clearly separated**.  

---

## Scheduler

### Definition
The **Scheduler** is the OS component that **decides which process should run next** from the ready queue, based on a scheduling algorithm.

### Responsibilities
- Select a process from the **ready queue**
- Apply scheduling policies (FCFS, RR, Priority, etc.)
- Decide *when* a context switch should occur

### Characteristics
- Involves **decision-making**
- Works at a **logical level**
- Invoked frequently (especially short-term scheduler)
- Affects overall system performance and fairness

---

## Dispatcher

### Definition
The **Dispatcher** is the OS component that **actually gives control of the CPU** to the process selected by the scheduler.

### Responsibilities
- Perform **context switching**
- Switch CPU from kernel mode to user mode
- Jump to the correct instruction of the selected process

### Characteristics
- No decision-making
- Works at a **low-level (mechanical execution)**
- Must be extremely fast
- Responsible for execution transfer

---

## Scheduler vs Dispatcher – Comparison Table

| Aspect | Scheduler | Dispatcher |
|------|-----------|------------|
| Role | Decides which process runs next | Executes the decision |
| Decision making | Yes | No |
| Works on | Ready queue | CPU & registers |
| Context switching | Decides when | Performs it |
| Speed requirement | High | Very high |
| Level | Logical | Low-level / operational |
| Example | Selecting process P2 | Loading P2’s PCB and registers |

---

## Relationship Between Scheduler and Dispatcher

1. Scheduler selects the next process  
2. Dispatcher performs context switch  
3. CPU control is transferred to the selected process  

They always work **together**:
- Scheduler = **brain**
- Dispatcher = **hands**

---

## Key Takeaways

- Scheduler decides **who runs**

- Dispatcher ensures the selected process **actually runs**

- Scheduler focuses on policy; dispatcher focuses on execution

- Both are essential for multitasking and process management
