# Multilevel Queue Scheduling

**Multilevel Queue Scheduling (MLQ)** is a CPU scheduling technique in which the **ready queue is divided into multiple separate queues**, each representing a **different class of processes**.  

Each queue has its **own scheduling algorithm**, and processes are **permanently assigned** to a specific queue.

This approach is useful when processes can be **clearly categorized** based on priority or behavior.

---

## 1. What is Multilevel Queue Scheduling?

### Definition
In **Multilevel Queue Scheduling**, the ready queue is split into **multiple queues**, and:
- each queue has a **fixed priority**
- processes **do not move between queues**
- CPU scheduling happens **between queues and within queues**

---

## 2. Why Multilevel Queue Scheduling is Needed

Different processes have different requirements:

- System processes → need high priority  
- Interactive processes → need quick response  
- Batch processes → need high throughput  

Using a **single ready queue** cannot efficiently satisfy all these needs.

MLQ solves this by **segregating processes into queues**.

---

## 3. Structure of Multilevel Queue Scheduling

Typical queue separation:

1. **System processes**
2. **Interactive processes**
3. **Batch processes**

Each queue:
- has its own priority
- uses its own scheduling algorithm

---

## 4. Example Queue Structure

| Queue | Process Type | Scheduling Algorithm | Priority |
|-----|--------------|----------------------|----------|
| Q1 | System processes | Priority Scheduling | Highest |
| Q2 | Interactive processes | Round Robin | Medium |
| Q3 | Batch processes | FCFS | Lowest |

---

## 5. Scheduling Between Queues

### Two Approaches

#### 5.1 Fixed Priority Scheduling (Most Common)

- CPU always serves **highest-priority non-empty queue**
- Lower-priority queues may **starve**

Example:

```
Q1 > Q2 > Q3
```

If Q1 always has processes, Q2 and Q3 never execute.

---

#### 5.2 Time Slicing Between Queues

- Each queue gets a **fixed percentage of CPU time**

Example:
- Q1 → 50%
- Q2 → 30%
- Q3 → 20%

This reduces starvation.

---

## 6. Scheduling Within Queues

Each queue can use a **different scheduling algorithm**:

| Queue | Algorithm Used |
|-----|----------------|
| System | Priority |
| Interactive | Round Robin |
| Batch | FCFS |

This allows **custom scheduling behavior** per process type.

---

## 7. Example Scenario

Processes categorized as:

- Foreground (interactive)
- Background (batch)

Queues:
```
Q1 (Foreground) → Round Robin
Q2 (Background) → FCFS
```

CPU always checks Q1 first.  
Only when Q1 is empty does Q2 get CPU time.

---

## 8. Key Characteristics

- Multiple ready queues
- Fixed queue assignment
- Different scheduling policies per queue
- Priority-based CPU allocation

---

## 9. Advantages vs Disadvantages

| Advantages | Disadvantages |
|------------|----------------|
| Clear process categorization | Starvation of lower-priority queues |
| Custom scheduling per queue | Rigid structure (no queue movement) |
| Efficient for mixed workloads | Complexity in managing multiple queues |
| Easy to implement | Less flexible than dynamic approaches |

---

## Key Takeaways

- Multilevel Queue Scheduling divides ready queue into **multiple fixed queues**

- Each queue has its own **priority and algorithm**

- Processes **cannot move between queues**

- Simple but may cause **starvation**

- Foundation for **Multilevel Feedback Queue Scheduling**
