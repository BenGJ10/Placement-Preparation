# Fragmentation in Operating Systems

**Fragmentation** is a critical problem in memory management that reduces the efficiency of RAM utilization and impacts system performance.

Understanding internal vs external fragmentation is essential for placement exams and interview preparation.

---

## 1. What is Fragmentation?

### Definition

**Fragmentation** is the phenomenon where memory becomes unusable or inefficiently distributed, either **within** allocated blocks or as **scattered free spaces**.

### Impact

- Reduces usable memory
- Prevents allocation of available space
- Degrades system performance
- Increases need for compaction or reallocation

---

## 2. Two Types of Fragmentation

Fragmentation occurs in two distinct forms:

1. **Internal Fragmentation** – Waste inside allocated blocks
2. **External Fragmentation** – Unusable scattered free holes

---

## 3. Internal Fragmentation

### Definition

**Internal Fragmentation** is the unused memory **within** an allocated memory block or page.

### When It Occurs

- Process smaller than allocated partition/page
- Fixed partition size not matching process size
- Alignment requirements waste space

### Example

**Scenario:**
- Page size: 4096 bytes
- Process needs: 3900 bytes
- Allocated: 4096 bytes (one full page)
- Wasted: 196 bytes (internal fragmentation)

### Common in

- Fixed partitioning
- Paging systems
- Fixed-size memory allocators

### Severity

- Moderate impact
- Decreases with smaller page/partition size
- Typically 10-50% of page size

### Solution Approaches

- Smaller page sizes (but increases overhead)
- Exact-fit allocation (not always possible)
- Accept as necessary trade-off

---

## 4. External Fragmentation

### Definition

**External Fragmentation** is fragmentation where **free memory exists but is scattered** into small non-contiguous holes, preventing allocation of contiguous blocks.

### When It Occurs

- Dynamic allocation and deallocation
- Processes of varying sizes
- Variable partition sizing

### Example

**Memory Layout:**
```
[Process A: 1000B] [Free: 300B] [Process B: 500B] [Free: 200B] [Process C: 800B] [Free: 100B]
```

**Scenario:**
- Total free memory: 600 B
- Process needs: 400 B continuous
- Cannot allocate despite 600 B free!

### Common in

- Variable partitioning
- Contiguous allocation schemes
- Linked lists / malloc implementations

### Severity

- **High impact** – Can make large portions of RAM unusable
- Worsens over time with usage
- Eventually 50% of memory may be fragmented

### Solution Approaches

- Compaction (expensive)
- Non-contiguous allocation (paging)
- Segmentation with relocation
- Virtual memory techniques

---

## 5. Internal vs External Fragmentation

| Aspect | Internal Fragmentation | External Fragmentation |
|------|--------------------------|------------------------|
| **Location** | Within allocated block | Between allocated blocks |
| **Memory status** | Allocated but unused | Free but scattered |
| **Severity** | Moderate | High (increases over time) |
| **Solution** | Accept or use smaller units | Compaction or non-contiguous allocation |
| **Allocation scheme** | Fixed partitioning, paging | Dynamic/variable partitioning |
| **Can prevent allocation** | No (doesn't block other processes) | Yes (critical problem) |

---

## 6. Causes of Fragmentation

### Internal Fragmentation Causes

1. **Fixed page/partition size** larger than actual need
2. **Alignment requirements** (e.g., processes start at boundary)
3. **Overhead** in allocation structures
4. **Memory granularity** of hardware

### External Fragmentation Causes

1. **Variable process sizes** → different-sized gaps
2. **Process termination** → creates holes
3. **Dynamic allocation patterns** → irregular free space
4. **No compaction policy** → gaps accumulate

---

## 7. Fragmentation Ratio

### Measurement

**External Fragmentation Ratio:**
```
Fragmentation Ratio = (Fragmented Memory / Total Free Memory) × 100%
```

**Example:**
```
Total RAM: 10,000 KB
Allocated: 6,000 KB
Free: 4,000 KB
Largest contiguous hole: 500 KB
Fragmentation: (3,500 / 4,000) × 100 = 87.5%
```

---

## 8. Fragmentation in Different Memory Systems

### In Paging

- **Internal fragmentation:** Common (one page per process last page)
- **External fragmentation:** Eliminated (non-contiguous allocation)
- **Typical waste:** ~50% of page size per process

### In Segmentation

- **Internal fragmentation:** Minimal (variable-size segments)
- **External fragmentation:** Significant (like dynamic partitioning)
- Requires compaction over time

### In Fixed Partitioning

- **Internal fragmentation:** High (partition size mismatch)
- **External fragmentation:** None (contiguous partitions)
- Entire partitions wasted if process small

### In Variable Partitioning

- **Internal fragmentation:** Minimal (exact-fit possible)
- **External fragmentation:** High (accumulates over time)
- Compaction needed periodically

---

## 9. Addressing Fragmentation

### For Internal Fragmentation

**Reduce by:**
- Smaller page/partition size (but increases management overhead)
- Exact-fit allocation where possible
- Accept as reasonable cost

**Accept because:**
- Benefit of fixed-size management outweighs small waste
- Trade-off inherent in design

### For External Fragmentation

**Solution strategies:**

1. **Compaction**
   - Move all processes together
   - Consolidate free space
   - Drawback: Expensive, causes system pause

2. **Non-contiguous Allocation**
   - Use paging or segmentation
   - Eliminate relocation requirement
   - Requires translation mechanism (MMU)

3. **Buddy System**
   - Allocate in power-of-2 sizes
   - Reduces fragmentation probability
   - Balanced tree-like merging

4. **Garbage Collection**
   - Compact memory periodically
   - More feasible for certain systems

---

## 10. Fragmentation in Real Systems

### Operating System Approaches

**Linux:**
- Page-based (minimal external fragmentation)
- Internal fragmentation accepted cost
- Page size: 4096 B (4 KB)

**Windows:**
- Page-based memory management
- Similar fragmentation profile
- Page size varies by architecture

**Embedded Systems:**
- Often variable partitioning
- Fragmentation carefully managed
- Limited memory demands custom approaches

---

## 11. Real-World Analogy

**Apartment building evacuation and resettlement**

- Internal fragmentation = Empty space in occupied apartment
- External fragmentation = Many small empty apartments scattered
- Compaction = Moving remaining tenants to consolidate occupied/empty blocks
- Paging = Prefabricated modular units (no fragmentation fitting)

---

## 12. Memory Fragmentation in Different Contexts

| Context | Type | Severity | Solution |
|---------|------|----------|----------|
| User-level malloc | External | High | Compaction, buddy system |
| OS paging | Internal | Low | Accept (inherent) |
| Fixed partitions | Internal | High | Accept or redesign |
| Dynamic partitions | External | High | Compaction, paging |

---

## Summary

| Type | Where | Severity | Solution |
|------|-------|----------|----------|
| Internal | Inside allocated block | Moderate | Accept, reduce block size |
| External | Between blocks | High | Compaction, non-contiguous allocation |

---

## Key Takeaways

- **Fragmentation wastes memory** and reduces effective utilization.

- **Internal fragmentation** acceptable in paging (small, bounded cost).

- **External fragmentation** critical problem in contiguous schemes.

- **Paging solves external fragmentation** by allowing non-contiguous allocation.

- **Trade-off:** Fixed-size (simple, some internal waste) vs. variable-size (complex, external fragmentation).

- Understanding fragmentation critical for interview questions on **memory management trade-offs**.
