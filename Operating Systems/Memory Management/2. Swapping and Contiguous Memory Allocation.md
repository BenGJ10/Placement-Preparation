# Swapping and Contiguous Memory Allocation

**Swapping** and **Contiguous Memory Allocation** are fundamental memory-management techniques that address how processes are placed and managed in RAM, forming the basis for understanding modern memory systems.

---

## 1. Swapping

### Definition

**Swapping** is a memory-management technique where the OS temporarily moves an entire process from RAM to secondary storage (disk) and later brings it back into RAM.

### Purpose

- Free up RAM for higher-priority or active processes
- Support a higher degree of multiprogramming than physical RAM allows
- Improve system responsiveness when RAM is insufficient

---

## 2. Why Swapping is Needed

- **Limited RAM:** Processes combined may exceed physical memory
- **Inactive processes:** Waiting processes consume valuable RAM
- **Priority changes:** New high-priority process needs immediate RAM
- **Virtual memory:** Enables system to run processes larger than RAM

---

## 3. Swapping Mechanism

### Basic Flow

```
Process in Ready/Blocked state in RAM (idle)
                ↓
      Context saved
                ↓
      Process written to Swap Space (Disk)
                ↓
    RAM freed for other processes
                ↓
    When needed, process loaded back
                ↓
      Process resumes execution
```

### Swap Space

- Special disk area reserved for process images
- Slower than RAM but allows more processes
- Often on fast SSD for performance

---

## 4. Advantages of Swapping

- **Higher multiprogramming:** More processes than RAM can hold
- **Better interactivity:** Active processes get RAM priority
- **System flexibility:** Process placement not limited to RAM size
- **Fair CPU time:** All processes get execution opportunities

---

## 5. Disadvantages of Swapping

- **Disk I/O overhead:** Reading/writing to disk is very slow
- **Thrashing risk:** Excessive swapping degrades performance
- **Context switch delay:** Swap-in/swap-out adds latency
- **Extra disk space needed:** Swap partition must be maintained

---

## 6. Contiguous Memory Allocation

### Definition

In **contiguous memory allocation**, each process is loaded into **one continuous block** of physical memory.

All instructions and data of a process occupy consecutive memory addresses.

---

## 7. Types of Contiguous Allocation

### 7.1 Fixed Partitioning

**Concept:**
- RAM divided into fixed-size partitions at boot time
- Each partition holds one process
- Number of partitions = max concurrent processes

**Characteristics:**
- Simple implementation
- Low overhead
- Wastes memory (internal fragmentation)
- Limited degree of multiprogramming

### 7.2 Variable (Dynamic) Partitioning

**Concept:**
- Partition size allocated dynamically based on process needs
- Partitions created on-the-fly as processes arrive
- More efficient memory use than fixed partitioning

**Characteristics:**
- Better memory utilization
- Causes external fragmentation
- Requires compaction periodically
- More complex to implement

---

## 8. Fragmentation in Contiguous Allocation

### Internal Fragmentation

**Definition:**  
Unused memory **within** an allocated partition.

**Occurs when:**
- Fixed partitions too large for process
- Process smaller than assigned partition

**Example:**
- Partition size: 1000 KB
- Process size: 600 KB
- Wasted space: 400 KB (internal fragmentation)

**Severity:** Common in fixed partitioning

### External Fragmentation

**Definition:**  
Free memory exists but is **split into small, non-contiguous holes**.

**Occurs when:**
- Processes are allocated and deallocated dynamically
- Gaps appear between process blocks

**Example:**
```
[Process A] [Free 200KB] [Process B] [Free 150KB] [Process C]

New process needs 300KB but max free hole is 200KB → Cannot allocate
```

**Severity:** Increases over time in dynamic partitioning

---

## 9. Compaction

### Definition

**Compaction** is a technique to reduce external fragmentation by moving all processes together and consolidating free space.

### Process

```
Before: [Process A] [Free] [Process B] [Free] [Process C] [Free]
           ↓ (Move processes together)
After:  [Process A] [Process B] [Process C] [Free...............]
```

### Advantages

- Recovers fragmented free space
- Allows more processes to fit

### Disadvantages

- **Very expensive:** Requires moving processes and updating references
- **Time-consuming:** Causes system pause during compaction
- **Not practical for large systems:** Frequent compaction impractical

---

## 10. Placement Strategies (Dynamic Partitioning)

When allocating memory from available holes, scheduler uses:

| Strategy | Algorithm | Advantage | Limitation |
|------|-----------|-----------|------------|
| **First Fit** | Pick first hole large enough | Fast search | Leaves many small holes at start |
| **Best Fit** | Pick smallest suitable hole | Minimal waste at allocation time | Creates tiny unusable fragments |
| **Worst Fit** | Pick largest hole | Keeps large remainders | Wastes largest potential hole |
| **Next Fit** | Start from last found (circular) | Reduces clustering at start | May miss better early holes |

**Recommendation:**  
First Fit offers good balance of speed and fragmentation.

---

## 11. Swapping vs Contiguous Allocation

| Aspect | Swapping | Contiguous Allocation |
|------|----------|-----------------------|
| **Primary goal** | Move processes to disk when RAM full | Allocate processes to RAM |
| **Scope** | Entire process at once | Within available RAM |
| **Storage location** | Disk (secondary memory) | RAM (primary memory) |
| **Fragmentation** | Reduces RAM fragmentation indirectly | Directly causes fragmentation |
| **Speed impact** | High (disk I/O very slow) | Minimal (within RAM) |
| **When used** | Memory pressure, priority changes | Always for process placement |

---

## 12. Real-World Analogy

**Apartment building management**

- RAM = Available floors in building
- Processes = Tenants
- Fixed partitions = Predefined unit sizes
- Dynamic partitions = Custom-sized units
- Swapping to disk = Moving tenants to temporary warehouse
- Fragmentation = Unusable space gaps
- Compaction = Reorganizing all tenants together

---

## Summary

| Concept | Key Idea |
|------|-----------|
| Swapping | Move entire process to/from disk |
| Contiguous Allocation | One continuous RAM block per process |
| Internal Fragmentation | Waste inside allocated block |
| External Fragmentation | Scattered free holes |
| Compaction | Consolidate free space by moving processes |

---

## Key Takeaways

- **Swapping** enables more processes than RAM can hold via disk storage.

- **Contiguous allocation** simple but causes fragmentation.

- **Fixed partitions** waste space; **dynamic partitions** fragment over time.

- **Placement strategies** (First Fit, Best Fit) balance performance and fragmentation.

- **Compaction** expensive but recovers external fragmentation.

- Both techniques fundamental to understanding **virtual memory** and **paging**.
