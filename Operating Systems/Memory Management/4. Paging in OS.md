# Paging in Operating Systems

**Paging** is a modern memory-management technique that divides memory into fixed-size units, eliminating external fragmentation and enabling efficient virtual memory systems.

It is one of the most important concepts in OS and appears frequently in interviews.

---

## 1. What is Paging?

### Definition

**Paging** is a memory-management technique that:
- Divides logical memory into fixed-size blocks called **pages**
- Divides physical memory into fixed-size blocks called **frames**
- Maps pages to frames (page size = frame size)

### Key Concept

Each process is divided into pages; pages can be scattered anywhere in RAM as long as mapping exists.

---

## 2. Why Paging?

### Problems with Contiguous Allocation

- External fragmentation limits usable memory
- Cannot use scattered free spaces
- Requires compaction (expensive)
- Limits multiprogramming

### Solutions Provided by Paging

- **Eliminates external fragmentation** completely
- Easy allocation of any free frame
- Supports virtual memory efficiently
- Flexible process placement

---

## 3. Basic Paging Terminology

### Page

- Fixed-size block of logical memory
- Typically 4 KB (can be 2 KB to 8 KB)
- All pages of a system same size

### Frame

- Fixed-size block of physical memory
- Same size as page
- Number of frames = RAM size / frame size

### Page Table

- Data structure mapping pages to frames
- One per process
- Stored in memory

### Page Offset

- Offset within a page
- Lower bits of logical address
- Same for logical and physical address

---

## 4. Address Translation in Paging

### Logical Address Structure

```
Logical Address = [Page Number | Offset]
                     (p bits)    (d bits)
```

### Translation Process

```
Step 1: Extract page number (p) and offset (d)
        from logical address

Step 2: Use page number to index page table
        Page Table[p] → Frame Number (f)

Step 3: Construct physical address
        Physical Address = [Frame Number | Offset]
                              (f)         (d)

Step 4: Memory accesses physical address
```

### Example

**Given:**
- Logical address: 4000 (10-bit address space)
- Page size: 1024 bytes
- Page number: 4000 / 1024 = 3
- Offset: 4000 % 1024 = 928

**Page Table Entry:**
- Page 3 → Frame 7

**Physical Address:**
- 7 × 1024 + 928 = 7168 + 928 = 8096

---

## 5. Page Table

### Purpose

Maps each logical page to physical frame.

### Structure

```
Page Number | Frame Number | Valid Bit | Other Bits
     0      |       2      |    1      | ...
     1      |       5      |    1      | ...
     2      |      **      |    0      | ... (page not in memory)
     3      |       7      |    1      | ...
```

### Size Calculation

```
Page Table Size = Number of Pages × Entry Size
                = (Logical Address Space / Page Size) × Entry Size

Example:
- 32-bit address space, 4 KB pages: 2^32 / 4096 = 1M entries
- 4 bytes per entry: 4 MB per process page table
```

### Stored In

- Main memory (fast access)
- Can be cached in TLB for performance

---

## 6. Advantages of Paging

✅ **Eliminates External Fragmentation**
- No scattered unusable holes
- Any frame can be allocated

✅ **Simple Allocation**
- Find any free frame and assign
- O(1) allocation time

✅ **Virtual Memory Support**
- Pages not in RAM stored on disk
- Demand paging feasible

✅ **Protection**
- Each page has separate entry
- Fine-grained access control

✅ **Sharing**
- Pages can be shared between processes
- Same physical frame, multiple page table entries

---

## 7. Disadvantages of Paging

❌ **Internal Fragmentation**
- Last page of process may not be full
- Typically ~50% of page size wasted

❌ **Page Table Overhead**
- Extra memory for page tables
- Each process needs separate table

❌ **Translation Overhead**
- Every memory access requires translation
- Can be slow without TLB

❌ **Page Table Size**
- For large address spaces, page tables huge
- Requires hierarchical or multi-level paging

❌ **Complexity**
- More complex than contiguous allocation
- Requires hardware support (MMU)

---

## 8. Page Table Entry (PTE) Structure

### Typical PTE Fields

| Field | Bits | Purpose |
|-------|------|---------|
| Frame Number | Variable | Physical frame location |
| Valid Bit | 1 | Is page in memory? |
| Dirty Bit | 1 | Has page been modified? |
| Reference Bit | 1 | Has page been recently accessed? |
| Protection Bits | 2-3 | Read, Write, Execute permissions |
| Cache Bit | 1 | Disable caching? |

### Example: 32-bit System

```
Frame Number (20 bits) | Flags (12 bits)
- Valid, Dirty, Reference, Protection, Cache, etc.
```

## 9. Page Size Selection

### Small Page Size (2 KB)

**Advantages:**
- Reduces internal fragmentation
- Reduces memory overhead per process

**Disadvantages:**
- Large page table
- More page faults
- Higher TLB miss rate

### Large Page Size (8 KB, 16 KB)

**Advantages:**
- Smaller page tables
- Fewer page faults
- Better I/O performance

**Disadvantages:**
- More internal fragmentation
- Wastes more memory per process

### Typical Choice: 4 KB

- Balance between fragmentation and overhead
- Default on x86, ARM systems

---

## 10. Paging Hardware Requirements

### MMU (Memory Management Unit)

- Performs address translation
- Consulted for every memory access
- Critical performance component

### TLB (Translation Lookaside Buffer)

- Cache of frequently used page table entries
- Very fast (4-5 CPU cycles vs 100+ for memory)
- Reduces translation overhead

### Protection Mechanisms

- Valid/invalid bits
- Permission bits (read, write, execute)
- Separate page tables per process

---

## 11. Real-World Analogy

**Library book storage system**

- Library = Physical memory (RAM)
- Books = Data
- Fixed shelves (pages) = Fixed memory blocks
- Book catalog (page table) = Mapping system
- Librarian lookup = MMU translation
- Catalog cache = TLB

---

## 12. Paging vs Segmentation (Quick Comparison)

| Aspect | Paging | Segmentation |
|--------|--------|--------------|
| Division | Fixed-size | Variable-size (logical) |
| Fragmentation (external) | Eliminated | Can occur |
| Fragmentation (internal) | Small | None |
| Page table size | Large for 32+ bit spaces | Variable |
| Translation complexity | Simple (one table lookup) | More complex (bounds check) |
| Sharing support | Excellent | Excellent |
| Protection granularity | Per page | Per segment |

---

## Summary

| Concept | Key Point |
|---------|-----------|
| Paging | Divide memory into fixed-size pages/frames |
| Address translation | Page number used as index into page table |
| Advantage | No external fragmentation |
| Disadvantage | Internal fragmentation + translation overhead |
| Hardware support | MMU + TLB required |

---

## Key Takeaways

- **Paging** solves external fragmentation by non-contiguous allocation.

- **Page table** maps logical pages to physical frames.

- **Address translation** uses page number to lookup frame number.

- **Internal fragmentation** small but exists (last page waste).

- **TLB** critical for performance (cache page table entries).

- **Page size trade-off:** 4 KB typical balance point.

- Interview questions focus on **translation mechanism, advantages vs contiguous allocation, and virtual memory integration**.
