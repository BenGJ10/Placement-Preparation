# Segmentation in Operating Systems

**Segmentation** is a memory-management technique that divides process address space into variable-size logical units, matching the programmer's logical view of the program.

It provides fine-grained protection and sharing but introduces external fragmentation.

---

## 1. What is Segmentation?

### Definition

**Segmentation** is a memory-management technique where a process address space is divided into **variable-size logical units called segments**.

Each segment represents a logical entity:
- Code segment
- Data segment
- Stack segment
- Heap segment

### Key Concept

Logical memory divided into segments based on **program logic**, not fixed size.

---

## 2. Why Segmentation?

### Limitations of Contiguous Allocation

- No protection within process (code, data, stack)
- Cannot share code/data between processes easily
- Entire address space contiguous

### Limitations of Simple Paging

- Hides logical structure
- Difficult to implement protection per module
- Poor sharing granularity

### Solutions by Segmentation

- Matches programmer's logical view
- Fine-grained protection per segment
- Efficient sharing of segments
- Supports different access rights per segment

---

## 3. Segment Structure

### What Defines a Segment

A segment can represent:

| Segment Type | Example | Size |
|--------|---------|------|
| **Code** | Function, procedure | Variable |
| **Data** | Global variables, constants | Variable |
| **Stack** | Local variables, return addresses | Variable, grows |
| **Heap** | Dynamic memory | Variable, grows |
| **Shared Library** | libc, etc. | Variable |

### Process Memory with Segmentation

```
High Address: [Stack Segment - growing down]
                      ↕
                  [Free Space]
                      ↕
              [Heap Segment - growing up]
                      ↓
              [Data Segment - static]
                      ↓
              [Code Segment]
Low Address:  [OS Reserved]
```

---

## 4. Segment Table

### Purpose

Maps logical segments to physical memory.

### Structure

```
Segment Number | Base Address | Limit | Other Bits
      0        |   1000       | 2000  | Read, Write, Execute
      1        |   4000       | 1500  | Read, Execute
      2        |   6000       | 3000  | Read, Write
      3        |   9500       | 2500  | Read, Write
```

### Entry Components

- **Segment number:** Logical identifier (0-31 typically)
- **Base:** Starting physical address
- **Limit:** Segment size (length)
- **Protection bits:** Read, Write, Execute, Shared

---

## 5. Address Translation in Segmentation

### Logical Address Format

```
Logical Address = [Segment Number | Offset]
                      (s bits)    (d bits)
```

### Translation Process

```
Step 1: Extract segment number (s) and offset (d)
        from logical address

Step 2: Check if s < Number of Segments
        If not → Trap (segment number out of range)

Step 3: Check if d < Segment Limit
        If not → Trap (offset beyond segment)

Step 4: Physical Address = Base + offset
        (if protection checks pass)

Step 5: Memory accesses physical address
```

### Example

**Given:**
- Logical address: (segment 1, offset 500)
- Segment table entry 1: Base = 6000, Limit = 1000
- Offset check: 500 < 1000 ✓

**Physical Address:**
- 6000 + 500 = 6500

## 6. Protection in Segmentation

### Access Control

Each segment can have independent permissions:

```
Code Segment:    Read, Execute (not Write)
Data Segment:    Read, Write (not Execute)
Stack Segment:   Read, Write (not Execute)
Shared Library:  Read, Execute (shared)
```

### Protection Check During Translation

```
For each memory access:
  IF offset ≥ limit
    THEN Trap (access violation)
  IF access_type NOT in segment_permissions
    THEN Trap (protection violation)
  ELSE Allow access
```

### Advantages

- **Fine-grained control** per module/function
- **Prevents code corruption** (execute-only)
- **Stack overflow detection** (limit check)
- **Sharing with controls** (different processes different permissions)

---

## 7. Advantages of Segmentation

✅ **Logical Organization**
- Matches programmer's view
- Easy to understand and debug

✅ **Fine-Grained Protection**
- Per-segment access control
- Prevents code/data intermingling corruption

✅ **Sharing**
- Segments easily shared between processes
- Example: shared library in memory once

✅ **Dynamic Growth**
- Segments can grow dynamically
- Stack/heap can expand as needed

✅ **Modularity**
- Program naturally divided by function
- Different modules can have different properties

---

## 8. Disadvantages of Segmentation

❌ **External Fragmentation**
- Variable-size segments cause fragmentation
- Free holes accumulate over time
- Requires compaction

❌ **Complexity**
- More complex translation than paging
- Compaction expensive
- Variable-size management overhead

❌ **Allocation Difficulty**
- Finding suitable hole for segment difficult
- First Fit, Best Fit decisions
- Performance unpredictable

❌ **Segment Table Size**
- Can be large for process with many segments
- Still per-process overhead

❌ **Unused Segments**
- Allocated but not fully utilized
- Wastes memory if sparse usage

---

## 9. Segmentation vs Paging

| Aspect | Segmentation | Paging |
|--------|--------------|--------|
| **Division basis** | Logical units | Fixed-size blocks |
| **Size of units** | Variable | Fixed (e.g., 4 KB) |
| **External fragmentation** | Yes (can occur) | No (eliminated) |
| **Internal fragmentation** | No | Yes (small per page) |
| **Translation** | Bounds check + Base | Page table lookup |
| **Protection granularity** | Per segment | Per page |
| **Sharing** | Efficient (segments) | Efficient (pages) |
| **Programmer awareness** | Visible | Usually invisible |
| **Hardware complexity** | Moderate | Simple |

## 10. Segment Table Entry (STE) Fields

| Field | Bits | Purpose |
|-------|------|---------|
| Base Address | 24-30 | Starting physical address |
| Limit (Size) | 10-16 | Segment length |
| Valid Bit | 1 | Is segment in memory? |
| Access Rights | 3-4 | Read, Write, Execute, Shared |
| Dirty Bit | 1 | Modified since loaded? |
| Referenced Bit | 1 | Recently accessed? |

**Multi-building university campus**

## 12. Combined Segmentation + Paging

### Modern Hybrid Approach

Many modern systems use both:

```
Logical Address
    ↓
  [Segment Table] → Intermediate Address
    ↓
  [Page Table] → Physical Address
```

**Benefits:**
- Logical view of segmentation
- No external fragmentation (paging)
- Fine-grained protection (segments)

**Used by:** Intel x86 (IA-32 uses both), some RISC systems

## 14. Common Segmentation Issues

### Stack Overflow

**Detection:**
- Stack grows downward
- If offset > limit (downward), trap occurs
- Prevents stack from corrupting data

### Illegal Code Execution

**Prevention:**
- Code segment execute-only
- Data segment non-executable
- Bounds and permission checks catch violations

## Summary

| Concept | Key Point |
|---------|-----------|
| Segmentation | Variable-size logical memory divisions |
| Segment table | Maps segments to base + limit |
| Translation | Segment number, bounds check, base + offset |
| Advantage | Logical structure, fine protection |
| Disadvantage | External fragmentation |

---

## Key Takeaways

- **Segmentation** matches logical program structure (code, data, stack).

- **Variable-size** segments provide flexibility and fine-grained protection.

- **Address translation** includes bounds checking (offset < limit).

- **Sharing** efficient at segment level (entire modules shared).

- **External fragmentation** main drawback (requires compaction or hybrid approach).

- **Often combined with paging** in modern systems for best of both.

- Interview questions focus on **translation, protection, and comparison with paging**.
