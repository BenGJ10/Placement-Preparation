# BIOS vs UEFI

When a computer is powered on, a small program stored on the motherboard initializes the hardware and starts the operating system.  
Historically, this was done by **BIOS**, but modern systems now use **UEFI**, which offers enhanced features, security, and performance.

This comparison is essential for understanding system boot processes, OS installation, firmware design, and hardware interaction.

---

## Definition

### BIOS (Basic Input/Output System)

- BIOS is a **firmware interface** introduced in the late 1970s.  
- Stored in a **ROM/EEPROM chip** on the motherboard.  
- Performs **Power-On Self Test (POST)** and initializes hardware.  
- Uses the **MBR (Master Boot Record)** boot method.  
- Operates in **16-bit real mode**, limiting hardware capabilities.

### UEFI (Unified Extensible Firmware Interface)

- UEFI is a modern replacement for BIOS, introduced to overcome its limitations.  
- Stored in **flash memory** on the motherboard.  
- Supports a **graphical interface**, mouse support, and advanced drivers.  
- Uses the **GPT (GUID Partition Table)** boot method.  
- Operates in **32-bit or 64-bit mode**, supporting large storage and faster initialization.

---

## Key Differences

| Feature                       | BIOS                                           | UEFI                                               |
|------------------------------|------------------------------------------------|----------------------------------------------------|
| **Full Form**                | Basic Input/Output System                      | Unified Extensible Firmware Interface              |
| **Launch Mode**              | 16-bit Real Mode                               | 32-bit / 64-bit mode                               |
| **Boot Method**              | MBR (Master Boot Record)                       | GPT (GUID Partition Table)                         |
| **Supported Disk Size**      | Up to 2 TB                                     | Larger than 2 TB (up to 9.4 ZB theoretically)      |
| **Number of Partitions**     | Maximum 4 primary partitions                    | Up to 128 partitions                               |
| **Boot Speed**               | Slower                                         | Faster                                             |
| **User Interface**           | Text-based                                     | Graphical with mouse support                       |
| **Security**                 | No Secure Boot                                 | Supports Secure Boot                               |
| **Driver Support**           | Limited, legacy                                 | Advanced drivers, modular architecture             |
| **Network Boot Support**     | Basic                                           | Advanced (PXE, remote diagnostics)                 |
| **Extensibility**            | Limited                                         | Highly extensible via drivers & applications       |
| **Compatibility**            | Supported by older hardware                     | Supported by modern hardware                       |

## How They Work

### BIOS Boot Process

1. System powers on  

2. BIOS performs **POST**  

3. BIOS checks boot device order  

4. Reads first sector from disk (**MBR**)  

5. Loads bootloader from MBR  

6. Bootloader loads the OS  

**Limitation:**  
MBR can only store boot information in the first 512 bytes of disk.

---

### UEFI Boot Process

1. System powers on  

2. UEFI runs **POST**  

3. Looks for `.efi` files in the **EFI System Partition (ESP)**  

4. Loads UEFI boot manager  

5. Boot manager loads OS loader (e.g., `grubx64.efi`, `bootmgfw.efi`)  

**Benefit:**  
Multiple OS bootloaders can coexist in the EFI System Partition.

---

## Security Features

### BIOS
- Lacks modern security features.
- No built-in system to verify the OS bootloader integrity.

### UEFI
- Supports **Secure Boot**, which:
  - Verifies digital signatures of bootloaders
  - Prevents rootkits/malware at boot level  
- Supports Trusted Platform Module (**TPM**) integration.

---

## MBR vs GPT (Boot Disk Format)

| Aspect                   | MBR                              | GPT                                   |
|--------------------------|-----------------------------------|----------------------------------------|
| **Max Disk Size**        | 2 TB                              | > 2 TB                                 |
| **Partitions**           | 4 primary partitions              | 128 partitions                         |
| **Data Integrity**       | No redundancy                     | CRC32 checksum for partition tables    |
| **Boot Compatibility**   | BIOS only                         | UEFI (with backward support)           |

---

### Advantages of BIOS

- Highly compatible with older hardware  
- Simple and stable  
- Works well for older operating systems (e.g., Windows XP)  

### Advantages of UEFI

- Much faster boot process  
- Supports very large disks with GPT  
- Better security (Secure Boot)  
- Better UI and diagnostics tools  
- Network and remote troubleshooting support  
- Can run applications before OS boot  

---

## Compatibility Layers

- **UEFI systems can run BIOS-mode booting** through **CSM (Compatibility Support Module)**.  
- BIOS cannot run UEFI booting.  

Most modern motherboards still include CSM for legacy boot support.

## Key Takeaways

- **BIOS is older and simpler**, but limited in speed, security, and disk support.  

- **UEFI is modern, fast, secure, and supports large storage** → used in all modern systems.  

- UEFI uses **GPT**, while BIOS uses **MBR** for boot management.  

- UEFI’s Secure Boot enhances system integrity against malware.  

- Modern operating systems (Windows 10+, Linux distros, macOS) prefer UEFI.
