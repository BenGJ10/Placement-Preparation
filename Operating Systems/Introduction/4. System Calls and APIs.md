# System Calls and APIs

In an operating system, **System Calls** and **APIs** form the backbone of interaction between user-level applications and the underlying hardware or OS services.  

Although related, they serve different purposes and operate at different levels of abstraction.

---

## System Calls

- A **system call** is a **low-level, privileged interface** that allows user applications to request services from the **kernel** of the operating system.

- Provides controlled access to hardware and critical OS functionalities.

- Represents a **boundary** between user mode and kernel mode.

**Examples of System Call Operations:**

- File operations (open, read, write, close)
- Process control (fork, exec, exit)
- Memory management (mmap, brk)
- Device handling (ioctl)
- Networking (socket, bind, connect)

---

## API (Application Programming Interface)

- An **API** is a **high-level interface** used by application developers to interact with system services, libraries, or frameworks.

- APIs do **not directly interact with the kernel**; instead, they often **wrap system calls** internally.

- Examples include:
  - POSIX API
  - Win32 API
  - Java I/O API
  - Python’s os module

**APIs are meant for developers;  
System Calls are meant for the OS itself.**

---

## How System Calls Work (Concept)

1. User program makes an API call → e.g., `fopen()`.  

2. The library function translates it into a system call → e.g., `open()`.  

3. CPU switches from **User Mode → Kernel Mode**.  

4. Kernel executes the requested operation.  

5. Returns result back to user program → Kernel Mode → User Mode.

---

## Types of System Calls

### 1. Process Control
Used to create, execute, and manage processes.

Examples:
- `fork()` – create new process  
- `exec()` – replace process image  
- `exit()` – terminate process  
- `wait()` – wait for process completion  

---

### 2. File Management
Operations on files and directories.

Examples:
- `open()`  
- `read()`  
- `write()`  
- `close()`  
- `unlink()`  

---

### 3. Device Management
Communicate with hardware devices.

Examples:
- `ioctl()` – device-specific operations  
- `read()` / `write()` on device files  

---

### 4. Information Maintenance
Retrieve and set system information.

Examples:
- `getpid()` – get process ID  
- `gettimeofday()` – time fetching  
- `uname()` – OS info  

---

### 5. Communication (IPC)
Enable inter-process communication.

Examples:
- `pipe()`  
- `shmget()` – shared memory  
- `send()` / `recv()` – message passing  
- `socket()` – network communication  

---

## API vs System Call

| Feature                | System Call                                  | API                                           |
|------------------------|-----------------------------------------------|-----------------------------------------------|
| **Level**              | Low-level, kernel-level                      | High-level, user-level                        |
| **Mode**               | Requires switch to kernel mode               | Runs in user mode                             |
| **Purpose**            | Access OS services                           | Provide a programming interface               |
| **Performance**        | Slower (context switches)                    | Faster; may call system calls internally      |
| **Portability**        | OS-specific                                   | More portable (POSIX, Java, Python APIs)      |
| **Ease of Use**        | Hard for developers                          | Easy to use and understand                    |
| **Example**            | `open()`, `fork()`, `read()`                 | `fopen()`, Java File API, Python os module    |

---

## Example: System Call vs API Call

### API Call (C code)
```c
FILE *fp = fopen("data.txt", "r");
````

### Translation:

`fopen()` internally invokes the **system call**:

```c
open("data.txt", O_RDONLY);
```

### Why this abstraction?

* API adds error handling
* API is portable across OS
* User doesn't need to handle low-level kernel details

## Real-World Analogy

| Layer           | Analogy                                              |
| --------------- | ---------------------------------------------------- |
| **API**         | Hotel **reception desk** (friendly, easy to talk to) |
| **System Call** | The **back-office staff** doing the real work        |
| **Kernel**      | The **engine room** running the operations           |

---


## Key Takeaways

* **System Calls = The OS entry point for low-level operations.**

* **APIs = High-level abstractions that internally use system calls.**

* System calls require **mode switching** and direct kernel interaction; APIs do not.

* Developers mostly interact with APIs; the OS interacts with system calls.
