# Deadlock Prevention

**Deadlock Prevention** is a strategy used by operating systems to **ensure that deadlocks never occur** by **eliminating at least one of the four necessary conditions for deadlock**.

Instead of detecting or recovering from deadlocks, prevention **proactively restricts resource allocation policies**.

---

## 1. Idea Behind Deadlock Prevention

A deadlock can occur **if and only if** all four Coffman conditions hold simultaneously:

1. Mutual Exclusion  
2. Hold and Wait  
3. No Preemption  
4. Circular Wait  

> **Deadlock prevention works by breaking at least one of these conditions.**

---

## 2. Breaking Mutual Exclusion

### Concept
- Make resources **shareable** whenever possible
- If resources can be shared, mutual exclusion is removed

### Example
- Read-only files
- Shared memory for reading

### Limitation
- Many resources **cannot be shared**
  - printers
  - mutex locks
  - critical sections

➡️ Not a general solution

---

## 3. Breaking Hold and Wait

### Technique 1: Request All Resources at Once

- A process must request **all required resources before execution**
- Process runs only if all resources are available

### Example

```
Request R1, R2, R3 together
```

### Technique 2: Release Before Requesting More

- Process must release all currently held resources
- Then request new resources

### Advantages
- Prevents partial holding
- Eliminates hold-and-wait

### Disadvantages
- Poor resource utilization
- Starvation possible
- Difficult to predict all resources in advance

---

## 4. Breaking No Preemption

### Concept
- If a process holding resources requests another unavailable resource:
  - force it to **release all held resources**
  - resources are preempted

### Example
- CPU registers
- Memory pages (can be swapped)

### Limitation
- Not possible for:
  - printers
  - mutex-protected critical sections

---

## 5. Breaking Circular Wait (Most Practical Method)

### Resource Ordering

- Assign a **total order** to all resource types
- Processes must request resources in **increasing order**

### Example

```
R1 < R2 < R3
```

Valid:

```
Request R1 → R2 → R3
```

Invalid:
```
Request R3 → R1
```

### Why It Works
- Cycles become impossible
- Circular wait is eliminated

---

## 6. Comparison of Prevention Techniques

| Condition Broken | Technique | Practicality |
|-----------------|-----------|--------------|
| Mutual Exclusion | Share resources | Low |
| Hold and Wait | Request all at once | Medium |
| No Preemption | Force release | Low |
| Circular Wait | Resource ordering | High |

---

## 7. Deadlock Prevention vs Deadlock Avoidance

| Aspect | Prevention | Avoidance |
|------|------------|-----------|
| Strategy | Restrictive | Predictive |
| Deadlock | Impossible | Avoided dynamically |
| Resource utilization | Low | Better |
| Knowledge required | No | Yes |

---

## 8. Advantages of Deadlock Prevention

- Simple concept
- No runtime deadlock detection
- Guaranteed deadlock-free system

---

## 9. Disadvantages of Deadlock Prevention

- Reduced concurrency
- Poor resource utilization
- Possible starvation
- Rigid system rules

---

## 10. Real-World Analogy

**One-way streets**

- Cars must follow a fixed direction
- No circular traffic flow
- Deadlocks avoided

---

## Summary

| Aspect | Description |
|------|-------------|
| Goal | Ensure deadlock never occurs |
| Method | Break necessary conditions |
| Best technique | Circular wait prevention |
| Trade-off | Reduced efficiency |

---

## Key Takeaways

- Deadlock prevention ensures **deadlocks never happen**

- Breaks at least one of the four conditions

- Resource ordering is the most practical method

- Comes at the cost of reduced performance

- Used in systems where deadlock is unacceptable
