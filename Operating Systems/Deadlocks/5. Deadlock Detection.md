# Deadlock Detection

**Deadlock Detection** is a strategy where the operating system **allows deadlocks to occur** and then **detects and recovers from them**.  

Instead of preventing or avoiding deadlocks, the OS periodically **checks the system state** to determine whether a deadlock exists.

This approach is used when:
- Deadlocks are **rare**
- Prevention or avoidance is **too costly**

---

## 1. What is Deadlock Detection?

### Definition
Deadlock detection is a technique in which:
> The operating system examines the system’s resource allocation state to determine whether a **deadlock has occurred**.

If deadlock is found, the system then initiates **recovery actions**.

---

## 2. When is Deadlock Detection Used?

Deadlock detection is suitable when:
- Deadlocks are infrequent
- System can tolerate temporary deadlock
- Overhead of prevention/avoidance is high

Many general-purpose OSes follow this approach.

---

## 3. Difference from Other Deadlock Strategies

| Strategy | Deadlock Occurrence | Action Taken |
|--------|--------------------|--------------|
| Prevention | Never allowed | Restrict conditions |
| Avoidance | Avoid unsafe states | Predict & check |
| Detection | Allowed | Detect & recover |
| Ignorance | Ignored | Manual handling |

---

## 4. Deadlock Detection Using Resource Allocation Graph (RAG)

### Case 1: Single Instance per Resource

- Construct a **Resource Allocation Graph**
- If a **cycle exists**, a deadlock is present

### Graph Elements
- Process → Circle
- Resource → Square
- Request edge: P → R
- Assignment edge: R → P

---

### Case 2: Multiple Instances per Resource

- Cycle alone is **not sufficient**
- Use a **Deadlock Detection Algorithm** (similar to Banker’s Algorithm)

---

## 5. Deadlock Detection Algorithm (Multiple Instances)

### Data Structures Used

| Structure | Description |
|---------|-------------|
| Available | Number of free resources |
| Allocation | Resources allocated to processes |
| Request | Current outstanding requests |

---

### Algorithm Steps

1. Initialize:
```

Work = Available
Finish[i] = false (for all i where Allocation[i] ≠ 0)

```

2. Find a process `Pi` such that:
```

Finish[i] == false AND Request[i] ≤ Work

```

3. If found:
```

Work = Work + Allocation[i]
Finish[i] = true

```

4. Repeat steps 2–3 until no such process exists

5. If:
```

Finish[i] == false

```
for any process → **deadlock exists**

---

## 6. Example (Conceptual)

Processes P0, P1, P2 are deadlocked if:
- None of them can satisfy their requests with available resources
- Each is waiting for others to release resources

---

## 7. Deadlock Recovery Methods

Once deadlock is detected, OS must recover.

---

### 7.1 Process Termination

- Abort all deadlocked processes  
or  
- Abort one process at a time until deadlock is resolved

**Selection Criteria:**
- Priority
- Resources held
- Execution time
- Process type

---

### 7.2 Resource Preemption

- Temporarily take resources from processes
- Rollback process to safe state
- Risk of starvation

---

## 8. Cost of Deadlock Detection

| Cost Factor | Impact |
|-----------|-------|
| Detection frequency | High frequency → overhead |
| Number of processes | More → complex |
| Recovery cost | Process loss |

---

## 9. Deadlock Detection vs Deadlock Avoidance

| Aspect | Detection | Avoidance |
|------|-----------|-----------|
| Deadlock allowed | Yes | No |
| Runtime checks | Periodic | On every request |
| Resource utilization | High | Medium |
| Complexity | Medium | High |

---

**Traffic monitoring**

## Summary

| Aspect | Description |
|------|-------------|
| Strategy | Detect & recover |
| Deadlock allowed | Yes |
| Key tools | RAG, detection algorithm |

---

## Key Takeaways

- Deadlock detection allows deadlocks to occur  

- OS periodically checks for deadlock  

- Cycle detection works for single-instance resources  

- Recovery is essential after detection  

- Used when deadlocks are rare
