# Starvation in Operating Systems

**Starvation** is a major problem in **CPU scheduling and resource allocation** where a process is **ready to execute but never gets the required resources**.  

Unlike deadlock, the system continues running, but **some processes may wait indefinitely**.

---

## 1. What is Starvation?

### Definition
**Starvation** (also called *indefinite postponement*) occurs when:
> A process waits for CPU or resources **for an unbounded amount of time** due to **unfair scheduling or resource allocation**.

The process is alive and ready, but **never selected**.

---

## 2. How Starvation Occurs

Starvation typically arises due to:

- Priority-based scheduling
- Shortest Job First (SJF / SRTF)
- Multilevel Queue Scheduling
- Improper resource allocation policies

---

## 3. Starvation Example

### Priority Scheduling Example

| Process | Priority |
|-------|----------|
| P1 | High |
| P2 | Low |

If high-priority processes keep arriving:
- P1 keeps executing
- P2 never gets CPU → **starvation**

---

## 4. Starvation vs Deadlock

| Aspect | Starvation | Deadlock |
|------|------------|----------|
| Nature | Indefinite waiting | Circular waiting |
| System state | System runs normally | System halts |
| Cause | Scheduling unfairness | Resource dependency |
| Recovery | Aging, fair scheduling | Prevention / Detection |

---

## 5. Starvation vs Livelock

| Aspect | Starvation | Livelock |
|------|------------|----------|
| Progress | No | No |
| CPU usage | Low for starved process | High |
| Cause | Resource denial | Continuous state changes |

---

## 6. Effects of Starvation

- Poor fairness
- Unpredictable execution
- Some processes never complete
- Reduced system reliability

---

## 7. How to Prevent Starvation

### 7.1 Aging (Primary Solution)

**Aging** increases a process’s priority the longer it waits.

Example:
```

Every 10 seconds waiting → increase priority

```

Eventually, the process executes.

---

### 7.2 Fair Scheduling Algorithms

- Round Robin
- Multilevel Feedback Queue (MLFQ)
- Completely Fair Scheduler (Linux)

---

### 7.3 Resource Request Limits

- Limit repeated resource allocation to same process
- Enforce fairness constraints

---

## 8. Starvation in Synchronization

Starvation can occur with:
- Semaphores (wrong signaling order)
- Locks (priority inversion)
- Reader–Writer problem (writer starvation)

---

## 9. Real-World Analogy

**Queue-jumping in a hospital**

- Emergency patients keep arriving
- Regular patients wait indefinitely
- Regular patients are starved

---

## Summary

| Concept | Description |
|------|-------------|
| Starvation | Indefinite waiting |
| Cause | Unfair scheduling |
| System state | Running |
| Solution | Aging, fairness |

---

## Key Takeaways

- Starvation means a process **never gets CPU/resources**

- System continues running, unlike deadlock

- Common in priority-based algorithms

- **Aging is the most effective solution**

- Fair scheduling prevents starvation
