# Banker’s Algorithm

**Banker’s Algorithm** is a **deadlock avoidance algorithm** used in Operating Systems to ensure that the system **never enters an unsafe state**.  

It works by **simulating resource allocation** and checking whether the system can still satisfy all processes in some safe order.

The algorithm is named after a banker who only lends money if he can ensure all customers will be able to repay.

---

## 1. Why Banker’s Algorithm is Needed

- Deadlock avoidance requires the system to **make decisions before allocating resources**
- Allocating resources blindly may push the system into an **unsafe state**
- Banker’s Algorithm checks **system safety** before granting requests

---

## 2. Key Idea of Banker’s Algorithm

> A resource request is granted **only if the system remains in a safe state** after allocation.

- **Safe State** → There exists a safe sequence
- **Unsafe State** → Deadlock may occur

---

## 3. Assumptions of Banker’s Algorithm

1. Number of processes is fixed
2. Number of resource types is fixed
3. Maximum resource requirement of each process is known in advance
4. Resources are not preempted forcibly
5. Processes eventually release resources

---

## 4. Data Structures Used

For **n processes** and **m resource types**:

### 4.1 Available

```
Available[m]
```
Number of available instances of each resource

---

### 4.2 Max

```
Max[n][m]
```
Maximum demand of each process

---

### 4.3 Allocation

```
Allocation[n][m]
```
Resources currently allocated to each process

---

### 4.4 Need

```
Need[n][m] = Max[n][m] − Allocation[n][m]
```
Remaining resources required by each process

---

## 5. Banker’s Algorithm Components

Banker’s Algorithm consists of **two main algorithms**:

1. **Safety Algorithm**
2. **Resource Request Algorithm**

---

## 6. Safety Algorithm

### Purpose
To determine whether the system is in a **safe state**.

---

### Steps

1. Initialize:

```
Work = Available
Finish[i] = false (for all processes)
```

2. Find a process `Pi` such that:

```
Finish[i] == false AND Need[i] ≤ Work
```

3. If found:

```
Work = Work + Allocation[i]
Finish[i] = true
```

4. Repeat until no such process exists

5. If all `Finish[i] == true`:
- System is **safe**
- Safe sequence exists

Else:
- System is **unsafe**

---

## 7. Resource Request Algorithm

When a process `Pi` makes a request `Request[i]`:

1. If:

```
Request[i] > Need[i]
```
→ Error (process exceeded max claim)

2. If:

```
Request[i] > Available
```
→ Process must wait

3. Pretend to allocate resources:

```
Available = Available − Request[i]
Allocation[i] = Allocation[i] + Request[i]
Need[i] = Need[i] − Request[i]
```

4. Run **Safety Algorithm**
   - If safe → grant request
   - If unsafe → rollback allocation

---

## 8. Banker’s Algorithm Example (Numerical)

### Given:
- **5 processes** (P0–P4)
- **3 resource types** (A, B, C)

---

### Available

| A | B | C |
|---|---|---|
| 3 | 3 | 2 |

---

### Max Matrix

| Process | A | B | C |
|-------|---|---|---|
| P0 | 7 | 5 | 3 |
| P1 | 3 | 2 | 2 |
| P2 | 9 | 0 | 2 |
| P3 | 2 | 2 | 2 |
| P4 | 4 | 3 | 3 |

---

### Allocation Matrix

| Process | A | B | C |
|-------|---|---|---|
| P0 | 0 | 1 | 0 |
| P1 | 2 | 0 | 0 |
| P2 | 3 | 0 | 2 |
| P3 | 2 | 1 | 1 |
| P4 | 0 | 0 | 2 |

---

### Need Matrix (Max − Allocation)

| Process | A | B | C |
|-------|---|---|---|
| P0 | 7 | 4 | 3 |
| P1 | 1 | 2 | 2 |
| P2 | 6 | 0 | 0 |
| P3 | 0 | 1 | 1 |
| P4 | 4 | 3 | 1 |

---

## 9. Safety Check (Step-by-Step)

Initial:
```

Work = (3,3,2)

```

### Step 1:
- P1 can execute (Need ≤ Work)

```
Work = (5,3,2)
```

### Step 2:
- P3 can execute

```
Work = (7,4,3)
```

### Step 3:
- P4 can execute

```
Work = (7,4,5)
```

### Step 4:
- P0 can execute

```
Work = (7,5,5)
```

### Step 5:
- P2 can execute

All processes finish.

---

### Safe Sequence

```
⟨ P1, P3, P4, P0, P2 ⟩
```

✅ System is in a **safe state**.

---

## 10. Banker’s Algorithm vs Deadlock Detection

| Aspect | Banker’s Algorithm | Deadlock Detection |
|------|-------------------|-------------------|
| Deadlock allowed | No | Yes |
| Strategy | Avoidance | Detect & recover |
| Runtime overhead | High | Medium |
| Resource utilization | Medium | High |

---

## 11. Advantages of Banker’s Algorithm

- Guarantees deadlock-free execution
- Better resource utilization than prevention
- Formal and systematic approach

---

## 12. Disadvantages of Banker’s Algorithm

- Requires advance knowledge of max demand
- High computational overhead
- Not suitable for large, dynamic systems
- Rarely used in real-world OS kernels

---

## Summary

| Aspect | Description |
|------|-------------|
| Type | Deadlock Avoidance |
| Key Concept | Safe state |
| Main Tools | Safety + Request algorithms |

## Key Takeaways

- Banker’s Algorithm avoids deadlock by ensuring safety  

- Works only when maximum resource needs are known  

- Uses `Available`, `Max`, `Allocation`, and `Need` matrices  

- Safe sequence guarantees deadlock-free execution  

- Important for exams and OS fundamentals
