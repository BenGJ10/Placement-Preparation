# `const` Keyword in C++

The **`const` keyword** in C++ is used to **enforce immutability** and **enable safer, more predictable code**.

It tells the compiler:

> **“This value or behavior must not be modified.”**

---

## 1. Why `const` Exists

Without `const`:

* Objects can be modified accidentally
* APIs become unsafe
* Compiler optimizations are limited

Using `const`:

* Prevents bugs
* Improves code readability
* Enables compiler optimizations
* Expresses design intent clearly

---

## 2. `const` Variables

### Basic Example

```cpp
const int x = 10;
x = 20;   // ❌ Error
```

✔ Value cannot be modified after initialization
✔ Must be initialized at declaration

---

## 3. `const` with Pointers (Most Confusing Part)

### Rule of Thumb

> **Read `const` from right to left.**

---

### 3.1 Pointer to Constant Data

```cpp
const int* ptr;
```

or

```cpp
int const* ptr;
```

Meaning:

* Data is constant
* Pointer can change

```cpp
*ptr = 10;   // ❌
ptr = &x;    // ✔
```

---

### 3.2 Constant Pointer

```cpp
int* const ptr;
```

Meaning:

* Pointer is constant
* Data can change

```cpp
*ptr = 10;   // ✔
ptr = &x;    // ❌
```

---

### 3.3 Constant Pointer to Constant Data

```cpp
const int* const ptr;
```

Meaning:

* Neither pointer nor data can change

---

### Summary Table

| Declaration            | Pointer Change | Data Change |
| ---------------------- | -------------- | ----------- |
| `const int* ptr`       | ✔              | ❌           |
| `int* const ptr`       | ❌              | ✔           |
| `const int* const ptr` | ❌              | ❌           |

---

## 4. `const` Function Parameters

### Pass by Value

```cpp
void func(const int x);
```

* Protects local copy
* Rarely useful

---

### Pass by Reference (Important)

```cpp
void print(const string& s);
```

✔ Prevents modification
✔ Avoids copying
✔ Preferred for large objects

---

## 5. `const` Return Types

```cpp
const int getValue();
```

* Prevents modification of returned value
* Rarely useful for primitive types

More useful with references:

```cpp
const string& getName();
```

---

## 6. `const` Member Functions

### Definition

A **const member function** guarantees that:

* It does **not modify object state**

Syntax:

```cpp
void show() const;
```

---

### Example

```cpp
class Test {
    int x;
public:
    void set(int v) {
        x = v;
    }

    void show() const {
        cout << x;
    }
};
```

Inside `show()`:

* `this` becomes `const Test* const`

---

## 7. Why `const` Member Functions Matter

* Can be called on **const objects**
* Enable read-only access
* Required for STL compatibility

```cpp
const Test t;
t.show();    // ✔
t.set(5);    // ❌
```

---

## 8. `mutable` Keyword (Exception to `const`)

`mutable` allows modification inside `const` functions.

```cpp
class Cache {
    mutable int hits = 0;
public:
    void get() const {
        hits++;
    }
};
```

✔ Logical constness
✔ Physical mutation allowed

---

## 9. `const` Objects

```cpp
const Test t;
```

Rules:

* Can call only `const` member functions
* Cannot modify data members

---

## 10. `const` and Overloading

C++ allows overloading based on `const`.

```cpp
class Demo {
public:
    void show() {
        cout << "Non-const\n";
    }

    void show() const {
        cout << "Const\n";
    }
};
```

Called based on object constness.

---

## 11. `const` and References

```cpp
int x = 10;
const int& ref = x;
```

✔ Cannot modify through reference
✔ Can bind to temporaries

---

## 12. `const` and `static`

```cpp
class A {
public:
    static const int size = 100;
};
```

✔ Compile-time constant
✔ No separate definition needed (integral types)

Modern C++:

```cpp
static constexpr int size = 100;
```

---

## 13. `const` vs `#define`

| Aspect      | `const` | `#define` |
| ----------- | ------- | --------- |
| Type safety | ✔ Yes   | ❌ No      |
| Scope       | Scoped  | Global    |
| Debugging   | ✔ Easy  | ❌ Hard    |
| Preferred   | ✔ Yes   | ❌ No      |

---

## 14. Common Mistakes

* Forgetting `const` on member functions
* Misplacing `const` with pointers
* Overusing `const` on return-by-value
* Ignoring const correctness in APIs

---

## Key Takeaways

* `const` enforces immutability and safety

* Read pointer `const` **right to left**

* Always use `const` references for parameters

* Mark member functions `const` whenever possible

* `mutable` supports logical constness

* Essential for professional C++ design
