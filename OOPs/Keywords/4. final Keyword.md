# `final` Keyword in C++

The **`final` keyword** in C++ is used to **restrict inheritance and overriding**.

It enforces **design intent** by preventing:

* Further inheritance of a class
* Further overriding of a virtual function

> **`final` means: “This is the end of the inheritance chain.”**

---

## 1. Why `final` Exists

Without `final`:

* Classes can be inherited unintentionally
* Virtual functions can be overridden incorrectly
* Design contracts can be violated

`final` helps:

* Preserve **class invariants**
* Prevent misuse of polymorphism
* Improve **code safety and clarity**

---

## 2. `final` Applied to Virtual Functions

### Definition

When `final` is applied to a **virtual function**, it **prevents further overriding** in derived classes.

---

### Example

```cpp
class Base {
public:
    virtual void show() final {
        cout << "Base show()\n";
    }
};

class Derived : public Base {
public:
    void show() {   // ❌ Error
        cout << "Derived show()\n";
    }
};
```

✔ Compiler error prevents override
✔ Enforces final behavior

---

## 3. `final` with `override` (Best Practice)

The recommended order is:

```cpp
void show() override final;
```

Example:

```cpp
class Derived : public Base {
public:
    void show() override final {
        cout << "Final implementation\n";
    }
};
```

Meaning:

* This function **overrides**
* This override is the **last allowed one**

---

## 4. `final` Applied to Classes

### Definition

When applied to a class, `final` **prevents inheritance**.

---

### Example

```cpp
class Logger final {
public:
    void log() {
        cout << "Logging\n";
    }
};

class FileLogger : public Logger {  // ❌ Error
};
```

✔ No subclassing allowed
✔ Class can still be instantiated

---

## 5. When to Make a Class `final`

Use `final` for:

* Utility classes
* Security-sensitive classes
* Classes not designed for inheritance
* Performance-critical base classes

Example:

```cpp
class MathUtils final {
};
```

---

## 6. `final` and Abstract Classes

```cpp
class Shape final {
    virtual void draw() = 0;
};
```

❌ Invalid design:

* Abstract class **requires inheritance**
* `final` **prevents inheritance**

This combination is logically contradictory.

---

## 7. `final` vs `virtual`

| Aspect       | `virtual`         | `final`            |
| ------------ | ----------------- | ------------------ |
| Purpose      | Enable overriding | Prevent overriding |
| Usage        | Base behavior     | End behavior       |
| Polymorphism | Enables           | Restricts          |

They are **complementary**, not opposites.

---

## 8. `final` and Performance (Devirtualization)

Using `final` allows the compiler to:

* Skip vtable lookup
* Perform **devirtualization**
* Inline calls more aggressively

```cpp
class A {
public:
    virtual void f() final {}
};
```

✔ Potential performance improvement
✔ Zero semantic change

---

## 9. `final` vs `const`

| Aspect       | `final`               | `const`                |
| ------------ | --------------------- | ---------------------- |
| Applies to   | Class / function      | Data / functions       |
| Purpose      | Restricts inheritance | Restricts modification |
| Polymorphism | Affects               | Independent            |

---

## 10. `final` in Inheritance Chains

```cpp
class A {
public:
    virtual void f() {}
};

class B : public A {
public:
    void f() override final {}
};

class C : public B {
    // Cannot override f()
};
```

✔ Controlled inheritance depth
✔ Clear design boundary

---

## 11. Common Mistakes

* Marking non-virtual functions as `final`
* Making abstract classes `final`
* Assuming `final` means immutable
* Overusing `final` unnecessarily

---

## Key Takeaways

* `final` enforces **design intent**

* Prevents unwanted inheritance and overriding

* Works only with **virtual functions or classes**

* Helps compiler optimizations

* Improves code clarity and safety

* Should be used **intentionally**
