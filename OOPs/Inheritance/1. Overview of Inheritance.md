# Overview of Inheritance

**Inheritance** is a core principle of Object-Oriented Programming that allows a class to **acquire properties and behavior of another class**.

It models an **“is-a” relationship** between classes.

> **Inheritance enables code reuse, extensibility, and polymorphism.**

---

## 1. What is Inheritance?

Inheritance allows:

* A **derived (child) class** to reuse
* The **data members and member functions** of a **base (parent) class**

```cpp
class Base {
public:
    void show() {}
};

class Derived : public Base {
};
```

Here:

* `Derived` **is a** `Base`
* `Derived` automatically gets access to `Base`’s public/protected members

---

## 2. Why Inheritance Is Needed

Inheritance helps:

* Avoid code duplication
* Promote reuse
* Enable runtime polymorphism
* Create hierarchical class designs

Without inheritance:

* Same logic is rewritten
* Changes become error-prone
* Polymorphism is impossible

---

## 3. Basic Inheritance Example

```cpp
#include <iostream>
using namespace std;

class Animal {
public:
    void eat() {
        cout << "Eating\n";
    }
};

class Dog : public Animal {
public:
    void bark() {
        cout << "Barking\n";
    }
};

int main() {
    Dog d;
    d.eat();   // Inherited
    d.bark();  // Own behavior
}
```

✔ Code reuse
✔ Clear hierarchy

---

## 4. Access Specifiers in Inheritance

Inheritance behavior depends on **how the base class is inherited**.

### Access Rules

| Base Member | Public Inheritance | Protected Inheritance | Private Inheritance |
| ----------- | ------------------ | --------------------- | ------------------- |
| public      | public             | protected             | private             |
| protected   | protected          | protected             | private             |
| private     | ❌ not accessible   | ❌ not accessible      | ❌ not accessible    |

---

### Best Practice

👉 **Always prefer `public` inheritance**
It preserves the **“is-a” relationship**.

---

## 5. Types of Inheritance in C++

C++ supports multiple inheritance models:

| Type         | Description                  |
| ------------ | ---------------------------- |
| Single       | One base → one derived       |
| Multilevel   | Base → Derived → Derived     |
| Multiple     | Multiple bases → one derived |
| Hierarchical | One base → many derived      |
| Hybrid       | Combination of above         |

---

## 6. Inheritance and Polymorphism

Inheritance is a **prerequisite** for runtime polymorphism.

```cpp
class Base {
public:
    virtual void show() {
        cout << "Base\n";
    }
};

class Derived : public Base {
public:
    void show() override {
        cout << "Derived\n";
    }
};
```

```cpp
Base* b = new Derived();
b->show();   // Derived
```

✔ Behavior depends on object type
✔ Enabled by inheritance + virtual functions

---

## 7. What Inheritance Does NOT Inherit

A derived class does **not** inherit:

* Constructors
* Destructors
* Private members
* Assignment operators (directly)

But:

* Base constructors are **called automatically**
* Base destructor is called during object destruction

---

## 8. Constructor Order in Inheritance

```cpp
class Base {
public:
    Base() { cout << "Base\n"; }
};

class Derived : public Base {
public:
    Derived() { cout << "Derived\n"; }
};
```

Output:

```
Base
Derived
```

✔ Base constructed first
✔ Derived constructed later

Destruction happens in **reverse order**.

---

## 9. Common Mistakes with Inheritance

* Using inheritance instead of composition
* Forgetting virtual destructors
* Overusing multiple inheritance
* Violating Liskov Substitution Principle
* Inheriting for code reuse only (bad design)

---

| Aspect          | Inheritance              |
| --------------- | ------------------------ |
| Relationship    | Is-a                     |
| Enables         | Code reuse, polymorphism |

## Key Takeaways (Inheritance)

* Inheritance models real-world hierarchies
* Enables polymorphism when combined with `virtual`
* Base class is constructed before derived
* Prefer composition unless inheritance is semantically correct
