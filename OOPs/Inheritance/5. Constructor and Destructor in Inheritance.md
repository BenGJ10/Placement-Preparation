# Constructors and Destructors in Inheritance (C++)

In C++, **constructors and destructors play a critical role in inheritance**, as they control **object initialization and cleanup across class hierarchies**.

Understanding their **order of execution** and **rules** is essential to avoid:

* Undefined behavior
* Resource leaks
* Partial initialization

---

## 1. Why Constructors and Destructors Matter in Inheritance

When inheritance is involved:

* An object consists of **multiple subobjects**
* Each base class must be **properly initialized**
* Each base class must be **properly destroyed**

C++ enforces strict rules to guarantee:

* Safe construction
* Predictable destruction

---

## 2. Constructor Execution Order in Inheritance

### Core Rule

> **Base class constructors are executed before derived class constructors.**

This ensures:

* Base part of the object is fully initialized
* Derived class can safely use base members

---

## 3. Basic Constructor Order Example

```cpp
#include <iostream>
using namespace std;

class Base {
public:
    Base() {
        cout << "Base constructor\n";
    }
};

class Derived : public Base {
public:
    Derived() {
        cout << "Derived constructor\n";
    }
};

int main() {
    Derived obj;
}
```

### Output

```
Base constructor
Derived constructor
```

✔ Base constructed first
✔ Derived constructed after

---

## 4. Why Base Constructor Runs First

Reason:

* Derived class **depends on base class**
* Base members must exist before derived members
* Prevents access to uninitialized data

This is a **language guarantee**, not a convention.

---

## 5. Parameterized Base Class Constructors

If the base class has a **parameterized constructor**, the derived class must explicitly call it using an **initializer list**.

---

### Example

```cpp
class Base {
public:
    Base(int x) {
        cout << "Base: " << x << endl;
    }
};

class Derived : public Base {
public:
    Derived() : Base(10) {
        cout << "Derived\n";
    }
};
```

✔ `Base(10)` is mandatory
✔ Equivalent to `super(10)` in Java

---

## 6. What If Base Constructor Is Not Called Explicitly?

* Compiler tries to call **default constructor**
* If no default constructor exists → **compile-time error**

```cpp
class Base {
public:
    Base(int x) {}
};

class Derived : public Base {
public:
    Derived() {}   // ❌ Error
};
```

---

## 7. Constructor Order in Multiple Inheritance

### Rule

> Base class constructors are called **in the order of inheritance declaration**, not initializer list order.

---

### Example

```cpp
class A {
public:
    A() { cout << "A\n"; }
};

class B {
public:
    B() { cout << "B\n"; }
};

class C : public A, public B {
public:
    C() { cout << "C\n"; }
};
```

### Output

```
A
B
C
```

✔ Order fixed by class declaration

---

## 8. Constructor Order with Virtual Base Classes

### Rule (Very Important)

> **Virtual base class constructors are called first**, before non-virtual bases.

And:

> **They are constructed only once.**

---

### Example

```cpp
class A {
public:
    A() { cout << "A\n"; }
};

class B : virtual public A {
public:
    B() { cout << "B\n"; }
};

class C : virtual public A {
public:
    C() { cout << "C\n"; }
};

class D : public B, public C {
public:
    D() { cout << "D\n"; }
};
```

### Output

```
A
B
C
D
```

✔ `A` constructed once
✔ Virtual base comes first

---

## 9. Who Initializes Virtual Base Classes?

> **The most derived class is responsible for initializing virtual base classes.**

```cpp
class D : public B, public C {
public:
    D() : A() {}
};
```

Initializers in `B` and `C` are ignored.

---

## 10. Destructor Execution Order in Inheritance

### Core Rule

> **Destructors are called in the reverse order of constructors.**

---

### Example

```cpp
class Base {
public:
    ~Base() {
        cout << "Base destroyed\n";
    }
};

class Derived : public Base {
public:
    ~Derived() {
        cout << "Derived destroyed\n";
    }
};
```

### Output

```
Derived destroyed
Base destroyed
```

✔ Derived destroyed first
✔ Base destroyed last

---

## 11. Why Destruction Happens in Reverse Order

Reason:

* Derived class may depend on base resources
* Derived cleanup must happen first
* Base cleanup last ensures safety

---

## 12. Virtual Destructors (CRITICAL)

If a base class is used **polymorphically**, its destructor **must be virtual**.

---

### Problem Without Virtual Destructor

```cpp
class Base {
public:
    ~Base() {}
};

class Derived : public Base {
public:
    ~Derived() {
        cout << "Derived cleanup\n";
    }
};

Base* b = new Derived();
delete b;   // ❌ Derived destructor not called
```

---

### Correct Design

```cpp
class Base {
public:
    virtual ~Base() {}
};
```

✔ Both destructors called
✔ Prevents memory leaks

---

## 13. Constructors Are NOT Virtual

Important facts:

* Constructors **cannot be virtual**
* Virtual dispatch requires a fully constructed object
* During construction, dynamic type is incomplete

---

## 14. Function Calls Inside Constructors/Destructors

### Important Rule

> **Virtual function calls inside constructors/destructors are NOT polymorphic.**

---

### Example

```cpp
class Base {
public:
    Base() {
        show();
    }
    virtual void show() {
        cout << "Base show\n";
    }
};

class Derived : public Base {
public:
    void show() override {
        cout << "Derived show\n";
    }
};
```

Output:

```
Base show
```

✔ Base version called
✔ Derived part not yet constructed

---

## 15. Common Mistakes

* Forgetting initializer lists
* Assuming constructor order follows initializer list
* Missing virtual destructor
* Calling virtual functions in constructors
* Improper virtual base initialization

---

## Key Takeaways

* Base class constructors always run first

* Derived class destructors run first during cleanup

* Use initializer lists for base initialization

* Virtual base classes are constructed once

* Always use virtual destructors in polymorphic bases

* Never rely on virtual calls inside constructors
