# Access Specifiers in Inheritance (C++)

**Access specifiers** control **visibility and accessibility** of class members.
In inheritance, they determine **how base class members are exposed inside derived classes** and to the outside world.

C++ provides **three access specifiers**:

* `public`
* `protected`
* `private`

> In inheritance, **both the member’s original access level and the inheritance type matter**.

---

## 1. Access Specifiers Recap (Within a Class)

| Access Specifier | Accessible Within Class | Accessible in Derived Class | Accessible Outside |
| ---------------- | ----------------------- | --------------------------- | ------------------ |
| `public`         | ✔ Yes                   | ✔ Yes                       | ✔ Yes              |
| `protected`      | ✔ Yes                   | ✔ Yes                       | ❌ No               |
| `private`        | ✔ Yes                   | ❌ No                        | ❌ No               |

---

## 2. Why Access Specifiers Matter in Inheritance

They help:

* Protect internal implementation
* Expose only necessary functionality
* Maintain encapsulation
* Enforce correct usage of base classes

Poor access control leads to:

* Tight coupling
* Fragile designs
* Misuse of base internals

---

## 3. Types of Inheritance Based on Access

In C++, inheritance itself has **three forms**:

```cpp
class Derived : public Base {};
class Derived : protected Base {};
class Derived : private Base {};
```

Each form affects **how base class members are inherited**.

---

## 4. Public Inheritance (Most Important)

### Definition

```cpp
class Derived : public Base {};
```

Public inheritance preserves the **original access levels**.

---

### Access Transformation

| Base Member | In Derived Class |
| ----------- | ---------------- |
| `public`    | `public`         |
| `protected` | `protected`      |
| `private`   | ❌ Not accessible |

---

### Example

```cpp
class Base {
public:
    int a;
protected:
    int b;
private:
    int c;
};

class Derived : public Base {
public:
    void test() {
        a = 1;   // ✔
        b = 2;   // ✔
        // c = 3; ❌
    }
};
```

---

### When to Use Public Inheritance

✔ True **is-a** relationship
✔ Polymorphism required
✔ Base interface should remain public

👉 **Recommended default choice**

---

## 5. Protected Inheritance

### Definition

```cpp
class Derived : protected Base {};
```

Public and protected members of base become **protected** in derived.

---

### Access Transformation

| Base Member | In Derived Class |
| ----------- | ---------------- |
| `public`    | `protected`      |
| `protected` | `protected`      |
| `private`   | ❌ Not accessible |

---

### Example

```cpp
class Derived : protected Base {
public:
    void test() {
        a = 1;   // ✔ (now protected)
        b = 2;   // ✔
    }
};
```

Outside access:

```cpp
Derived d;
d.a;   // ❌ (no longer public)
```

---

### When to Use Protected Inheritance

* Internal reuse only
* Base functionality should not be exposed publicly
* Rare in application-level code

---

## 6. Private Inheritance

### Definition

```cpp
class Derived : private Base {};
```

Public and protected members of base become **private** in derived.

---

### Access Transformation

| Base Member | In Derived Class |
| ----------- | ---------------- |
| `public`    | `private`        |
| `protected` | `private`        |
| `private`   | ❌ Not accessible |

---

### Example

```cpp
class Derived : private Base {
public:
    void test() {
        a = 1;   // ✔ (now private)
        b = 2;   // ✔
    }
};
```

Outside access:

```cpp
Derived d;
d.a;   // ❌
```

---

### When to Use Private Inheritance

* Implementation reuse only
* **Has-a implemented using inheritance**
* Prefer composition instead

---

## 7. Visual Summary of Access Transformation

| Inheritance Type | Base `public` | Base `protected` | Base `private` |
| ---------------- | ------------- | ---------------- | -------------- |
| `public`         | public        | protected        | ❌              |
| `protected`      | protected     | protected        | ❌              |
| `private`        | private       | private          | ❌              |

---

## 8. Access Specifiers and Polymorphism

Polymorphism requires:

* Public inheritance
* Public virtual functions

```cpp
Base* b = new Derived();
```

✔ Works only with `public` inheritance
❌ Breaks with protected/private inheritance

---

## 9. Access Specifiers and Base Class Pointers

```cpp
class Derived : private Base {};
Base* b = new Derived();   // ❌ Error
```

Reason:

* Base part is not publicly accessible

---

## 10. `protected` Members: Design Insight

`protected` exists for:

* Derived class customization
* Framework-level extensibility

Overusing `protected`:

* Breaks encapsulation
* Leads to fragile designs

Best practice:

> **Prefer private + protected functions (not data)**

---

## 11. Friend Functions and Inheritance

* `friend` functions **do not get inherited**
* Friendship is **not transitive**
* Friendship breaks encapsulation — use carefully

---

## 12. Common Mistakes

* Using private inheritance instead of composition
* Overexposing data as `protected`
* Forgetting inheritance type defaults
* Assuming private members are inherited

---

## 13. Default Inheritance Type (Interview Trap)

```cpp
class Derived : Base {};   // private inheritance (default)
```

| Context  | Default   |
| -------- | --------- |
| `class`  | `private` |
| `struct` | `public`  |

---

## Key Takeaways

* Access specifiers control **visibility in inheritance**

* Public inheritance preserves **is-a** relationship

* Protected and private inheritance hide base interface

* Private members are **never inherited**

* Polymorphism works **only with public inheritance**

* Use protected sparingly

* Prefer composition over private inheritance
