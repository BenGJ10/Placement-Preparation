# Function Overriding in C++

**Function overriding** is a key concept that enables **runtime (dynamic) polymorphism** in C++.

It allows a **derived class** to provide its **own implementation** of a function already defined in the **base class**, **with the same function signature**.

> **Same function signature, different behavior — resolved at runtime**

---

## 1. What is Function Overriding?

Function overriding occurs when:

* A base class has a **virtual function**
* A derived class defines a function with:

  * Same name
  * Same parameter list
  * Same return type (or covariant return)

The function call is resolved **at runtime**, based on the **actual object type**, not the pointer type.

---

## 2. Why Function Overriding is Needed

Without function overriding:

* Base class behavior is always executed
* Derived classes cannot customize behavior
* Polymorphism is impossible

Function overriding enables:

* **Dynamic behavior**
* **Extensible design**
* **Substitutability (LSP)**

---

## 3. Basic Function Overriding Example

```cpp
#include <iostream>
using namespace std;

class Shape {
public:
    virtual void draw() {
        cout << "Drawing Shape\n";
    }
};

class Circle : public Shape {
public:
    void draw() {
        cout << "Drawing Circle\n";
    }
};

int main() {
    Shape* s = new Circle();
    s->draw();   // Calls Circle::draw()
}
```

✔ Same function signature
✔ Base pointer → derived object
✔ Resolved at runtime

---

## 4. Role of `virtual` Keyword

The `virtual` keyword tells the compiler:

> “This function can be overridden, and resolution must happen at runtime.”

### Without `virtual`

```cpp
class Shape {
public:
    void draw() {
        cout << "Shape\n";
    }
};

class Circle : public Shape {
public:
    void draw() {
        cout << "Circle\n";
    }
};

Shape* s = new Circle();
s->draw();   // Output: Shape
```

❌ No overriding

❌ This is **function hiding**

✔ Compile-time binding

---

## 5. Rules for Function Overriding in C++

| Rule                          | Explanation                      |
| ----------------------------- | -------------------------------- |
| Same name                     | Function names must match        |
| Same parameters               | Parameter list must be identical |
| Same return type              | Or covariant return              |
| Inheritance required          | Base → Derived                   |
| Base function must be virtual | Mandatory                        |
| Access specifier              | Can differ, but not recommended  |

---

## 6. Covariant Return Types

C++ allows **covariant return types** in overriding.

```cpp
class Base {
public:
    virtual Base* getObject() {
        return this;
    }
};

class Derived : public Base {
public:
    Derived* getObject() {
        return this;
    }
};
```

✔ Return type is more specific
✔ Still valid overriding

---

## 7. Overriding vs Function Hiding

If function signatures differ:

```cpp
class Base {
public:
    virtual void show(int x) {
        cout << "Base\n";
    }
};

class Derived : public Base {
public:
    void show(double x) {
        cout << "Derived\n";
    }
};
```

Result:

* Base function is **hidden**
* No overriding occurs

To fix:

```cpp
using Base::show;
```

---

## 8. `override` Keyword (Best Practice)

C++11 introduced the `override` keyword.

```cpp
class Circle : public Shape {
public:
    void draw() override {
        cout << "Drawing Circle\n";
    }
};
```

Benefits:

* Compiler checks correct overriding
* Prevents subtle bugs
* Improves readability

---

## 9. Function Overriding and Base Class Pointers

Core rule:

> **Polymorphism works only through base class pointers or references**

```cpp
Circle c;
Shape s = c;   // Object slicing
s.draw();      // Calls Shape::draw()
```

✔ Object slicing destroys polymorphism
✔ Always use pointers or references

---

## 10. Object Slicing Problem

```cpp
Shape s = Circle();
s.draw();  // Calls Shape::draw()
```

Reason:

* Derived part is sliced off
* Object becomes pure base object

Solution:

```cpp
Shape& s = Circle();
```

---

## 11. Virtual Destructors (Critical)

When using polymorphism, **base class destructors must be virtual**.

```cpp
class Base {
public:
    virtual ~Base() {
        cout << "Base destroyed\n";
    }
};
```

Otherwise:

* Derived destructor may not be called
* Leads to memory leaks

---

## 12. Overriding vs Overloading

| Aspect             | Overriding | Overloading  |
| ------------------ | ---------- | ------------ |
| Polymorphism Type  | Runtime    | Compile-time |
| Inheritance        | Required   | Not required |
| Function Signature | Same       | Different    |
| Uses `virtual`     | ✔ Yes      | ❌ No         |
| Binding Time       | Runtime    | Compile time |

* Function overriding is the **foundation of runtime polymorphism**

* `virtual` keyword is mandatory

* Function signatures must match exactly

* Use `override` keyword for safety

* Always use base pointers/references

* Avoid object slicing

* Use virtual destructors
