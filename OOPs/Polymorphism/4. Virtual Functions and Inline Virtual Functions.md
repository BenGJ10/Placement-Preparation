# Virtual Functions, Classes, and Inline Functions

These concepts are closely related to **runtime polymorphism** and **dynamic binding** in C++.

They answer three different questions:

* **Virtual function** → *How is the correct function chosen at runtime?*
* **Virtual class** → *How do we design base classes meant only for inheritance?*
* **Virtual inline function** → *Can a function be both virtual and inline?*

---

## 1. Virtual Functions in C++

### Definition

A **virtual function** is a member function of a class that is declared using the `virtual` keyword and is **meant to be overridden in a derived class**.

The function call is resolved **at runtime**, based on the **actual object type**, not the pointer type.

---

## 2. Why Virtual Functions Are Needed

Without virtual functions:

* Function calls are resolved at **compile time**
* Base class behavior is always executed
* Runtime polymorphism is impossible

Virtual functions enable:

* **Dynamic binding**
* **True polymorphism**
* **Extensible designs**

---

## 3. Basic Virtual Function Example

```cpp
#include <iostream>
using namespace std;

class Base {
public:
    virtual void show() {
        cout << "Base show()\n";
    }
};

class Derived : public Base {
public:
    void show() {
        cout << "Derived show()\n";
    }
};

int main() {
    Base* b = new Derived();
    b->show();   // Calls Derived::show()
}
```

✔ Function chosen at runtime
✔ Based on actual object (`Derived`)

---

## 4. Virtual vs Non-Virtual Function Call

### Without `virtual`

```cpp
class Base {
public:
    void show() {
        cout << "Base\n";
    }
};

Base* b = new Derived();
b->show();   // Base::show()
```

❌ Compile-time binding

❌ No polymorphism

---

## 5. How Virtual Functions Work Internally (vtable)

Virtual functions are implemented using a **Virtual Table (vtable)**.

### Key Points:

* Each class with virtual functions has a **vtable**
* Each object has a hidden **vptr** pointing to its class’s vtable
* Function call is resolved via vtable lookup

Conceptually:

```
Base pointer → vptr → vtable → correct function
```

---

## 6. Important Rules of Virtual Functions

| Rule                         | Explanation                        |
| ---------------------------- | ---------------------------------- |
| Must be member functions     | Cannot be static                   |
| Resolved at runtime          | Uses dynamic binding               |
| Inheritance required         | Base → Derived                     |
| Virtual once, virtual always | Remains virtual in derived classes |
| Destructor should be virtual | If class is polymorphic            |

---

## 7. Virtual Destructor (Critical)

If a class has **any virtual function**, its destructor should usually be virtual.

```cpp
class Base {
public:
    virtual ~Base() {
        cout << "Base destroyed\n";
    }
};
```

Otherwise:

* Derived destructor may not run
* Causes memory leaks

---

## 8. Virtual Class in C++

### Important Clarification

👉 **There is NO keyword called `virtual class` in C++.**

The term **“virtual class”** usually means one of the following:

1. A class containing **pure virtual functions**
2. An **abstract base class**
3. A class designed **only for inheritance**

---

## 9. Abstract Class Using Pure Virtual Functions

### Pure Virtual Function

```cpp
virtual void draw() = 0;
```

* `= 0` makes the function **pure virtual**
* Class becomes **abstract**
* Cannot be instantiated

---

### Abstract Class Example

```cpp
class Shape {
public:
    virtual void draw() = 0;  // Pure virtual
    virtual ~Shape() {}
};
```

Usage:

```cpp
class Circle : public Shape {
public:
    void draw() override {
        cout << "Drawing Circle\n";
    }
};
```

✔ `Shape` acts as an interface
✔ Forces derived classes to implement `draw()`

---

## 10. Characteristics of Abstract (Virtual) Classes

| Aspect        | Description          |
| ------------- | -------------------- |
| Instantiation | ❌ Not allowed        |
| Purpose       | Interface / contract |
| Uses          | Runtime polymorphism |
| Destructor    | Should be virtual    |
| Common role   | Base class           |

---

## 11. Virtual Inline Functions in C++

### Key Question:

**Can a function be both `virtual` and `inline`?**

### Short Answer:

👉 **Yes, syntactically allowed, but semantically limited**

---

## 12. Virtual + Inline Example

```cpp
class Base {
public:
    virtual inline void show() {
        cout << "Base show\n";
    }
};
```

This **compiles**, but…

---

## 13. Why Virtual Inline Is Usually Ignored

### Reason:

* `inline` → compile-time decision
* `virtual` → runtime decision

These goals **conflict**.

### What Actually Happens:

* Compiler may inline the function **only when object type is known at compile time**
* In polymorphic calls, **inlining is not possible**

Example:

```cpp
Base b;
b.show();      // May be inlined

Base* ptr = new Derived();
ptr->show();   // Cannot be inlined (runtime dispatch)
```

---

## 14. When Virtual Inline Makes Sense

Rare cases:

* Function is virtual
* Call site knows exact object type
* Compiler performs **devirtualization**

But:

* You should **not rely on this**
* Let the compiler decide

---

## 15. Virtual Functions and Performance

| Aspect   | Virtual Function        |
| -------- | ----------------------- |
| Dispatch | Runtime                 |
| Overhead | One pointer indirection |
| Cost     | Very small              |
| Tradeoff | Flexibility vs speed    |

In practice:

* Overhead is negligible
* Design clarity matters more

---

## 16. Common Misconceptions

* ❌ Virtual functions slow programs significantly
* ❌ Virtual = inline impossible
* ❌ Abstract class = interface only
* ❌ Virtual keyword required in derived class

## Summary Table

| Concept                 | Meaning                             |
| ----------------------- | ----------------------------------- |
| Virtual function        | Runtime method dispatch             |
| Pure virtual function   | Forces overriding                   |
| Abstract class          | Class with pure virtual functions   |
| Virtual class           | Informal term (abstract base class) |
| Virtual inline function | Allowed but rarely effective        |

---

## Key Takeaways

* Virtual functions enable **runtime polymorphism**

* Implemented using **vtable and dynamic binding**

* C++ has **no `virtual class` keyword**

* Abstract classes use **pure virtual functions**

* `virtual inline` is allowed but rarely useful

* Always use **virtual destructors** in polymorphic bases
