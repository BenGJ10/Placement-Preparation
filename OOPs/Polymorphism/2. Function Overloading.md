# Function and Operator Overloading in C++

**Function Overloading** and **Operator Overloading** are forms of **compile-time (static) polymorphism** in C++.

They allow **multiple meanings to be assigned to the same name**, as long as the compiler can **uniquely distinguish them at compile time**.

> **Same name, different behavior — resolved at compile time**

---

## 1. What is Function Overloading?

**Function overloading** allows multiple functions with the **same name** but **different parameter lists**.

The compiler decides **which function to call** based on:

* Number of parameters
* Type of parameters
* Order of parameters

---

### Basic Definition

> Two or more functions can have the same name **if their signatures are different**.

Function signature includes:

* Function name
* Parameter types
* Parameter order

❌ Return type alone is **not sufficient**

---

## 2. Why Function Overloading is Needed

Without function overloading:

* You would need different names for similar operations
* Code becomes harder to read and maintain

Function overloading provides:

* **Readability**
* **Logical grouping**
* **Cleaner APIs**

Example:

```cpp
print(int);
print(double);
print(string);
```

---

## 3. Function Overloading Example

```cpp
class Calculator {
public:
    int add(int a, int b) {
        return a + b;
    }

    double add(double a, double b) {
        return a + b;
    }

    int add(int a, int b, int c) {
        return a + b + c;
    }
};
```

✔ Same function name
✔ Different parameter lists
✔ Resolved at compile time

---

## 4. How the Compiler Resolves Overloaded Functions

This process is called **Compile-Time Binding**.

Steps:

1. Match function name
2. Match number of arguments
3. Match argument types
4. Perform standard type promotions if needed

Example:

```cpp
add(5, 3);        // calls add(int, int)
add(2.5, 4.5);    // calls add(double, double)
```

---

## 5. Invalid Function Overloading

### ❌ Overloading by Return Type Only (NOT allowed)

```cpp
int func(int a);
double func(int a);   // ❌ Error
```

Reason:

* Compiler cannot decide which function to call

---

### ❌ Ambiguous Overloading

```cpp
void func(float);
void func(double);

func(10);  // ❌ Ambiguous
```

Integer literal `10` can convert to both `float` and `double`.

---

## 6. Operator Overloading

**Operator overloading** allows operators (`+`, `-`, `*`, `==`, etc.) to work with **user-defined data types**.

> Operator overloading does **not change operator meaning** — it extends it.

---

## 7. Why Operator Overloading Exists

Consider adding two objects:

```cpp
Point p1, p2;
Point p3 = p1 + p2;
```

Without operator overloading:

```cpp
Point p3 = addPoints(p1, p2);
```

Operator overloading improves:

* **Readability**
* **Intuitiveness**
* **Mathematical modeling**

---

## 8. Operator Overloading Example

```cpp
class Point {
public:
    int x, y;

    Point(int x, int y) : x(x), y(y) {}

    Point operator + (const Point& p) {
        return Point(x + p.x, y + p.y);
    }
};
```

Usage:

```cpp
Point p1(2, 3), p2(4, 5);
Point p3 = p1 + p2;
```

---

## 9. Operator Overloading as Member vs Non-Member

### Member Function Overloading

```cpp
class A {
public:
    A operator+(const A& obj);
};
```

Called as:

```cpp
a + b;
```

---

### Non-Member (Friend) Function Overloading

```cpp
class A {
public:
    int x;
    friend A operator+(const A& a1, const A& a2);
};
```

Use non-member when:

* Left operand is **not** a class object
* Symmetry is required

---

## 10. Operators That Can Be Overloaded

✔ Can be overloaded:

```
+  -  *  /  %  
== != < > <= >=
[] () ++ --
<< >>
```

❌ Cannot be overloaded:

```
::  .*  .  sizeof  ?:  typeid
```

---

## 11. Rules and Constraints

| Rule                                      | Explanation                    |
| ----------------------------------------- | ------------------------------ |
| No new operators                          | Only existing operators        |
| Precedence unchanged                      | Operator priority remains same |
| At least one operand must be user-defined | Prevents redefining built-ins  |
| Overloading ≠ Overriding                  | Different concepts             |

---

## 12. Compile-Time Polymorphism Characteristics

| Aspect               | Description          |
| -------------------- | -------------------- |
| Binding              | Early (compile time) |
| Performance          | Fast                 |
| Flexibility          | Limited              |
| Uses `virtual`       | ❌ No                 |
| Inheritance required | ❌ No                 |

---

## 13. Function Overloading vs Operator Overloading

| Aspect            | Function Overloading | Operator Overloading  |
| ----------------- | -------------------- | --------------------- |
| Purpose           | Multiple functions   | Extend operators      |
| Syntax            | Same function name   | Operator keyword      |
| Use case          | Logical grouping     | Mathematical behavior |
| Polymorphism type | Compile-time         | Compile-time          |

---

## 14. Common Mistakes

* Overloading with ambiguous parameters
* Forgetting `const` correctness
* Overusing operator overloading (hurts readability)
* Assuming runtime polymorphism

---

## 15. What Overloading Does NOT Do

Overloading does **not**:

* Enable runtime polymorphism
* Use vtables
* Support dynamic binding
* Depend on object type at runtime

---

---

## Key Takeaways

* Function overloading improves **readability and design clarity**

* Operator overloading extends operators to **user-defined types**

* All overloading decisions are made **at compile time**

* Overloading is **not dynamic polymorphism**

* Use operator overloading **sparingly and logically**
