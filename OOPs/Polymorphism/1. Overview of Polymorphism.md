# Polymorphism in OOPS

**Polymorphism** is one of the four core principles of Object-Oriented Programming (OOP).

The term comes from Greek:

* **Poly** → many
* **Morph** → forms

It allows **the same interface (function/method name) to exhibit different behavior** depending on:

* The type of object
* The context in which it is used

In simple terms:

> **One name, many behaviors**

---

## 1. What is Polymorphism?

Polymorphism enables a single function or operation to work in **multiple ways**.

It means:

* Different objects can respond differently to the **same function call**
* The correct behavior is determined **at compile time or runtime**

Example idea:

```cpp
draw(shape);
```

* If `shape` is a `Circle` → draw a circle
* If `shape` is a `Rectangle` → draw a rectangle

The **function call remains the same**, but behavior changes.

---

## 2. Why Polymorphism is Necessary

Without polymorphism:

* Code becomes full of `if-else` or `switch` blocks
* Adding new behavior requires modifying existing code
* Violates **Open–Closed Principle**

Polymorphism helps achieve:

* **Extensibility**
* **Loose coupling**
* **Cleaner, scalable design**

---

## 3. Types of Polymorphism in C++

Polymorphism in C++ is broadly classified into:

| Type                      | Binding Time | Also Known As        |
| ------------------------- | ------------ | -------------------- |
| Compile-Time Polymorphism | Compile time | Static Polymorphism  |
| Runtime Polymorphism      | Runtime      | Dynamic Polymorphism |

---

## 4. Compile-Time Polymorphism (Static)

The function call is resolved **at compile time**.

Achieved using:

1. **Function Overloading**
2. **Operator Overloading**

---

### 4.1 Function Overloading

Multiple functions with the **same name** but **different parameters**.

```cpp
class Calculator {
public:
    int add(int a, int b) {
        return a + b;
    }

    double add(double a, double b) {
        return a + b;
    }
};
```

✔ Decision made at compile time
✔ Based on function signature
❌ No dynamic behavior

---

### 4.2 Operator Overloading

Custom behavior for operators.

```cpp
class Point {
public:
    int x, y;

    Point operator + (const Point& p) {
        return {x + p.x, y + p.y};
    }
};
```

---

### Characteristics of Compile-Time Polymorphism

| Aspect          | Description                  |
| --------------- | ---------------------------- |
| Binding         | Early binding                |
| Flexibility     | Limited                      |
| Performance     | Faster (no runtime overhead) |
| Uses `virtual`? | ❌ No                         |

---

## 5. Runtime Polymorphism (Dynamic)

The function call is resolved **at runtime**, based on the **actual object type**, not pointer type.

Achieved using:

* **Inheritance**
* **Virtual functions**
* **Base class pointers / references**

---

### 5.1 Virtual Functions

A function declared using the `virtual` keyword in the base class.

```cpp
class Shape {
public:
    virtual void draw() {
        cout << "Drawing Shape\n";
    }
};

class Circle : public Shape {
public:
    void draw() {
        cout << "Drawing Circle\n";
    }
};
```

Usage:

```cpp
Shape* s;
Circle c;
s = &c;
s->draw();   // Calls Circle::draw()
```

✔ Function call decided at runtime
✔ Enables true polymorphism

---

## 6. How Runtime Polymorphism Works Internally

Runtime polymorphism in C++ is implemented using:

### Virtual Table (vtable)

* Each class with virtual functions has a **vtable**
* Object contains a hidden pointer (`vptr`) to its class vtable
* Function call is resolved via vtable lookup

```
Base pointer → vptr → vtable → correct function
```

This is why:

* Runtime polymorphism has **slight overhead**
* Requires `virtual` keyword

---

## 7. Polymorphism with Base Class Pointers

Core rule:

> **Base class pointer can point to derived class object**

```cpp
Shape* s = new Circle();
s->draw();
```

This enables:

* Writing generic code
* Plug-and-play behavior
* Dependency inversion

---

## 8. What Happens Without `virtual`?

```cpp
class Shape {
public:
    void draw() {
        cout << "Shape\n";
    }
};

class Circle : public Shape {
public:
    void draw() {
        cout << "Circle\n";
    }
};

Shape* s = new Circle();
s->draw();   // Output: Shape
```

❌ Function resolved at compile time

❌ No runtime polymorphism

✔ This is **function hiding**, not overriding

---

## 9. Polymorphism vs Function Overloading

| Aspect               | Overloading  | Runtime Polymorphism |
| -------------------- | ------------ | -------------------- |
| Binding Time         | Compile time | Runtime              |
| Requires Inheritance | ❌ No         | ✔ Yes                |
| Uses `virtual`       | ❌ No         | ✔ Yes                |
| Flexibility          | Limited      | High                 |
| Performance          | Faster       | Slightly slower      |

---

## 10. Real-World Analogy

Consider a **remote control**:

* Same button: `power()`
* TV → turns TV on
* AC → turns AC on
* Fan → turns fan on

The **interface is same**, behavior depends on the device.

That’s polymorphism.

---

## 11. What Polymorphism Does NOT Do

Polymorphism does **not**:

* Replace inheritance
* Guarantee correctness of logic
* Improve performance automatically

It must be used **intentionally**, not blindly.

## Key Takeaways

* Polymorphism allows **different behavior through the same interface**.

* C++ supports **both static and dynamic polymorphism**.

* **True polymorphism requires `virtual` functions**.

* Runtime polymorphism works via **vtable and dynamic binding**.

* Essential for writing **scalable and flexible OOP systems**.
