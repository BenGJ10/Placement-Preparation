# Abstract Class in C++

An **abstract class** in C++ is a class that **cannot be instantiated** and is intended to be **used only as a base class**.

It defines a **common interface** for derived classes and may contain:

* **Pure virtual functions**
* **Virtual functions**
* **Data members**
* **Constructors and destructors**

---

## 1. What is an Abstract Class?

A class becomes **abstract** when it contains **at least one pure virtual function**.

### Pure Virtual Function

```cpp
virtual void draw() = 0;
```

* `= 0` indicates **no implementation**
* Forces derived classes to implement the function

---

## 2. Why Abstract Classes Are Needed

Abstract classes are used when:

* A base class represents a **concept**, not a concrete object
* You want to **enforce a contract**
* Derived classes must provide **specific behavior**

They help achieve:

* **Runtime polymorphism**
* **Design consistency**
* **Loose coupling**

---

## 3. Basic Abstract Class Example

```cpp
#include <iostream>
using namespace std;

class Shape {
public:
    virtual void draw() = 0;   // Pure virtual
};

class Circle : public Shape {
public:
    void draw() override {
        cout << "Drawing Circle\n";
    }
};

int main() {
    Shape* s = new Circle();
    s->draw();
}
```

✔ `Shape` cannot be instantiated
✔ Derived class must implement `draw()`
✔ Enables polymorphism

---

## 4. Instantiation Rules

```cpp
Shape s;   // ❌ Error: abstract class
Shape* s;  // ✔ Allowed
```

| Case                     | Allowed |
| ------------------------ | ------- |
| Object of abstract class | ❌ No    |
| Pointer/reference        | ✔ Yes   |
| Derived class object     | ✔ Yes   |

---

## 5. Abstract Class with Data Members

Abstract classes **can have member variables**.

```cpp
class Employee {
protected:
    int id;
public:
    Employee(int id) : id(id) {}
    virtual double calculateSalary() = 0;
};
```

✔ Unlike interfaces, state is allowed

✔ Useful for shared data

---

## 6. Abstract Class with Constructors

Abstract classes **can have constructors**.

```cpp
class Base {
public:
    Base() {
        cout << "Base constructor\n";
    }
    virtual void show() = 0;
};
```

* Constructor runs when derived object is created
* Used to initialize base data

---

## 7. Abstract Class with Destructors

Destructors in abstract classes **must be virtual**.

```cpp
class Shape {
public:
    virtual ~Shape() {
        cout << "Shape destroyed\n";
    }
};
```

Ensures:

* Derived destructors are called
* Prevents memory leaks

---

## 8. Partial Implementation in Abstract Classes

An abstract class may:

* Implement some functions
* Leave others pure virtual

```cpp
class Vehicle {
public:
    void start() {
        cout << "Vehicle started\n";
    }
    virtual void move() = 0;
};
```

✔ Common behavior shared
✔ Specific behavior enforced

---

## 9. Abstract Class vs Interface (Conceptual)

| Aspect                 | Abstract Class | Interface (Concept) |
| ---------------------- | -------------- | ------------------- |
| Instantiation          | ❌ No           | ❌ No                |
| Data members           | ✔ Yes          | ❌ No                |
| Constructors           | ✔ Yes          | ❌ No                |
| Partial implementation | ✔ Yes          | ❌ No                |
| Multiple inheritance   | ✔ Yes          | ✔ Yes               |

> In C++, interfaces are implemented using **pure abstract classes**.

---

## 10. Abstract Class and Polymorphism

Abstract classes are **designed for polymorphism**.

```cpp
Shape* s1 = new Circle();
Shape* s2 = new Rectangle();

s1->draw();
s2->draw();
```

Same interface → different behavior.

---

## 11. When a Derived Class Remains Abstract

If a derived class:

* Does **not** implement all pure virtual functions

Then:

* It also becomes **abstract**

```cpp
class Derived : public Shape {
    // draw() not implemented
};
```

---

## 12. Abstract Class and Final Keyword

```cpp
class Shape final {
    virtual void draw() = 0;
};
```

❌ Meaningless:

* `final` prevents inheritance
* Abstract class requires inheritance

---

## 13. Common Use Cases

Abstract classes are commonly used for:

* Framework base classes
* Plugin systems
* APIs and libraries
* Strategy pattern
* Template method pattern

---

## 14. Common Mistakes

* Forgetting to implement pure virtual functions
* Not using `override`
* Non-virtual destructors
* Treating abstract class as concrete
* Overusing abstract classes

---

## 15. Abstract Class vs Concrete Class

| Aspect                          | Abstract             | Concrete        |
| ------------------------------- | -------------------- | --------------- |
| Instantiable                    | ❌ No                 | ✔ Yes           |
| Purpose                         | Interface / contract | Object creation |
| Contains pure virtual functions | ✔ Yes                | ❌ No            |

---

## Summary Table

| Feature               | Abstract Class         |
| --------------------- | ---------------------- |
| Instantiation         | Not allowed            |
| Key Mechanism         | Pure virtual functions |
| Supports data         | ✔ Yes                  |
| Supports constructors | ✔ Yes                  |
| Enables polymorphism  | ✔ Yes                  |

---

## Key Takeaways

* Abstract classes define **what** must be done, not **how**

* Created using **pure virtual functions**

* Cannot be instantiated

* Can contain data and implementation

* Essential for runtime polymorphism

* Always use **virtual destructors**
