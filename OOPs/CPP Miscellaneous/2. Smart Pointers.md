# Smart Pointers in C++

**Smart pointers** are C++ objects that manage **dynamic memory automatically** using **RAII (Resource Acquisition Is Initialization)**.

They ensure:

* Proper resource deallocation
* Clear ownership semantics
* Exception safety

> **Smart pointers replace raw `new` / `delete` in modern C++.**

---

## 1. Why Smart Pointers Are Needed

### Problems with Raw Pointers

```cpp
int* p = new int(10);
// forgot delete → memory leak
```

Common issues:

* Memory leaks
* Dangling pointers
* Double deletion
* Exception-unsafe code

Smart pointers solve these by:

* Binding memory lifetime to object lifetime
* Automatically freeing resources

---

## 2. RAII and Smart Pointers

Smart pointers are a direct application of **RAII**.

| Event                   | Action            |
| ----------------------- | ----------------- |
| Smart pointer created   | Resource acquired |
| Smart pointer destroyed | Resource released |

No manual `delete`.

---

## 3. Types of Smart Pointers in C++

C++ provides three main smart pointers in `<memory>`:

| Smart Pointer     | Ownership Model      |
| ----------------- | -------------------- |
| `std::unique_ptr` | Exclusive ownership  |
| `std::shared_ptr` | Shared ownership     |
| `std::weak_ptr`   | Non-owning reference |

---

## 4. `std::unique_ptr`

### Definition

`std::unique_ptr` represents **exclusive ownership** of a resource.

> **Only one `unique_ptr` can own an object at a time.**

---

### Basic Example

```cpp
#include <memory>

std::unique_ptr<int> p = std::make_unique<int>(10);
```

✔ Cannot be copied
✔ Can be moved
✔ Zero overhead

---

### Ownership Transfer (Move Semantics)

```cpp
std::unique_ptr<int> p1 = std::make_unique<int>(5);
std::unique_ptr<int> p2 = std::move(p1);
```

After move:

* `p1` becomes `nullptr`
* `p2` owns the object

---

### Why `unique_ptr` Is Preferred

* Fastest smart pointer
* Expresses clear ownership
* Prevents accidental sharing

---

## 5. `std::shared_ptr`

### Definition

`std::shared_ptr` represents **shared ownership** of a resource.

> The resource is destroyed **only when the last owner releases it**.

---

### Basic Example

```cpp
#include <memory>

std::shared_ptr<int> p1 = std::make_shared<int>(10);
std::shared_ptr<int> p2 = p1;
```

✔ Reference count = 2
✔ Memory freed when count = 0

---

### Reference Counting

```cpp
p1.use_count();  // Number of shared owners
```

Internally:

* Control block tracks count
* Thread-safe (atomic operations)

---

### When to Use `shared_ptr`

* Multiple objects need shared access
* Ownership is unclear or distributed
* Observer-like patterns

---

## 6. `std::weak_ptr`

### Definition

`std::weak_ptr` is a **non-owning reference** to a resource managed by `shared_ptr`.

> It prevents **cyclic references**.

---

### The Cyclic Dependency Problem

```cpp
class A {
public:
    std::shared_ptr<B> b;
};

class B {
public:
    std::shared_ptr<A> a;
};
```

Result:

* Reference count never reaches zero
* Memory leak

---

### Solution Using `weak_ptr`

```cpp
class B {
public:
    std::weak_ptr<A> a;
};
```

✔ Breaks ownership cycle
✔ No memory leak

---

### Accessing `weak_ptr`

```cpp
if (auto sp = wp.lock()) {
    // safe access
}
```

* `lock()` returns `shared_ptr`
* Returns `nullptr` if object expired

---

## 7. `make_unique` vs `make_shared`

### `make_unique`

```cpp
auto p = std::make_unique<int>(10);
```

✔ Safer
✔ No memory leak on exceptions

---

### `make_shared`

```cpp
auto p = std::make_shared<int>(10);
```

✔ Single memory allocation
✔ Better cache locality

---

### Comparison

| Aspect        | make_unique | make_shared    |
| ------------- | ----------- | -------------- |
| Allocation    | One         | One (combined) |
| Performance   | Fast        | Faster         |
| Control block | Separate    | Combined       |

---

## 8. Smart Pointers and Custom Deleters

```cpp
std::unique_ptr<FILE, decltype(&fclose)>
    file(fopen("data.txt", "r"), fclose);
```

✔ Manages non-memory resources
✔ Works with RAII

---

## 9. Smart Pointers vs Raw Pointers

| Aspect         | Raw Pointer | Smart Pointer |
| -------------- | ----------- | ------------- |
| Ownership      | Unclear     | Explicit      |
| Deallocation   | Manual      | Automatic     |
| Safety         | Low         | High          |
| Exception safe | ❌ No        | ✔ Yes         |

---

## 10. Performance Considerations

| Pointer      | Overhead            |
| ------------ | ------------------- |
| `unique_ptr` | None                |
| `shared_ptr` | Atomic ref counting |
| `weak_ptr`   | Minimal             |

Rule:

> **Use the least powerful pointer that solves the problem.**

---

## 11. Common Mistakes

* Using `shared_ptr` everywhere
* Creating `shared_ptr` from raw pointers multiple times
* Forgetting `weak_ptr` in cycles
* Mixing raw `delete` with smart pointers

---

## 12. Smart Pointers and Polymorphism

```cpp
std::unique_ptr<Base> p = std::make_unique<Derived>();
```

✔ Works perfectly
✔ Requires virtual destructor in base

---

## 13. Best Practices (VERY IMPORTANT)

* Prefer `unique_ptr` by default
* Use `shared_ptr` only when ownership is shared
* Use `weak_ptr` to break cycles
* Avoid raw `new` / `delete`
* Always use `make_unique` / `make_shared`

---

## Key Takeaways

* Smart pointers implement RAII

* They prevent memory leaks and dangling pointers

* `unique_ptr` is the safest and fastest

* `shared_ptr` uses reference counting

* `weak_ptr` prevents cyclic ownership

* Prefer smart pointers over raw pointers
